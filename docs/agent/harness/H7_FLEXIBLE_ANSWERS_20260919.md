# H7：自由答案表达与逐项要求验收

本轮已完成：新增可选 `supervisor_v2`、中文/英文开放题与 CPU 混合题实验、逐项独立内容审核，以及审核后资料分组修正。**31 次真实调用，6 道计划题实际交付 5 道草稿**，包含一个英文两题任务。这里的交付是保存为 `draft`，不是教师批准或正式发放；并非五题均被独立证明完全正确。

可以保留的结论是：主计划与逐题 worker 可配合自由回答、开放立场、逐项证据审核运行；CPU 的确定性计算可与自由解释组合。仍不能宣称难度精准控制或文科答案正确率已经解决。独立审核发现逻辑漏检、篇幅不符、公开资料缺口及 hard 证据不足，详见下文。

## 问题与设计

H6 已将出题拆成主计划和逐题子任务，但 CPU worker 只能改变数值规格，固定渲染器无法满足某些临时提出的概念解释要求。最后两个候选的数值正确，仍因缺少进程级响应/周转比较而失败。文科论述题更不能依赖一个固定的答案段落模板。

H7 新增可选 `AGENT_ORCHESTRATION=supervisor_v2`，把可验证的任务要求与答案表达分开。通用题目继续使用自由的 `answer` 和 `explanation`，可按需要组织段落、论点、比较或简短列表；这里的结构化 JSON 是传输和审核协议，不是规定学生答案写作格式。

主计划每题分配 1–6 个编号要求，每个要求包括类型、描述、支持资料 ID。数量、顺序、题型、难度配额和来源范围仍由程序校验。开放论述题允许 `multiple_defensible`：独立解题提供一种可能的回答，复核按证据、推理、要求覆盖评判，不把与示范立场不同直接判成错误。选择题仍必须有唯一正确选项；可多解也不放松事实或计算要求。

每项复核必须给出 `met/partial/missing/unsupported` 和实际题干、答案中的逐字片段。程序核对全部要求 ID、片段是否存在、引用是否在该要求和该题允许范围内；只有全部 `met` 且原正确性、难度、来源和歧义门槛通过，才接受该题。**引文存在只证明可追踪，不能证明语义评价正确**，仍需独立审查和后续人工评测。漏项与虚构引文不会被平均分掩盖。

CPU 路径先编译不可覆盖的数值题干、时间线和答案，再新增一个无工具的 `compose` 会话，用已计算的结果和资料补充题目要求、参考答案与解释。例如主计划要求进程间比较时，补充段可以具体指出哪个进程响应更快却周转更慢。原始数值内容始终保留；补充文字属于模型生成，所有新事实和数值说法都要再次复核，不能借用原始计算的确定性背书。

如果复核确认核心事实、计算、来源、条件和难度均通过，缺项只在解释表达，控制器复用冻结规格、只重写补充段，再独立解题和复核。如果输入本身无法支持要求，或核心门槛失败，仍须重新设计候选。每次调用都使用原任务账本、来源权限和有限修复次数；续做复用已完成的合法步骤。

规划、通用作者和 CPU 补充写作都没有工具；数值作者只提交一个规格，计算由程序执行。盲解题和复核仍保留受限工具。当前所有逐题子任务串行执行，未实现并发加速。默认仍为 `sequential_v1`，未修改生产 `.env`。

本轮使用明确标注的 AI 自编材料，跳过真实 RAG；不访问用户账号的课程文件。中文材料为虚构图书馆政策的多方记录，英文材料为虚构展览文本的叙述视角。二者均不是历史原始文献或教师金标。CPU 资料沿用现有 AI 教学 fixture。

| H7B | 英文论述题 2 题同一任务 | 12 次调用 | 检查主计划、独立子任务和整组汇总 |

本轮合计最多 **36 次实际调用**。各组单独硬限，不把剩余调用视为必须花完；根据 H7A 的情况，H7B 可不执行，但必须保留未执行原因。固定使用 Harness、high、JSON、32768 输出上限、每阶段最多 4 次请求、一次字段重评、一次候选修复。字段重评和失败候选均消耗共享预算。H7 与 H6 同时改变了规划协议、写作步骤与验收方式，是自适应开发实验，不是单因素消融。

预先区分的指标：计划契约通过、候选生成、事实正确、逐项要求完整落实、难度判断、实际交付题数；另记各阶段调用、tokens、耗时、费用缺失和失败。模型判为 `met` 或 `hard` 不作为独立金标。

独立内容复核在自动评分之外进行，阅读最终实际交付的文本和冻结资料；无交付时明确只检查候选。逐项记录完整/部分/缺失/不支持，不能把模型给的 `met` 直接抄成复核结论。论述题额外检查关键事实或引文、推论是否标明限度、替代立场是否被合理对待；CPU 额外检查补充文字中的数值和比较。需要评分时按要求完整度单独报“完整项/全部项”，难度只给暂定评语，不与算术正确率混成一个综合分。本轮没有教师金标、学生作答或严格盲评设计。

### H7B 开始前的有界协议修订

CPU 使用独立标准库模拟器重算，与实际成品核对：3/3 完整轨迹、54/54 区间、15/15 进程行、15/15 聚合值和 7/7 计算声明一致。原数值题干、答案、解释均保持不变，新增解释的具体数值未发现矛盾。这些核对视角重叠，不能相加制造更大的样本量。

最值得保留的语义失败是 H7C：答案声称“便利转移、没有服务净增”不能解释晚间读者受益。事实上便利转移本来就可能让晚间读者受益，同时让白天部分读者不便；需要总量与分时段对照才能区分。复核即使给出真实引文，仍把这项判为 `met`。**逐字引用解决可追踪性，不能代替反事实和替代解释的逻辑检查。**

篇幅也出现可测偏差：B 两题要求约 200–300、250–350 词，参考答案实际为 395、459 词（按空白分词）；C 要求约 400–600 字，参考答案正文含 1,202 个汉字、去空白 1,336 个字符。模型注意到超长却未阻断。更详细的教师解析应与符合长度的示范回答区分，不能靠把参考答案写长来获得高难度。

英文与中文样例都有较充分的公开方法提示，甚至提前给出可用解释和论证路线。因此，实际认知负担低于只看题干标签、步骤数或 solver 的 hard 判定。后续难度评估应覆盖学生真正看到的全部材料和前面题目提供的提示。

## 审核后的实现修正：尚未追加付费重测

为保留阶段边界，v3/v4/v5 单独保存，不回写 A/B/C 档案或草稿。

1. **学生可见条件。** v3 为 CPU composer 单独提供 `student_visible_context`，区分给学生的题干/讲解与写作者内部的答案/计算结果；不得把后者写成“已给出的表格”，应明确引用学生前一部分自行计算的结果。v4 也对通用作者和复核明确：冻结 reference_chunks 并不自动等于给学生的摘录。此类提示修订已有离线契约回归，尚无修订后模型遵守率数据。
2. **按题保留资料。** v4 的多题 `supervisor_v2` 将每题已审核小节按原顺序聚合到带题号的资料块中；不改题干/答案、不改写原讲解、不给模型再加工，不把各题局部 Source B 混入同一个无归属列表。每段引用再次限定在其 worker 范围内；聚合展示按原序合并引用，原逐段来源仍保存在 accepted_asset 及哈希中。
3. **不丢失后续材料。** 新 `section_scope=per_question` 必须与 q1..qn 的题目一一对应，可容纳 50 个题目资料块，每个原 worker 至多 10 节。原共享讲解仍最多 10 节；v2 多题不再受旧组卷的静默截断影响。测试覆盖 50 题的 100 段及 500 段原文完整保留。这是离线容量验证，不是 50 题付费生成成功率。

## 后续实验优先级与采用范围

本轮采用 `supervisor_v2` 作为下一阶段的可选实验基础，生产默认和 `.env` 保持原配置。固定计算与灵活解释各自承担可验证的任务；开放题不以“是否同示范答案立场”评分，仍严格检查事实、证据和逻辑。

下一轮优先冻结本轮失败题，单独验证三点：一是针对最强竞争解释检查反驳是否成立，尤其避免将局部收益误作净收益证据；二是题干、学生可见资料与参考答案的篇幅一致性；三是减少结论式提示后，困难题是否仍有可重复的独立评价。固定题复核和新题生成必须分开计分，不能把增加调用与同时改多个提示词的收益归于单一因素。

正式论文评测仍需中英文真实课程材料、教师标注及固定测试集，并报告多次重复、误接受/误拒绝、调用和耗时。当前虚构材料、极小样本、自适应修订和开发 AI 评价只支持工程验证与失败分析，不支持“准确率提升到某百分比”或“已达到 precise control over difficulty”的结论。
