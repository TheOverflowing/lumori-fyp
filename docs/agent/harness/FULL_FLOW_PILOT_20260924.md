# Harness 全流程接入与隔离试运行（2026-09-24）

本次将 `AGENT_RUNTIME=deepseek_harness` 扩展到 Auto exploration 的覆盖判断、受限联网搜索和来源选择，以及课程讲解写作。测验与作业继续由主规划阶段产生每道题的要求，再由宿主按 `AGENT_MAX_PARALLEL_QUESTIONS` 同时运行独立的 Harness 题目会话。HTTP 请求、工具、账号、来源和发布仍经过项目原有控制器；Harness 内建的任意子代理、Shell、文件和网页工具保持关闭。

搜索阶段的 `search_web` MCP 工具只接受覆盖判断给出的公开概念词，允许在同语种内重组这些词。父进程使用现有 curated/hybrid/Brave 搜索接口及调用账本，返回的 URL 只是候选；许可证、可抓取性、正文支持、索引和最终覆盖仍要逐关通过。模型无法直接下载任意 URL，也拿不到真实模型 API 密钥。

## 真实调用观察

全部任务运行在 `/private/tmp` 中的隔离数据库，使用本机已配置的 `deepseek-flash` 和现有嵌入/重排服务。调用数包括失败尝试，费用字段没有可核实金额。没有修改用户课程或已有内容。

| --- | --- | --- |
| Round Robin 自动探索初次 | 3 次文本调用；旧搜索校验拒绝了模型对公开关键词的重组 | 修正校验，原任务不追认成功 |
| Round Robin 自动探索复测 | 10 次调用；两次真实搜索成功，OpenStax 候选因 `link_only` 不可收录，另一候选正文不支持要求 | 未生成草稿；保留拒绝理由 |
| Python 资料自动探索 | 12 次调用；搜索、抓取、索引并收录 Python 官方教程，覆盖 4/5 项 | 受隔离试运行调用上限约束，未发布草稿 |

这证明了真实模型下的联网搜索工具调用、课程讲解生成和两题并发派发；没有证明自动探索对任意主题都能找到可收录资料，也没有证明双题题目质量或完整交付率。独立课程/教师评价仍缺失。并发依据是两个作者阶段开始时间相差约 21 毫秒，而非仅靠配置标记。

后续只读复核确认：Python 主题收录的“数据结构”页使模型判定 5 项中的 4 项覆盖，剩余 g1 要求列表的定义、创建、索引和可变性。该页偏向“进一步介绍列表方法”，覆盖判断没有找到能同时支持 g1 的明确片段。已在精选目录补充 Python 官方入门页的中英文版本；其英文页实际抓取为 HTML、PSF 许可、可保存，目录查询能优先找到它。这是来源覆盖修正，尚未追加付费的端到端重测。

双题失败发生在 q1 的 r2：复核给出的 `answer_evidence` 并非最终题目答案或解析的逐字内容。新任务现会先重评同一候选的引文，必要时逐题重写；单题耗尽也继续完成其他题，并保留全部通过的检查点，仍不发布残缺题组。该代码路径已由模拟模型验证，原真实失败仍保留，未追认通过。

后续使用同一隔离数据库、课程资料、主题、两题数量、难度和题型新建恢复策略任务，硬限 12 次任务模型调用。实际共 12 次应用调用（嵌入 1、重排 1、文本 10）；q1/q2 均在首候选通过，并保存隔离草稿 `b64cce5faca54ba5ab09345928e849b8`。两题都触发一次引文重评；q2 初审 3 项中的 2 条答案片段不在成品答案/解析中，重评后无此类无效片段。该结果证明修复路径在真实响应中可完成，不是同一随机输出的严格 A/B，更不是两题正确率或难度准确率。

为回答“与原生相比”，另在同一隔离库、相同资料和双题参数下试运行 native，仍使用新逐题恢复策略与 12 次任务调用上限。首轮重排服务 HTTP 503，在出题前停止（嵌入成功、重排失败）；新任务复测重排成功，但 12 次调用耗尽，q1 有一次无效要求引文，q2 前两次作者格式无效，未发布草稿。Harness 新任务在同额度下交付 2/2。两种运行的模型样本不同、服务商状态不同，且只有一次完整尝试；**不能把本轮交付差异归因为 Harness 质量提升**。它只显示新修复路径可运行，并暴露格式与上游可用性仍会影响交付。

固定运行时、模拟模型的 ACP/MCP 搜索和课程阶段测试通过。相关回归 **282 passed**，另一次工具与探索预算聚焦复核 **56 passed**；部署/CA1 冒烟 **15 passed**。这些测试验证路由、权限、预算和协议，不作为模型内容正确率。

加入新来源和逐题恢复策略后，Agent、恢复、Harness 字段修复及 Auto exploration 相关回归 **383 passed**；旧历史检查点仍沿用原策略。上述测试集合相互重叠，不能求和。

## 本机启用状态

本机 `.env` 已设置 `AGENT_RUNTIME=deepseek_harness` 和 `HARNESS_MAX_OUTPUT_TOKENS=8192`，以容纳当前文字接口配置的 6000 token 上限。`GENERATION_WORKFLOW=agent_v1` 与 `AGENT_ORCHESTRATION=sequential_v1` 保持默认；网页开启“逐题子代理”时请求会选择 `supervisor_v2`。配置将在下次启动服务时生效。官方运行时固定为 `0.1.5rc1`。
