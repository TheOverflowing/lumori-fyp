# H5J / H5T 冻结题目独立审计

日期：2026-09-19。审计只读取归档和只读 SQLite 账本，并运行本地数值核对；新增模型调用 **0 次**。未复制模型完整 reasoning 内容或任何凭据。

## 结论

H5J 与 H5T 使用的是 H4B 的同两道冻结题，分别以关闭思考 / high 思考重新运行 solve 与 review。**不是新增四道题，也不是完整出题能力对比。** 两组所有已完成角色的最终输出都是完整合法 JSON；英文 reviewer 都因额外字段 `feedback_note` 被严格业务 schema 拒绝。关闭思考的中文 solver 改变了 RR 边界规则，被规格绑定检查拦截；high 思考的中文题成功交付。因此本小样本的草稿交付率为 0/2 与 1/2，不能表述为答案正确率由 0% 提升至 50%。

数值独立核对确认：被冻结的两份候选答案本来都是数值正确的。两组的差异发生在模型复核与协议遵循阶段，不是生成了更正确的新答案。

## 各项门槛的分开统计

“角色最终输出”指 solve/review 结束时的 assistant JSON；中间工具调用允许空 content，不作为最终 JSON 分母。注入的 author 也不计作模型生成 JSON。

| 指标 | H5J | H5T | 含义 |
| --- | ---: | ---: | --- |
| 最终输出通过严格 JSON 语法与单对象检查 | 3/3 | 4/4 | 无前后说明、重复字段或截断 |
| 最终输出通过该角色业务 schema | 2/3 | 3/4 | 两组英文 reviewer 各失败一次 |
| solver 工具请求与全部冻结场景一致 | 1/2 | 2/2 | 输入绑定检查，不是教师评分 |
| solver 判断为目标 hard | 2/2 | 2/2 | 模型难度判断；无学生作答校准 |
| 正确性模型门槛实际获得有效结论 | 0/2 | 1/2 | 其他情况因协议或预检失败，未评价 |
| 完整草稿交付 | 0/2 | 1/2 | 所有门槛均通过才交付 |
| 独立核对冻结候选答案的数值 | 2/2 | 同两题，无新增样本 | 与前述模型门槛分开 |

### 英文：两组相同的严格字段失败

两组 solve 都判断 hard、工具输入绑定正确。review 返回合法 JSON，布尔结论均为通过，但附加了 schema 未声明的 `feedback_note`。以当前 `Review.model_validate()` 独立重放，错误均是 `feedback_note: extra_forbidden`。

因此 agent 状态为 `protocol_failure`，正确性记录为 `not_evaluated / invalid_review_output`，不发布草稿。不能将有效 JSON 说成“整个输出协议已解决”，也不能把一个 schema 无效的 reviewer 判断视为有效的通过票。

H5J 英文 solver 另有一处说明性错误：在 q=4 场景，P1 的最后片段为 [15,18)，实际运行 3 单位，却称其用满时间片。这个错误不改变冻结答案的数值，也不是本次系统停止的直接原因；它说明工具输入和数值正确仍不能保证 solver 的自由文字解释完全正确。H5T 英文相应陈述未见此错误。

### 中文：关闭思考时改变边界条件

冻结题要求 `boundary=before`。H5J 的两个 RR `tool_requests` 均写成 `boundary=after`，S2/q=2、S3/q=6 都不匹配。中文 solver 甚至让 q=2 时 P1 在 [0,4) 连续运行；按题目的 before 规则，t=2 到达的 P2 应先入队，P1 应在 t=2 让出 CPU。这个数值结果解答的是另一套规则。

系统正确在 review 前以 `spec_tool_inputs_mismatch` 拒绝；这是实际绑定错误，不是仅凭模型自报的错误。solver 的 STCF 自由说明也出现先声称 P2 尚未完成、随后自我否定的混乱。其 hard 判断通过并不能抵消这些问题。

H5T 中文三项工具输入全部匹配冻结规格，review schema 合格，各布尔检查通过，最终生成 1 份草稿。

## 数值独立核对

核对过程另写一个临时、仅使用 Python 标准库的调度器：STCF 按单位时间选择 `(剩余服务量, ID)` 最小者；RR 使用 FIFO，在 before 边界先入队新到达进程，再入队未完成进程，切换期新到达进程排队尾，按该片段是否提前完成决定下一次转换是否免费。该实现未导入项目的 `cpu_schedule_v1`，也未用项目调度工具产生预期值。

对 7 个场景逐个验证：每一整数时间单位的实际执行进程、每进程首开/响应/完成/周转、精确分数均值、切换次数、开销与 makespan，全部与归档一致；另外 4 项中途剩余服务量均一致。这是单独实现的离线复核，仍不是教师标注或真实学生难度测量。

| 冻结题 / 场景 | 平均响应 | 平均周转 | 切换次数 | 开销 | makespan |
| --- | ---: | ---: | ---: | ---: | ---: |
| 英文 S_STCF | 5/2 | 19/2 | 4 | 0 | 22 |
| 英文 S_RR_Q2 | 7/4 | 25/2 | 9 | 0 | 22 |
| 英文 S_RR_Q5 | 17/4 | 27/2 | 5 | 0 | 22 |
| 英文 S_RR_Q4_SW1 | 23/4 | 16 | 5 | 5 | 27 |
| 中文 S1 | 5/2 | 10 | 4 | 0 | 23 |
| 中文 S2 | 15/4 | 21 | 10 | 8 | 31 |
| 中文 S3 | 6 | 67/4 | 5 | 2 | 25 |

- 英文剩余量：S_RR_Q4_SW1 的 P3 在 t=14 剩 5；S_RR_Q2 的 P4 在 t=9 剩 2。约束留下 S_STCF 与 S_RR_Q5，最小平均周转为 S_STCF 的 19/2。
- 中文剩余量：S1 的 P1 在 t=10 剩 4；S3 的 P3 在 t=20 剩 3。约束留下 S1 与 S3，最小平均响应为 S1 的 5/2。

这些结果验证的是冻结候选题的数值内容。尤其不能把 H5J 中文 solver 在错误 boundary 下的结果算作“正确数值”；它与正确候选答案必须分别看待。

## 论文中可使用的描述

在两道既有中英文 CPU 调度题的冻结复核实验中，开启 high 思考后，规格绑定通过数由 1/2 变为 2/2，完整草稿交付由 0/2 变为 1/2；所有实际完成的角色最终输出均通过严格 JSON 语法检查，但两种思考设置下的英文 reviewer 都违反业务字段约束。实验展示了错误类型的变化及严格门槛的作用，不能建立统计上的模型优势、普遍正确率提升或学生难度符合度结论。
