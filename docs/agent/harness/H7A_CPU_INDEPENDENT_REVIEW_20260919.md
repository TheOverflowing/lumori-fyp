## 数值重算

P1/P2/P3/P5 均为 `(arrival=0, burst=8)`，P4 为 `(2,1)`，总服务量 33。两组 RR 的 q 分别为 2、4，切换费为 1，边界新到达先于被抢占进程，切换期间新到达入队尾，短片完成可豁免随后切换费用。STCF 切换费为 0，并按 `(剩余服务量, ID)` 选进程。

独立轨迹核对的关键事件：RR q=2 时 P4 在 t=2 入队，排在已经等候的 P2/P3/P5 之后、重新入队的 P1 之前。P4 运行 `[12,13)`，之后 P4→P1 免费。q=4 时 P4 运行 `[20,21)`，同样只有这一次后续免费转换。STCF 在 t=2 用 P4 抢占仍余 6 的 P1，P4 完成后继续 P1；本例确实发生抢占。

约束为 overhead ≤8：rr_q2 的 15 不合规，rr_q4 的 7 和 stcf 的 0 合规。可行集合 `{rr_q4, stcf}` 中，`48/5 <51/5`，因此唯一最优是 **rr_q4，平均响应 48/5**。

## 新增自由解释是否与 base 冲突

未发现其具体数字、给定条件或最优选择与独立结果矛盾。例如：

- P1 的响应始终是 0，但周转分别为 39、25、9，确实支持“先获得 CPU 不代表早完成”。
- q 从 2 变为 4，切换次数 16→8、开销 15→7，平均响应增加 `48/5−28/5=4`，与解释一致。
- stcf 相对 rr_q4 的逐进程响应差为 `[0,+4,+7,−18,+10]`，合计 3，平均差为 **3/5**；这是不同进程收益与损失抵消后的结果，不是所有进程同向改善。
- 把开销上限放宽到 15，rr_q2 会成为平均响应最优；改成最小平均周转或 makespan，stcf 最优。两条敏感性判断可由同一组三条冻结轨迹直接检验，不需要改变仿真输入。
- 已知 burst 前提、单 CPU、无 I/O 和结论仅限有限候选都被保留。引用也仅使用本题冻结 source ID。

有两处表达边界宜更准确，但没有因此推翻本例数值：STCF 的 “run-to-completion order” 容易让人联想到非抢占 SJF，应写成基于剩余服务量的选择次序；“RR 保证 roughly one rotation” 不宜单独作为普适时延保证，应绑定这里的有限队列、到达和切换规则。比较还同时包含 RR 付切换费、STCF 免费这一题设差异，因此不能把周转优势全部归因于政策本身；候选最后的范围限定大体避免了这一推广。

新增题干的关键原句是 “Using only the three frozen traces and metric blocks already given … do not re-simulate”，并让学生 “refer to the original tables”。**实际 section 和 stem 只有工作负载、规则与任务；轨迹和结果表位于 answer。** 这把 composer 所见的内部计算结果写成了学生已经获得的资料。虽然可善意理解成“先完成前半题，再使用自己算出的结果”，题面应明确说出来，例如：

> Using the traces and metric values you obtained in the preceding part, explain the following comparisons without changing the stated workload or rules.

因此五项答案内容均基本具备，但不宜给题目整体任务覆盖无条件满分。按“完整=1、部分=0.5”的临时审查规则，完整交付形式暂评 **4.5/5**；这是可修正的题面说明问题，不是把算错题误认为算对。

主计划标记 `multiple_defensible`，但固定约束和目标下的数值最优者确实唯一，答案也正确坚持 rr_q4。多解应仅覆盖论证的组织、可接受的解释和另设约束的讨论，不能用这一标签接受其他固定条件下的错误赢家。

## 难度与结论

`hard` 匹配暂评 **4/5**：本题有真实抢占、边界入队、免费切换、指标排序分歧、两个可行方案的窄幅差距，以及条件变化导致赢家改变；新增解释也确实要求区分指标与作出有限论证，较符合综合分析任务。仍有较长的重复调度计算，六点提示也提供较充分的作答框架，所以这不是已校准的学生难度。

本例支持的结论是：**immutable base 与自由解释组合在这道题上保持了数值一致，并补足了概念分析；独立审核仍发现内部上下文泄漏成学生题面假设的问题。** 单题通过不能证明系统整体正确率或难度精准率达到 100%。
