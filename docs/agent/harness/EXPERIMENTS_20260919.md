# Harness 接入与正确性实验记录

日期：2026-09-19。本轮结论：**官方 Harness 已作为可选后端接通，但当前证据不支持替换默认 native 流程，也不支持宣称答案正确性已经解决。**

## 1. 已完成的系统改动

外层 Python 控制器继续管理逐题生成、精确难度配额、冻结 RAG 依据、盲解、独立重算、复核、有限修订和检查点。候选后端使用固定版本的官方 Harness 运行时；各角色使用不同 ACP 会话，通过 MCP 调用资料快照和 RR/STCF 计算工具。没有重写业务后端或维护修改版 Harness 核心。

同时保留账号与课程隔离、资料启用状态检查、真实 API 调用账本、日额度及单任务额度。子进程不继承真实模型密钥；模型请求经本地转发接口进入原提供商。默认 Shell、文件操作、网页、子 Agent、后台目标推进和远程遥测均已关闭。版本升级会被本地检查拒绝，需重新审计配置。

完整架构、配置和边界见 [使用说明](README.md)；官方版本、依赖哈希、取消/恢复记录见 [安装验收](INSTALL_20260919.md)。本轮未更改生产 `.env` 或用户内容；已在无活动任务时重启本地服务，默认仍为 `agent_v1 + native`。

## 2. 比较方法与证据等级

采用同一份计算机本科课程夹具，中英文 CPU 调度难题、中文数据库事务中等题各一组；另有已知错误/修正答案的 Q016 控制题。每个生成任务只要求一道题，允许最多一次修订；控制题作者由固定 fixture 注入，只有后续阶段真实调用模型。

两种运行方式共同使用 `deepseek-flash`、相同冻结资料、原生 v3 作者/盲解/复核任务契约、4096 输出 token 上限和关闭 thinking 的设置。候选增加 Harness 系统包装、工具循环说明和阶段内上下文，因此这是**整体运行策略比较**。不能声称完全相同提示词，更不能把所有差异归因于循环本身。

本轮不是正式保留测试集：样例少、未重复抽样、版本按发现的问题顺序修订，后续英文诊断题是有意选择的失败案例。来源是 AI 整理的固定课程夹具，未新增教师/学生金标准；冻结检索不测召回率。所有事后评分都是 Codex AI 审阅，不是盲审、教师认证或学生实测难度。

同一问题须区分：接口是否工作、结构是否合规、工具是否正确计算、输入是否对应题干、答案是否忠实转述结果、难度是否匹配。某个门槛先失败时，后面的门槛可能根本没有执行。

## 3. 实际实验与迭代

| 轮次 | 范围 | 真实调用 | token | 观察 |
| --- | --- | ---: | ---: | --- |
| H1 native | 5 任务 | 16 | 72,458 | 新题 1/3 成为草稿；两个控制题均被拒绝，但路径不同 |
| H1 Harness | 同 5 任务 | 5 | 24,857 | 5 次 HTTP 200 响应均被转发层格式校验拒绝；不可用于质量比较 |
| P1 | 单次协议诊断 | 1 | 4,832 | 证实真实非流式工具响应带 `index` 扩展；不执行工具、不评题 |
| H2 Harness | 修复后 5 任务 | 30 | 193,176 | 新题 2/3 成为草稿，但事后发现两份均有需修订之处 |
| H3 Harness v2 | 针对英文难题 | 8 | 68,649 | 难度门拒绝首稿，修订稿 JSON 转义失败；没有到达待验证的 review 节点 |
| **合计** | 含全部失败和诊断 | **60** | **363,972** | 预设累计上限 64；未使用剩余 4 次 |

60 次服务商 HTTP 状态均为 200，响应模型均为 `deepseek-flash`。HTTP 成功不等于协议、结构或教学质量成功。60 次均返回 token 用量，但均未返回费用；**费用未知**，账本的 `known_cost_usd=0` 只表示已知费用字段求和，不能解释为免费。

本表的调用数来自实际调用账本，不含作者 fixture 注入、本地确定性重算或本地模拟 HTTP 响应。逐轮机器汇总、每任务次数和提供商请求耗时见 [合并账本](LEDGER_20260919.json)。其中耗时是 API 请求耗时之和，不是用户端总等待时间，不能据此做完整性能排名。

### H1 → P1：补上真实协议兼容

真实 DeepSeek 非流式 `tool_calls` 项包含 `index`，原转发层仅允许 `id/type/function`，因此严格校验失败。模拟响应此前没有这个字段，未覆盖真实差异。

修复只接受与列表位置一致的、非布尔整数 `index`，规范化后移除；向 Harness 发送 SSE 时重新生成标准 index。其它未知工具字段仍拒绝。失败响应现在保留脱敏原文和固定诊断代码；格式校验失败仍计入失败调用。

P1 响应已通过离线回放，并加入真实运行时/真实 MCP/模拟模型的集成用例。H1 原始失败记录保留，不能把它们删除后展示一条连续质量提升曲线。

H1 运行期间另有一次转发层审计补丁落盘；其内容不改上述校验器，但没有记录模块导入时哈希，因此不能声称 H1 与最终工作树严格同版本。具体时点、差异和加载证据见 [H1 代码时序说明](H1_RELAY_CODE_TIMELINE_20260919.md)。H2、H3 启动前分别冻结代码并保存新快照。

### H2：工具循环有效，答案复核仍会漏错

H2 五任务真实调用数依次为：错误控制题 2、修正版控制题 2、英文 CPU 6、中文 CPU 8、中文事务 12。

- 两控制题均被判为 medium，而目标为 hard，因此在难度门被拒绝，**未执行答案 review**。不能把错误控制题被拒绝算作答案检查器检出，也不能把修正版被拒绝算作答案检查器误拒。
- 英文 CPU 的 review 多写了 `tool_requests`，违反严格 Review schema；尽管有工具循环和复核文本，仍没有发布草稿。
- 中文 CPU 被批准，但解释中的剩余服务时间和时间线矛盾，还存在未被计算工具覆盖的额外比较论断。工具已经算对一组输入，模型仍可能转述错或增加没有验证的结论。
- 中文事务修订稿被批准，但其 Repeatable Read 分支遗漏了并发更新冲突：快照之后已被另一事务修改的同一行，后续更新应发生序列化失败，不能按作者描述完成两次提交。复核模型也漏掉了这个前提。

因此，“新题草稿通过 1/3 → 2/3”只是系统接受行为变化，**不是准确率从 33% 提升到 67%**。这两个已批准候选都发现了问题，本轮未证明候选后端更可靠。

每个作者候选、计算重放、难度判断及正确性评分见 [H1 原生复核](H1_NATIVE_REVIEW_20260919.md) 与 [H2 候选复核](H2_CANDIDATE_REVIEW_20260919.md)。两份复核的诊断分制不同：H1 用 C=1/0/U，H2 用 0/50/100 的部分正确程度；本报告不将它们混合平均。正式比较应先统一标注协议，再由评审者逐项重新标注。

### H3：显式绑定各阶段的输出字段

候选 adapter 从 v1 修订为 v2，明示当前角色及允许的最终 JSON 顶层字段，明确 author/review 不接受 `tool_requests`、`tool_results`。外层原生 v3 任务契约和评分门槛未改。

英文难题首稿仍被难度门判 medium；作者计算时使用 `before`，最终题干改成 `after`，导致工具参数与题面脱节。修订稿在 HTTP 200、`finish_reason=stop`、ACP `end_turn` 的情况下，仍因 JSON 引号转义失败而被拒绝。

本轮没有到达 review，因此不能声称这次提示修改已通过真实测试修复了 H2 的额外字段问题，更不能声称提升了答案分数。它作为一个明确的负结果保留。详见 [H3 针对性试验](H3_SCHEMA_PROBE_20260919.md)。

## 4. 难度稳定性与实验设计修正

H1 两份控制题的盲解输入逐字段相同，输入哈希相同，但分别得到 hard、medium，两次都自报高置信度。这证明至少观察到一次不稳定标签，不足以估计稳定性概率。

事后 AI 审阅也认为该控制题接近 medium/hard 边界：应用两种算法、计算指标并选择明显占优者，并不一定形成真正需要权衡的困难问题。原先把它硬设为 hard，不应继续作为未经校准的“难度金标准”。

下一版正式评测宜把“答案正确性控制题”和“难度匹配控制题”分开，让正负答案样例确实经过同一个答案校验节点；保留模型标签、AI 事后标签和教师标签的来源差异。正确性、题面完整性、难度、结构合规和成本分别报告，避免较早的拒绝掩盖下游漏检。

## 5. 验收与当前选择

- 完整回归：**1088 passed，6 skipped**。包括真实本地 Harness/MCP 集成，但其上游模型全部模拟；不把这些测试算成真实出题成功率。
- 最终 v2 提示修订后，相关回归及本地运行时集成：**209 passed**。
- 验证范围包括：两个受限工具、三角色新会话、无前角色上下文混入、资料停用与跨账号阻断、真实账本额度、超时取消、正常恢复、父进程退出后的子进程清理、真实工具响应 index 兼容。
- 固定版本与 wheel 哈希归档；实验文本文件已检查无当前配置的提供商密钥。真实密钥没有进入 Harness 子进程。
- 本地服务已加载本次更新，首页与 OpenAPI 返回 200，未登录读取任务证据返回 401。未修改账号数据或创建真实用户内容。

当前保留 `AGENT_RUNTIME=native`；`deepseek_harness` 可用于继续受控实验。下一轮优先把**题目参数、工具输入、答案数值绑定为同一个结构化对象**，由程序填入已验证数值，再分别检查文字解释、未覆盖分支及教学难度。数据库类题目还需要对应的执行或规则验证工具。本轮没有实现这些后续研究项。
