# H5：Harness 思考模式、严格 JSON 与固定题目复核

本轮已完成：39 次真实调用，529,205 tokens；全部失败、预算调整及原始响应保留。固定题复核显示可行性，完整新题生成仍不稳定，因此不切换生产默认配置。逐组结果和最终判断见本文末节，机器可读汇总见 [H5_RESULTS_20260919.json](H5_RESULTS_20260919.json)。

## 目标与预先固定的比较方法

上一轮 H4b 的英文题在答案复核阶段输出了说明段落和 Markdown 代码块，整体违反 JSON 契约；M1 的六题诊断则提示开启思考值得继续测试。本轮先改善协议与配置，再分别验证固定题目复核和新题生成。

计划在实际调用前固定为：

| 实验 | 输入 | 思考 | 输出格式 | 目的 | 调用上限 |
| --- | --- | --- | --- | --- | ---: |
| H5J | H4b 中英文两道冻结规格，作者为注入数据 | off | json_object | 在旧思考设置下验证格式控制 | 12 |
| H5T | 与 H5J 完全相同的冻结规格 | high | json_object | 固定题目下比较复核与难度判断 | 12 |
| H5G | 同一中英文课程要求，从头生成规格 | high | json_object | 验证完整作者→解题→复核流程 | 18 |
| H5C | 既有错误答案 canary，作者为注入数据 | high | json_object | 检查错误是否被实际拦截 | 6 |
| 合计 | 7 个任务，均使用隔离实验数据库 | — | — | — | 48 |

其中 H5J/H5T 各最多 12 次调用，H5G 最多 18 次，H5C 最多 6 次；每阶段最多四次请求，每次 8192 输出 token，包括思考消耗。全部使用请求型号 `deepseek-flash`，默认不自动重试网络或格式错误。仅从头生成的作者保留原有一次有界修订。

这不是 Gemini 比较，也不是留出集结果。H5J/H5T 使用参与开发的既有题目，复核提示还新增了明确的最终 JSON 要求；与 H4b 历史结果相比不属于仅改变一个变量。H5J 与 H5T 使用同一新版代码、预算、资料和冻结题目，区别为思考设置，但每题仅一次，仍不能证明统计显著性。

## 实现

- 新增 `HARNESS_REASONING_EFFORT=off|high` 与 `HARNESS_RESPONSE_FORMAT=text|json_object`。配置写入任务检查点；模式改变不能续接旧任务。
- profile 明确设置 enabled/high；转发层在请求时验证并补齐一致参数，不允许运行时或提供商额外参数悄悄更改实验条件。
- JSON 模式由转发层直接加入上游请求。官方固定版本适配器本身没有透传该参数，不能仅靠 profile 声称已开启。
- 工具循环保留先前 assistant 的 reasoning 字段。high + tools 历史缺失该字段、强制指定工具或配置冲突时，在调用前拒绝。
- 最终响应只接受一个完整 JSON 对象；拒绝前后说明、代码围栏、重复字段、NaN/Infinity、截断、拒绝响应和非对象。随后仍需通过业务字段校验及答案/难度门槛。
- 不通过裁剪文字、抽取大括号或另一次无记录调用来“修复”错误输出。API 调用及失败继续进入原账本。
- 原模型、课程权限、可用工具、并发和调用上限继续适用。实际思考内容供模型工具续接使用，不作为公开的质量证明展示。

JSON 模式控制语法，不等于严格 JSON Schema 生成，更不等于事实正确。本轮不宣称接入了 DeepSeek Beta strict 工具参数模式。

协议依据及固定安装包证据见 [研究记录](H5_THINKING_JSON_RESEARCH_20260919.md)。

## 冻结规格重放

新增 `--replay-specs`，读取此前实验中已成功编译的作者规格，校验资料一致、引用合法、只有一题、当前重新编译的规格哈希及完整生成内容哈希均不变。完整原记录哈希、规格、编译题目哈希及注入行为单独保存；作者阶段不会调用模型，也不会当作新生成计分。

运行示例（默认去掉 `--live` 就只保存计划）：

```sh
.venv/bin/python scripts/harness_correctness_experiment.py --live \
  --runtime deepseek_harness --question-spec cpu_schedule_v1 \
  --cases cpu_en_hard cpu_zh_hard --thinking high --response-format json_object \
  --replay-specs docs/agent/harness-experiments/H4B_20260919 \
  --call-cap 12 --harness-max-requests 4 --max-output-tokens 8192 \
  --output docs/agent/harness-experiments/H5T_20260919
```

## 测试与实际结果

### 第一阶段：H5J / H5T 原始失败保留

| 组别 | 实际调用 | 总 token | 英文冻结题 | 中文冻结题 | 交付 |
| --- | ---: | ---: | --- | --- | ---: |
| H5J：off + JSON | 6 | 54,285 | 复核增加 `feedback_note` 字段，被严格字段校验拒绝 | 解题把 RR 的到达顺序读反，被工具输入与规格绑定校验拒绝 | 0/2 |
| H5T：high + JSON | 8 | 97,474 | 同样增加契约外字段，被拒绝 | 工具输入绑定、复核字段及模型质量门槛通过 | 1/2 |

14 次请求均返回 HTTP 200，平台均未返回费用，不能报告为免费。JSON 对象模式解决了这四次任务中出现于最终响应的语法包装问题，但不能保证业务字段正确。开启思考的一组在两道题的输入绑定上都通过；样本很小且只有一次采样，不能推出普遍准确率。原题的数值核验继承 H4b 冻结题独立检查；本轮模型难度判定不能替代学生难度校准。

原始账本、响应、失败与检查点保存在 `../harness-experiments/H5J_20260919/`、`../harness-experiments/H5T_20260919/`，不覆盖。

### 观察失败后的有界方案修订

以下是看到 H5J/H5T 结果后增加的开发实验，不能称为预注册条件，也不能替换上表的原始失败。新增 `HARNESS_SCHEMA_REPAIRS=0|1`，默认 0；实验中设置 1，仅在解题/复核返回完整 JSON 对象、但未通过业务字段校验时，允许一次新的独立重评。新请求使用原题、原始证据与字段校验诊断，不提供上次错误响应的答案或结论。每个阶段最多一次，原始响应和新增调用分别留档，继续受任务总调用预算约束。合法的否定质量判断、格式截断、非法 JSON、HTTP 或网络失败不会触发这个分支。

| 修订后组别 | 条件 | 剩余调用上限 |
| --- | --- | ---: |
| H5S | 冻结两题，high + JSON + 单次字段重评 | 12 |
| H5G | 从头生成中英文两题，同 H5S 设置 | 16 |
| H5C | 既有错误答案 canary，同 H5S 设置 | 6 |
| 本轮总量 | 已用 14 + 最多新增 34 | 48 |

H5S 与 H5T 的差异包含字段重评功能和对应适配器版本。重评是新的模型判断，不是保持语义不变的格式修正。“一次重评”指一个新的 Harness 阶段，该阶段可有最多四次模型往返，不是最多增加一次 API 请求。新增 token、延迟与调用都须计入。离线协议测试、真实模型结果、AI 数值复核与学习者难度证据继续分别统计。

### 第二次有界修订：生成阶段输出预算

H5S 实际 8 次调用，两道冻结题均通过，且**没有触发字段重评**，不能把成功归因于新增分支。H5C 实际 4 次，正确性复核明确否决已知错误答案。H5G 实际 6 次，两道新题均在作者阶段以 `completion_tokens=reasoning_tokens=8192` 耗尽预算，未产生可编译规格；这是端到端失败，不能从正确率分母中删除。

此前实际累计 32 次。因此在开始后续调用前，追加 H5B：使用相同新题要求与 high + JSON + 单次字段重评条件，仅把每次输出上限从 8,192 提到 16,384；阶段请求上限仍为 4，本组总调用上限 16，本轮全部实验最多 48 次。此为见到截断失败后进行的预算探索，不是预先固定的主对照；提高 token 上限也提高潜在成本。不会自动续接或覆盖 H5G 失败任务。

脚本原先将输出上限限制在 8192，首次输入 16384 被参数检查拒绝，产生 0 次调用。随后将脚本和环境配置的有界上限同步提高至 16384，新增边界测试后运行 H5B；默认仍为 4096。H5B 代码快照因此与 H5G 有这处参数范围差异，未改题目要求、思考档位或生成提示。

## 全部真实结果

| 组别 | 实际调用 | 总 tokens | API 耗时累加 | 交付 / 检测结果 |
| --- | ---: | ---: | ---: | --- |
| H5J：冻结题 off + JSON | 6 | 54,285 | 23.225 秒 | 交付 0/2；字段失败、规格绑定失败各一题 |
| H5T：冻结题 high + JSON | 8 | 97,474 | 84.580 秒 | 交付 1/2；另题字段失败 |
| H5S：冻结题 high + JSON，允许字段重评 | 8 | 98,653 | 93.647 秒 | 交付 2/2；实际重评 0 次 |
| H5G：从头出题，8192 输出上限 | 6 | 113,194 | 125.290 秒 | 交付 0/2；两题作者输出截断 |
| H5C：注入已知错误答案 | 4 | 32,119 | 26.191 秒 | 正确拦截 1/1；不是新题交付样本 |
| H5B：从头出题，16384 输出上限 | 7 | 133,480 | 127.285 秒 | 交付 0/2；工具历史增长触及请求体上限 |
| 合计 | **39** | **529,205** | **480.218 秒** | 不混合不同目的、不同分母的评分 |

API 耗时是逐请求累计，包含运行时间重叠，不能当成整轮墙钟耗时。39 次实际提供商请求均 HTTP 200，请求及返回编号均为 `deepseek-flash`；其中 H5G 两次响应不完整，被本地完成结构校验记为失败。token 字段无缺失，39 次均缺失费用字段，无法据此给出实付金额。没有发生未登记的真实模型重试；本轮实际 39 次，低于 48 次硬计划上限。

### 固定题结果如何解释

H5J/T/S 都使用同一对 H4b 中英文题，完整题目、答案和说明的哈希一致，**不能当作六道独立新题**。两题原有数值已经通过独立复核，本轮衡量模型是否忠实读取题目、输出正确字段、作出质量判断并完成交付。

H5S 的普通 solve/review 四个角色输出第一次就符合字段约束，未执行任何 `_schema_repair`。其相对于 H5T 的 2/2 与 1/2 差异是重复采样结果，不能声称“字段重评把成功率提高到 100%”。这项新机制当前有离线故障注入证据，**真实模型恢复成功率仍未测得**。

H5J/T 共七个完整角色响应均是合法 JSON，其中两次含额外字段而失败；H5S 四个及 H5C 两个完整角色响应均通过字段校验。从未完成作者输出的 H5G/B 不能凭这个“已完成响应”分母声称格式成功。high 条件的工具调用确实发生，实际 wire 中存在思考参数、JSON 模式和工具后的完整 reasoning 历史，确认了当前接口与固定 Harness 的联合兼容性。

详见 [H5J/T 独立审计](H5_JT_AUDIT_20260919.md) 与 [H5S/G/C 独立审计](H5_SGC_AUDIT_20260919.md)。数值正确、自然语言解释正确和 hard 难度成立仍是三个不同判断：模型评为 hard 不等于学生实测难度。

### 错误答案是否真的被抓住

H5C 使用已知错误的 Q016 作者答案，作者为注入数据。复核明确返回 `answer_correct=false`、`explanation_correct=false`、`calculations_verified=false`，并正确指出已经等待的 B 应在边界到达的 C 前面：RR 平均响应为 **1**、平均周转为 **20/3**；STCF 分别为 **0** 和 **5**。独立核算与这些纠正一致。虽然难度也被评为 medium，本次拒绝具有独立的正确性依据，不能只算成难度门槛碰巧拦截。

### 新题作者阶段的两种失败

H5G 两个末次响应都为 `finish_reason=length`、空 content、无 tool_calls，`completion_tokens=reasoning_tokens=8192`。这证明输出预算耗在思考中，尚未返回完整规格；不是已经生成的题目被证明数值错误。

H5B 加大预算后，英文完成四次、中文完成三次有效模型往返，但每次都继续请求工具，没有提交规格。两题在各自的官方会话日志 `turn/end` 中均记录 **HTTP 413 / “The relay request exceeds the local size limit.”**。本地转发层限制请求体为 100,000 字符 / 300,000 字节；思考历史与完整工具轨迹共同增长。英文在下一次请求前也已用满四次阶段额度，但日志显示直接拒绝原因是先发生的大小检查，不能将其单独归因于 429 调用上限。

H5B 没有长度截断，也没有得到可编译候选；两题仍按端到端失败计入。提高输出预算未在这两个样本中解决生成交付，故不继续无界加大预算。H5G/B 共四个从头生成任务均未产生最终规格，不能报告新题答案准确率或难度符合率，只能报告本轮新题交付 **0/4**，并保留两个预算条件各自的 **0/2**。

## 本轮选择与下一阶段假设

保留可配置 high 思考、受控 JSON 模式、严格字段检查及一次有界字段重评，作为可选实验能力；当前证据支持继续研究固定题的独立复核，不足以将整套 high 作者循环直接设为默认，也没有证明它优于其他模型的完整出题流程。

下一阶段优先测试**短作者阶段 → 确定性计算 → 独立思考复核**：每轮作者只提交一个有界规格，程序计算后筛选或反馈具体约束，不让作者在同一会话中反复搜索大量工作负载。需要设定候选数量与工具调用预算，预留最终提交机会，并把完整轨迹保存在证据中，仅向新阶段提供与当前候选有关的事实。避免在必须完整保留 reasoning 的同一工具循环里随意截断历史。

这仍是后续待实验的假设。本轮没有实现候选搜索器，也没有给所有角色统一开启 high、切换生产后端或宣布解决全部答案错误。论文可据此讨论：协议可用、判断正确与整个任务可交付之间的差别，以及思考预算、工具探索和上下文增长的共同约束。
