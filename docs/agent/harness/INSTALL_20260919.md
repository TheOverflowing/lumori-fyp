## 教学专用 ACP 配置

`app/harness_profile.py::profile_patch(model, base_url, max_tokens, session_root)` 生成 JSON；JSON 也是合法 YAML，可以直接作为 `--patch` 文件。该函数是本任务按根代理后续授权交付的唯一 app 文件。

实际启动形式：

```text
dsh --profile education --from-default-profile acp --patch /absolute/profile.patch.yml
```

创建后的 education profile 可继续使用同一个 `DSH_HOME`；本次复用时直接传 `--profile education --patch ...`。运行环境仅显式提供 `PATH`、`DSH_HOME`、`PKG_NATIVE_CACHE_PATH` 和假代理令牌 `FYP_HARNESS_PROXY_TOKEN`。真实模型密钥不进入子进程。

最终组合保存为 `education-composed.yml`，生成的 JSON overlay 保存为 `education-generated.patch.yml`。保留 18 个内部插件，包括 ACP、agent loop、LLM adapter、工具注册服务、会话 JSONL 持久化、checkpoint policy 和本地 projection cache；禁用 68 个默认插件。默认 shell、文件读取/修改、搜索、web、后台任务、子 agent、workflow、goal、skills、工作区指令发现、用户设置/凭证发现、遥测、session log 上传和插件清单上传均关闭。LLM 内部自动重试及辅助标题模型调用也关闭。

关键配置经过实际线协议检查：

```json
{
  "id": "llm-deepseek",
  "config": {
    "protocol": "chat-completions",
    "baseURL": "http://127.0.0.1:<local-port>/v1",
    "apiKeyEnv": "FYP_HARNESS_PROXY_TOKEN",
    "thinking": "disabled",
    "reasoningEffort": "off",
    "maxTokens": 4096,
    "models": [{"id": "deepseek-flash", "contextWindow": 131072}]
  }
}
```

同时显式覆盖 `acp.config.model=deepseek-flash`，没有替换成 `deepseek-v4-flash`。`131072` 是本地保守目录配置，并非本次测得的 provider 上下文能力。`thinking=off` 是本次候选配置的选择，后续实验必须记录它以避免与其他方案不公平比较。

模型请求实际落到 `/v1/chat/completions`，只有 `model/messages/stream/stream_options/thinking/tools/max_tokens` 七类字段；没有附带 session-log 或插件清单请求扩展。唯一模型工具来自 ACP `session/new.mcpServers` 声明：

```json
{
  "name": "probe",
  "command": "/Users/theoverflow/Downloads/FYP/.venv-harness/bin/python",
  "args": ["/absolute/mcp_probe_server.py"],
  "env": []
}
```

Python MCP 2.2.0 使用 `from mcp.server.mcpserver import MCPServer`；旧 `mcp.server.fastmcp.FastMCP` 导入会报错。实际本地服务器已使用 `MCPServer.tool()` 和 `MCPServer.run(transport='stdio')` 跑通。

该 overlay 是 **0.1.5rc1 的版本特定禁用列表**，不是跨版本 allowlist，也不是操作系统沙箱。升级时必须重新审计完整 composition 和实际工具目录。生产接入应验证 wheel 版本与 CLI 版本；本机 executable SHA256 可进一步确认准确构件。可以按已验证路径、inode、mtime_ns、size 缓存成功结果，避免每次 phase 都启动一次版本检查。

## 实际验收结果

| 检查 | 结果与证据 |
|---|---|
| CLI / ACP 帮助、profile dump | 均 exit 0 |
| initialize → new → close → list → resume → close | 通过，`acp-handshake.json`，无 prompt |
| 新进程恢复前一进程持久化会话 | 通过，`acp-restart-handshake.json` |
| 官方 Python MCP 发现 | 成功，`mcp-probe.json` |
| 真实 Harness → 假模型 tool call → Python MCP → 假模型结束 | 通过，2 次 loopback 请求，`stopReason=end_turn` |
| 模型实际工具目录 | 两次均只有 `mcp__probe__echo_probe`；无默认 shell/fs/task/child 工具 |
| 慢 SSE 导致控制器 0.2 秒超时后发送 `session/cancel` | 返回 `stopReason=cancelled`，单次 7.94 ms 观察值 |
| 取消后同会话再次 prompt | `end_turn` |
| 关闭进程 → 重启 → resume → 再次 prompt | `end_turn`，两个 runtime 进程均 exit 0，stderr 均为空 |
| 持久化证据 | `mcp-session-1.jsonl`、`cancel-session-1.jsonl`，真实运行时落盘而非模拟 ACP |
| 调用数量 | 5 次本地假模型请求；真实 provider 请求 0 次 |

取消实验详见 `cancel-probe.json`。它模拟的是**控制器超时后主动取消**，不能据此声称 Harness 自动处理任意超时；7.94 ms 是一次本地模拟观察，不是生产性能结论。恢复实验经过正常关闭，未验证掉电或工具副作用执行中强杀的恢复保证。

探针源码在同目录归档，其原始实际执行路径是 `tmp/harness-install-probe/`；归档用于审计，脚本含相对自身位置的路径假设，不应把 docs 副本当成独立部署入口。运行的是官方原生 ACP，只有模型 HTTP 响应和 echo 工具输入是测试桩。

## 发现与处理的问题

1. 原生扩展默认解包到 `~/.cache/pkg`，触发 EPERM，外层只呈现 `ACP session persistence flush failed`。从实际 executable prelude 确认 `PKG_NATIVE_CACHE_PATH` 后，将其指向项目可写目录，持久化和恢复立即通过。没有修改系统 home 或接受 Xcode 许可。
2. 运行时内部 `deepseek-harness-runtime.json` 写着 `0.0.0-dev`，属于构件内占位元数据。本记录使用 dist-info、CLI 输出和 SHA256 三者交叉确认版本，不用该占位字符串判断版本。
3. 上游 master、PyPI rc 和 MCP 2.x 接口存在时间差；本次通过已安装运行时实测消除配置猜测。上游 [ACP 文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/acp/acp/README.md)、[DeepSeek adapter 文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-deepseek/README.md) 仅作为参考，最终证据是归档的真实 ACP 帧和请求。

业务账号隔离、任务预算、真实 provider 质量与比较评分仍属于主系统集成和后续实验范围，不能由此次 echo 工具验收替代。文件摘要在 `INSTALL_20260919.machine.json` 中保存。
