# A1 / A2：出题 Agent 首轮正确性实验

日期：2026-09-19。目的：验证大任务拆分、独立解题、确定性工具和有界修复是否能改善之前的答案错误。**这是开发阶段的小规模诊断，不是最终正确率评测，也不是 DeepSeek Harness 框架性能对比。**

## 1. 本轮做了什么

已有流程一次生成完整题组，失败后整组重做。首版 Agent 逐题生成，独立读题、调用工具、复核，最后用程序组装结果；每题最多修复一次。RR/STCF 使用本地计算器，不让模型执行任意代码。

研究选择参考 [DeepSeek Harness 官方说明](https://deepseek.com/harness/en/)、其 SDK/工具边界、LangGraph 持久执行和 Anthropic 的长期任务与 Agent 评测经验。官方性、成熟度、Python 桥接及适配取舍详见 [研究记录](RESEARCH_20260919.md)。本轮实际运行的是本项目的 Python 编排，**没有安装或声称运行 dsh / LangGraph**。

## 2. 预设材料与实验组

每轮固定 5 个任务：

1. Q016 原错误答案：注入旧 RR/STCF 题及其错误答案，期望拒绝。
2. Q016 修正答案：同题替换为验算正确的答案，期望接受。
3. 英文 CPU 调度 hard：模型从头生成。
4. 中文 CPU 调度 hard：模型从头生成。
5. 中文 PostgreSQL 事务 medium：模型从头生成。

两道 Q016 的作者输出是**注入的控制样例**，只有解题和复核调用是真实模型请求。不能把它们算成自动出题成功。Q016 的标注来自先前 AI 审阅与确定性验算，不是教师/学生标注。

三个生成任务复用 `benchmarks/difficulty/cases.json` 的开发集需求与 AI 整理资料；没有使用保留集。冻结上下文绕过线上 RAG，不测召回效果。所有角色使用实际返回模型名 `deepseek-flash`，不是跨模型独立评测。

| 组别 | 改动 | 原始目录 |
| --- | --- | --- |
| A1 | 逐题生成 → 独立解题（包含模型自行算出的答案）→ 工具 → 复核 | [20260919T094935231059Z](experiments/20260919T094935231059Z/manifest.json) |
| A2 | 工具优先：计算题先提取参数；不把独立解题的口算文字送给复核；补上严格 schema 和具体结构修复反馈 | [20260919T095242942229Z](experiments/20260919T095242942229Z/manifest.json) |

A2 同时包含多项开发修复，且每个需求只重复一次，没有固定供应商随机种子；不能把变化单独归因于某一句提示词。每轮真实调用上限 24，实际各 16。

## 3. 实际结果：放行不等于正确

| 指标 | A1 | A2 |
| --- | ---: | ---: |
| 旧错误 Q016 | 拒绝，但原因是模型未发工具请求 | 拒绝，列出部分正确数值差异，反馈仍有自相矛盾内容 |
| 修正 Q016 | **误拒绝** | 接受 |
| 控制样例决策符合预期 | 1/2 | 2/2 |
| 三个新生成任务完整草稿放行 | 0/3 | 1/3 |
| 英文 CPU hard | 修复后仍拒绝 | 修复后仍拒绝 |
| 中文 CPU hard | 第二次复核协议失败 | 修复后难度不匹配，拒绝 |
| 中文事务 medium | 两次作者输出未通过结构契约 | 模型放行，Codex 复查仍发现题面前提问题 |
| 真实 API 请求 | 16 | 16 |
| 记录的总 tokens | 83,495 | 72,503 |
| 有明确费用字段的请求 | 0/16 | 0/16 |

HTTP 层 32/32 返回成功，不表示 32 次生成或校验正确。两轮合计 **155,998 tokens**；供应商没有返回费用，无法给出完整美元成本。汇总里的 `known_cost_usd=0` 仅表示已知费用之和，没有费用记录时**不能解释为免费**。详见 [账本核对](A1_A2_LEDGER_20260919.json)。

A2 的 1/3 是**流程放行率**，不能写成“答案正确率 33.3%”。本轮没有产生通过 Codex 严格全文复查、可报告为最终合格的新题组。拒绝也不能一概记作正确拦截：A1 明确误拒绝了正确答案。

## 4. 关键失败及采取的修改

### 4.1 独立模型也会算错，并污染后续评审

A1 独立解题把 C 的到达时刻从 2 改成 3，或错误地让 C 越过已等待的 B；其答案同时包含正确和错误数字。即使工具随后给出正确结果，评审仍受这些文字影响，把完全匹配工具的修正答案说成错误。

A2 让计算题先提出结构化工具请求；评审仅收到题目、作者答案、工具输出及必要的可解性标志，不接收未经验证的口算答案。修正 Q016 因而在这一次调用中获准通过。这个结果证明该路径至少能工作，不能据此声称可靠性已达到 100%。

补充核查还发现：A1 中文 CPU 第二稿的核心时间线、指标和约束判断其实正确，只有局部解释需要编辑；保存下来的 review 却引用了作者未写过的错误数字。该复核另含不允许的字段，最终以协议失败停止。8 个 CPU 候选中 1 个核心计算正确、7 个有明确错误；这属于额外的 AI 与验算诊断，不是最终发布准确率，也不与 D1 的不同样本直接计算提升幅度。

### 4.2 工具输入与题面可能不一致

例如“任务提前完成不用满整个时间片”不等于“下一次切换免开销”。模型曾把前者错误转成 `early_finish_free=true`。工具对此输入可以完全算对，但不是题面要求的结果。因此记录工具结果之外，还必须检查参数对应关系；本版以模型门控检查，尚无形式化的题面绑定证明。

详细逐题计算审计见 [CPU 候选验算](A1_A2_CPU_CHECKS_20260919.md)。

实验后增加了一个工程保护（当前提示修订号 `20260919-tool-first-v3`）：复核若判定工具参数不匹配题面，下一轮作者只收到重新明确条件的要求，不再收到这些有争议的数值修订。原始工具和复核仍保留。此改动已加入离线回归，**没有计入 A2 的实测收益**。

### 4.3 结构反馈需要具体到出错字段

A1 事务题第一次给 medium 设置了 4 个步骤（量表要求 2–3），第二次漏了小节引用并增加 schema 不允许的 `type` 字段。只有“结构错误”的笼统反馈不足以修复。

A2 把当前档认知过程与步数范围直接写进 schema，明确资料不足的跨字段约束，并将脱敏后的字段错误及规则名作为局部修复反馈。原始失败输出保留，没有覆盖。

### 4.4 模型通过仍可能含不成立的前提

A2 获准通过的事务题只列出 S 的普通 SELECT 和 COMMIT，却追加“若 S 后来因序列化失败被拒绝”。在明确的 PostgreSQL Repeatable Read 只读事务中，这种序列化冲突不会发生；若要问一般重试知识，需要明确改成另一个会写入的事务或单独的条件讨论。资料和题面不能悄悄混用。

Codex 另外核对了 [PostgreSQL 17 原始文档](https://www.postgresql.org/docs/17/transaction-iso.html#XACT-REPEATABLE-READ)：同一行并发写冲突会中止 Repeatable Read 事务，不会像 A1 第二份事务答案所说直接覆盖已提交值；只读事务没有这种序列化冲突。本轮未实际运行 PostgreSQL，属于官方语义核对，不是数据库实测。

因此，**不能把 agent_review 的全部 true 当作金标准**。当前只有用户确认后的草稿才进入已批准内容流程。

## 5. Codex 评分口径

沿用用户希望由 Codex 逐组审阅的要求，本轮先对有确定预期的两个控制样例打“决策分”：每个接受/拒绝决定符合预期记 100，否则 0，组内平均。

| 组别 | 错误样例 | 正确样例 | 决策分 |
| --- | ---: | ---: | ---: |
| A1 | 100 | 0 | 50/100 |
| A2 | 100 | 100 | 100/100 |

这只是 **2 个已知样例的门控决定分**；A1 错误样例甚至不是因数值核对被拒，A2 错误样例反馈也有矛盾，所以此分数不评价解释质量。它不能充当整个系统正确率，也不能与 D1 的“难度40+正确性30+依据10+可答性10+清晰度10”题目质量分并图比较。

对于三个自动出题任务，保留完整成功/失败分母与逐题问题，不把未交付的题目补成成功。本次 Codex 已参与系统设计、看过样例标签和运行结果，评分是**非盲 AI 复查**，不是独立教师评价，也不以模型名称代替验证证据。

## 6. 工程验证与后续重点

离线测试覆盖：每题三阶段、精确数量和难度槽位、局部重做、未知在途调用显式恢复、同一任务发布幂等、账号/CSRF/来源状态、事务内总调用限制、800 区间工具输出的上下文压缩，以及 50 题的有界提示。全套 [Python 测试](VALIDATION_PYTEST_20260919.txt) **928 通过、6 跳过**；最终 v3 保护修改后的[定向回归](VALIDATION_FINAL_AGENT_20260919.txt) **95 通过**；[前端](VALIDATION_FRONTEND_20260919.txt) **66 通过**。50 题模拟共有 1 次模拟检索和 150 次模拟文本调用，不是 50 题真实生成质量测试。最后[本地服务检查](SERVICE_CHECK_20260919.json)确认已加载 50 题 schema、恢复路由、当前前端文件，匿名恢复请求返回 401。

目前可以确认工程路径已落地，但 hard 题的自动修复与一般知识题的语义校验仍未过关。下一轮应先做独立正确/错误题对照集，分别统计**错误接受率、正确误拒率、成功交付率**，再比较异模型复核、受约束的题面/答案结构、工具先生成数值事实后再写题。需要补充数据库和算法领域工具，而不是继续堆叠“请认真检查”之类指令。

所有组、失败、检查点、提示、响应、源码快照、真实账本均保留在各轮目录。不要覆盖本轮结果，也不要将开发集改进宣称为保留集或学生实测收益。
