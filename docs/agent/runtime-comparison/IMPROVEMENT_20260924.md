# Harness 引用协议改进与困难题复测

本轮完成了代码改进、固定输入复核和真实出题复测。最明确的工程结果是：**复核从抄写长引文改为选择当前成品的原文编号，两道旧的引用失败题都用一次调用完成复核，一道故意加入无依据结论的题仍被拒绝。** 困难题生成已有完整输出，但难度标签和成品质量仍不稳定。

## 实现

- 新增 `candidate-evidence-selection-v1`。程序从当前题干、答案、解析建立最长 400 字符的原文片段目录，保留字段、字符位置和候选哈希；模型选择 `stem_evidence_id` 与 `answer_evidence_id`，并解释语义判断。程序只把当前目录里的合法编号还原为原文，再经过原有结构、来源和逐项验收。独立解答与资料原文不进入成品目录；未知编号、字段混用和伪造原文字段被拒绝，负面结论不被更改。
- Harness adapter 升至 v8，保留原始编号和目录审计。扩展后的实际上下文仍受字符上限约束。当前题目的真实片段可能与要求无关，因此编号存在不能证明语义判断正确，模型仍必须解释要求是否真正满足。
- 作者提示明确 `Question`、`DifficultyDesign` 的合法字段和当前评分步骤数量；要求参考答案直接回应题目，区分材料缺项与事件不存在，并避免在困难题题干提前给出完整解释。
- 无效引用同时伴随难度不符时，修订反馈同时保留难度诊断和任务重设计要求，避免下一稿只盯着引用格式。
- 实验入口新增 thinking off/high，并单列“严格达到目标难度”和“调整难度后交付”计数，避免把草稿数量全部算成困难题成功。此计数改进发生在 R6 后；历史归档未回写，本报告指标从原 evidence 重新提取。

## 思考模式诊断：R6

英文同样目标 hard、单次仍为 8192 tokens，启用 high，计划最多 6 次调用。实际 **2 次、18,476 tokens**后失败：规划完成；作者响应 HTTP 200 但 `finish_reason=length`，8192 个输出 tokens 中有 7351 个思考 tokens，最终答案截断，系统拒绝。

这是单次 token 预算不够的证据，不是外网故障，也不能说明 high 在充足预算下质量更差。后续若研究 high，应预先单独设置思考/成品的可用输出预算并比较消耗；本次未切换产品默认配置。[完整响应与失败](R6_HIGH_20260924/humanities_en__deepseek_harness.json)

## 成品检查与局限

引用编号解决了“引文是否属于当前成品”的机械问题，没有解决所有内容判断：

1. 英文首次要求约 200–300 words，参考答案按空白分词为 **414 words**；重复组要求约 300–450 words，答案为 **551 words**，且题目要求 continuous essay，答案仍按编号展开。应用未拦截这些篇幅/形式差异。
2. 中英文题干仍给出了较多解释方法、可能立场或示例，作者对减少支架的提示遵守不足。因此，即使首组被模型标为 hard，也没有教师或学生数据证明真实难度。
3. 中文答案把概括后的学生材料当作逐字原文引用，并把某些来源说明归到“材料三”，归属措辞需教师核对。英文首次从集体 “we” 推到各参与群体的所有权分布，属于解释而非直接建立的事实。
4. 重复组拒绝了一个解释候选，但其中部分理由可能把允许的释义或题目自身的评分要求当成“无来源”，有误拒风险。无效引用减少之后，语义漏检和误拒应成为下一组固定正负题的验证重点。

这些是开发 AI 对实际成品及冻结材料的复核，不是独立教师盲评。原始文本保持不变，以上问题不因交付成功而删除。
