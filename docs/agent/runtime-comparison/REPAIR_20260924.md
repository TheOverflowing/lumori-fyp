## 修了什么，为什么不是简单加额度

1. **规划字段：**R1 英文规划把 `argument_with_counterargument`（支持的任务名称）填进 `requirement.kind`（只能取六种类别）。`assessment-contracts-v6` 在规划提示和输出约定中明确区分两者。`HARNESS_SCHEMA_REPAIRS=1` 时，完整 JSON 中的字段类别、缺失或额外字段可触发一次新的规划判断；原计划与新计划都留档。来源范围、要求编号等业务边界错误不触发重评，第二次仍不合格就停止。R2 英文真实运行用了一次规划结构重评，随后才派发子任务。
2. **调用预算：**R1 中文在 8 次上限前无法完成修订。本轮每任务上限设为 12、R2 全轮上限 24、R3 独立上限 12。R2 中文首候选只用 5 次就完成，说明这次中文交付不能归功于增加额度。R2 英文用满 12 次仍失败，也说明单纯提高上限不能保证 `hard` 输出。
3. **无效引文：**R2 英文复核把答案意译当作逐字引文，重评后仍有不在实际答案中的片段。R3 将复核提示收紧为从题干与答案/解析中复制 8–80 个连续字符，不拼接、不改标点；当独立解题已判难度不符时，跳过注定无法改变交付结果的引文重评，保留失败证据并将额度留给下一候选。R3 英文仍有一次无效引文和一次作者结构错误，第三候选才通过。
4. **难度条件：**R2 的英文 `hard` 多次被独立解题判为 `medium`。材料自身包含相当明确的解释方法和可接受立场，因此 R3 **明确改为 `medium`**；这是一组新的实验条件，不能拿它回填 R2 的困难题成功率。

R1、R2、R3 的模型样本与代码条件不同，不能从三轮推断某一项改动的单独因果效果，也不能据此认定 Harness 的总体质量高于或低于 native。

## 成品的独立只读复核

- **中文 `hard`：**题目要求比较机构简报和读者回忆，区分陈述、推论及证据空白，并回应竞争解释；答案逐项回应，未见明显脱离主题。不过答案把“试行不增加人员预算”进一步表述为“人员总量与总工时受约束”，后半句没有被材料直接量化证明。题干已经提供长篇方法说明及六条细化任务，模型给出的 `hard` 标签不能代替教师或学生难度验证。
- **英文 `medium`：**题目与答案覆盖了两位叙述者、竞争解释和证据边界。答案有“which contributions were rejected”一类措辞，可能把“材料没有列出被拒稿件”误读为“确有被拒稿件”；这一前提须改为未知。参考答案约 377 个英文词，而题干称为 short interpretive response，篇幅适配也应由教师判断。应用门槛通过只说明结构、引用检查和模型复核通过，不证明这些语义细节无误。

这次复核由开发过程中的 AI 对冻结材料和草稿逐项阅读，不是盲评、教师金标或学习者测试。成品仍应保持待教师审核状态。

## 验证与剩余问题

规划错误的有限重评、不开启重评时只调用一次、来源越界直接拒绝、难度不符时不额外修引文，都有模拟模型回归。最终相关 Agent/契约/Harness 测试 **224 passed、4 skipped**，`git diff --check` 与脚本语法检查通过。R2/R3 归档的 53 份代码快照哈希分别核对一致；扫描未发现本机配置中的提供商密钥。测试验证边界，不能代替真实内容评价。

英文 `hard` 仍未交付。下一轮应先由教师或统一量表判断冻结材料到底能否支撑困难题，再决定减少学生可见支架或更换材料；随后用同一组要求交错重复运行 native/Harness，并把**交付、错误接受、错误拒绝、事实与推理、难度、调用量**分开统计。继续增加调用额度之前，应确认失败确实来自额度，而不是题目目标与材料不匹配。
