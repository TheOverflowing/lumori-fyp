# P4 协议补充

2026-09-18，候选开发实验。

- Advanced 复用 P3 已通过的同一权重/运行时运行检查，仅更改档位。没有为 Advanced 重新生成一份独立的合成样例运行检查；新装的 Docling、GraniteDocling、PaddleOCR-VL 运行时先做非基准 preflight。原始方案文字保留，以此澄清既有运行时与新增运行时的区别。
- PaddleOCR-VL 1.6 官方 Transformers 示例仅支持元素识别/文字定位，不能冒充完整页级 PaddleOCR 管线。官方完整管线对 macOS 建议 Docker；本机可行性与任何自行组合的版面+元素识别流程必须分别命名，不能用外部完整管线成绩替代本项目分数。
- 主要对照仍使用已有固定12页；新样本的选择和配置将在读取其模型预测前单独冻结。没有使用模型输出生成或纠正金标准。

- 后续核查专门的官方 Apple Silicon 指南，确认完整 PaddleOCR-VL 可以用本机 Paddle CPU 版面检测 + MLX-VLM 服务；这修正了先前仅根据通用模型卡所作的可行性判断。参见 https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/PaddleOCR-VL-Apple-Silicon.html 。本次服务只监听回环地址，使用公开已校验本地权重。
- 增加表格 TEDS 诊断，协议单独固定在 table-protocol.json；它是在部分文字结果可见后新增的描述性分析，不冒充完全预注册的主指标。

- 确认集预测前发现应用解析器在P1后有资源清理/错误处理改动，虽无显然影响本轮单页adaptive识别逻辑，为保持基线精确可比，确认阶段直接动态加载P1冻结的app/document_parsing.py，使用同样参数。新应用源文件不回滚。实际模块路径和哈希记录在确认run配置及快照中。

- Advanced 的正式早期批次与依赖下载/合成运行检查有重叠；其超时保留为本次240秒预算内的失败，但不把这一失败解释为模型内在识别能力必然较差。正文CER包含运行可靠性的影响；原始PDF无超时条件、语言分层和后续独立确认均分别报告。未经重复受控计时，不作稳定吞吐或超时概率结论。

- Paddle默认配置的开发p07原始PDF出现显著段落乱序后，新增关闭merge_layout_blocks的单因素变体。保留默认36次结果，变体另做全36次，不挑子集替换；该追加决策是开发数据驱动，而不是完全事前假设。独立确认预测仍未开始。具体时间、依据及选型规则扩展见 paddle-unmerged-amendment.json。

- 在任何确认预测开始前，追加固定几何顺序候选并无条件进入第四组确认，详见geometry-preregistration.json。其开发指标复用未合并识别输出；不是额外36次推理。合成标题/双栏单测暴露最大Y间隙优先的问题，最终改为最上方合格Y间隙，修改发生在任何真实几何候选计分前，哈希与理由存geometry-rule-freeze.json。确认阶段不再改阈值或选样。

- 确认集没有figure类别金标准；在确认结构评分之前明确：此类总gold=0的集合仅保留原始预测/计数，PR均标N/A，不将该集合当作配图能力验证。开发集gold>0的既有一对一协议与数值不变。

- 原三组确认完成、几何原始识别仍在运行时，报告追加两个新增入围者（Advanced与固定几何方案）之间的描述性配对bootstrap区间，帮助说明最终排序的不确定性。此分析追加时已经可见部分确认预测，明确标为补充分析；没有更改主CER指标、候选、模型、阈值、参考或样本。
