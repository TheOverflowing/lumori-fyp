## 原流程与本轮变化

原流程：`PDF → pypdf.extract_text() → 逐页字符串 → chunk_pages → 课程索引`。TXT/Markdown 按 UTF-8 读取。它只提取 PDF 已有的文字层，没有 OCR、照片上传、图片提取或逐页质量报告。只要全文能生成片段就被接受，部分空白或无法识别的扫描页可能被遗漏。该版本保存在 `baselines/pypdf_20260918/`，P1 运行另有完整识别源码快照。

新流程：

```text
验证格式、文件大小、页数/像素限制
  → PDF 逐页提取原生文字；PNG/JPEG 没有文字层
  → 原生文字稀疏或疑似乱码的页进入本地 OCR
  → 保存逐页文字、方法、警告、坐标、原页预览和内嵌图片
  → 从保存的文字切分，关联原文件哈希、页码及图片 ID
  → 账号内建立索引；RAG 用同一份缓存解析文字组装上下文
```

本轮默认保留原生 pypdf 文字，OCR 使用 Tesseract PSM3、`chi_sim+eng`。Poppler layout、PSM6 和 RapidOCR/PP-OCRv6 作为比较候选，不能仅因为版本较新或输出看起来更整齐就自动替换。选型依据与负面案例见 [P1 对照结果](experiments/P1-baseline-adaptive-20260918/report.md)。

该应用默认选型来自 P1 的轻量候选比较。后续 P3 在独立环境实测 MinerU 4.0.2 Basic 与 Standard；混合正文平均 CER 有改善，同时保留英文退化反例和新增配图区域指标。P3 属于同一开发样本上的候选扩展，没有自动替换应用解析器或重解析用户资料。

P4继续在独立环境比较更强的候选和几何阅读顺序，并记录表格结构、内容与独立确认结果。研究选型与应用部署分开：这些专业候选尚未接入上传默认路径，实际用户文件仍按上面的轻量流程处理。

上传结束后的“有文字的页面”只表示覆盖率，不是识别准确率。空文本扫描件/照片仍保留源文件与可用的图像证据，报告标为未读出文字；没有片段时不能建立索引，不会编造文字让任务成功。

## 如何评判“解析率”

不存在覆盖所有文件和教学任务的统一百分比。按本项目目标，至少应同时记录以下层次。

| 指标 | 定义或依据 | 本轮情况 |
|---|---|---|
| 文件处理完成率 | 在规定资源内产生有效结果的文件 / 所有尝试文件 | 计算，包括失败与异常 |
| 文字覆盖率 | 输出非空文字的页面 / 所有参与页面 | 计算；不等于正确 |
| 字符错误率 CER | 替换、删除和插入字符数 / 金标准字符数，越低越好 | 有正文金标准的页计算；宏平均与微平均均保留 |
| 英文 WER | 词/标点 token 的编辑错误率 | 英文正文单独计算 |
| 正文初筛达标率 | 本轮预设 CER≤10%，且输出长度≥金标准80% | 自定义试验阈值，不代表可直接用于教学 |
| 阅读顺序 | 文本块先后顺序是否正确 | 本轮整页 CER 会暴露串栏；更细指标需独立评测 |
| 表格/公式 | TEDS、CDM，以及人工核对关键单元格、符号关系 | P4新增项目适配TEDS结构/内容评分；公式语义和人工关键事实准确率仍未测 |
| 配图区域与语义 | 区域框召回、图文对应、关系/数值正确性 | P3/P4对开发集原版/扫描版做区域匹配；P4确认集无Figure金标准；图意准确率仍未测，整页保存不算独立区域召回 |
| 视觉证据保留 | 是否能回到原页/原图 | 四个含图页单独审计 |
| 效率 | 每页耗时、资源与失败原因 | 单次、非空闲机器的描述性耗时，不用于稳定吞吐结论 |

没有金标准的用户文件不会显示伪造的“准确率”；报告的 `recognition_accuracy` 为 `null`。OCR 模型置信度未经过本系统校准，也无法检测字符都对但顺序错乱的情况。

## PDF 配图的处理范围

1. 原始 PDF/照片完整保存，可下载核对。原图和所有新接口继续按账号、课程与文档授权。
2. PDF 页面渲染为预览图，保留矢量绘制的曲线、箭头和流程图；照片保留自身作为视觉来源。
3. 对 PDF 内嵌位图另外导出图片。位图可能是图表的一部分、背景或整页扫描，不能直接当作语义完整的“Figure”。
4. 每个图像记录原文件、页码、内容摘要与文档内 ID；OCR 坐标明确使用图像左上角为原点的像素单位。原生文字没有准确区域时保持 bbox=null，不虚构坐标。
5. “文字与原图”可逐页对照；生成内容的来源提供“查看原页”。重复解析保留旧图片登记，历史引用仍可访问旧图片。
6. 当前只对文字建立 RAG 索引。图意没有自动解释，生成提示明确禁止补全未转录的图中关系、可疑数字或公式。纯图教学内容仍需人工说明，或在后续引入经过评测的视觉语言模型。

后续视觉模型说明应单独存储为模型生成内容，附模型版本、源图、原文图注和人工确认状态；不得混入原始 OCR 正文冒充源文件事实。候选方案、图表/公式评价方法见 [研究参考](research/REFERENCES_20260918.md)。

## 评测数据与复现

首轮使用官方 OmniDocBench 发布的人工校验标注及页面，固定仓库修订与文件哈希。共 12 个独立来源页，分中文/英文、普通正文及表格/公式/图片复杂页；原版、无文字层扫描版、模拟退化图像为同页配对变体，不作为 36 份独立文档。数据包含一般论文/教材等，不是已完成的计算机本科课程专用测试集，也不是我们的新增人工标注。

复杂页的金标准含 HTML/LaTeX，不能直接与纯 OCR 文字做整页字符比较。因此严格 CER 在 6 个正文页上计算，另 6 个复杂页报告处理、文字覆盖和时间，并保存结构标注供后续评分。真实拍照集和课程级人工语义评审仍待补充。

P4另取12个源文档组作为[确认集](benchmarks/omnidocbench-confirmation-v1/README.md)，与开发组不重叠；其中8个文本页计CER，三个条件共24个相关评分样本。文本层按标注类别筛选，可能包含索引/试题。P4对开发集6个、确认集3个表格执行TEDS；确认集没有Figure金标准。具体来源、疑似参考标注噪声与隔离边界均保留，没有按模型分数换样或修订答案。

数据说明与原始文件见 [固定清单](benchmarks/omnidocbench-pilot-v1/manifest.json)。源文档遵循上游科研使用条件，不将项目代码许可证外推为全部文档的再分发许可。

```sh
# 建立研究用 OCR 独立环境，不更改主应用的 Python 依赖
.venv/bin/python -m venv .venv-parsing
.venv-parsing/bin/python -m pip install -r docs/parsing/requirements-ocr.lock.txt

# 具体数据准备和识别命令以以下脚本 --help 和 P1 冻结配置为准
.venv/bin/python scripts/prepare_parsing_benchmark.py --help
.venv/bin/python scripts/evaluate_document_parsing.py --help

# 软件回归；不代表文档识别准确率
.venv/bin/python -m pytest -q
node --test tests/frontend_*.test.mjs
```

P1 保存 216 次配对调用的原始输出、每页分数、语言分层统计、失败信息、配置、来源代码和运行时/模型哈希。重放旧实验应使用对应冻结代码与配置，不覆盖已有结果目录。小样本区间和全部失败均保留，不把开发集选择描述为独立测试集上的保证。

## 应用配置与使用

本机已有 Poppler 和 Tesseract，含中英文语言文件。新机器可安装 `poppler`、`tesseract` 与对应中文语言数据。RapidOCR 是可选实验运行时，只有明确设置 `DOCUMENT_OCR_ENGINE=rapidocr` 才用于应用；默认不启用该候选。

配置项已列入 `.env.example`：`DOCUMENT_OCR_ENGINE`、`DOCUMENT_OCR_LANGUAGES`、`DOCUMENT_OCR_MAX_PAGES`、`DOCUMENT_VISUAL_MAX_PAGES`、`DOCUMENT_PARSE_TIMEOUT`。默认每份最多 OCR 30 页、保存前 30 页预览、整份解析预算 120 秒，最多并行解析 2 份；单图上限 1600 万像素、全部图像资产最多 120 个/32 MiB。超过限制会留出逐页提示。原生 PDF 仍可最多 300 页，单次上传最多 10 MiB；需要完整处理更长扫描件时按章节拆分。

已有课程和向量不会在升级时自动重新解析。打开旧资料的“文字与原图”，选择“重新解析（需重建索引）”后，才更新解析报告并清除该资料当前向量；随后显式建立索引。旧生成内容中的引用文字快照保持不变。改变 chunk 策略时使用保存的解析文字重新切分，不重复 OCR，避免上下文和原索引来自不同识别结果。

新增数据保存在 `data/document_assets/`，报告与历史图片登记使用 SQLite 附表。备份需包含整个 `data/`；不要把私有资料、会话或 API 密钥提交研究仓库。此次公开基准解析没有向第三方模型服务发送任何课程资料，也没有使用付费 API。
