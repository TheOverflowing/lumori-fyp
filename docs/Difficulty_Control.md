# 难度控制规则与验收

## 当前规则：2026-09-20

本节描述当前实现。后面的 **2026-09-12 历史快照**保留当时的流程、调用数和真实实验结果；其中“两轮失败停止”“最多 10 题”和整批复核的费用示例不代表当前所有工作流。当前难度策略版本为 `difficulty-calibration-v1`，操作性量表仍为 `difficulty-rubric-v1`；新 Agent 的普通修复策略为 `question-repair-v2`。难度与导出验收见[原更新记录](ui/difficulty-export-polish-20260920/README.md)，本轮格式兼容与继续修正见[修复记录](ops/format-repair-20260920/README.md)。

### 目标设置与实际判断

测验／作业可生成 1–50 题，实际可完成数量受单任务和每日 API 调用上限约束。统一难度、全部某一难度及自定义整数题数分配均支持；每档可以为 0，分配合计必须等于题目总数。固定槽位、数量、题型及引用规则继续严格检查。学习讲解只控制讲解深度，不执行题目难度复核。

测验／作业默认只生成题目，不附带题前的学习目标与背景讲解；可开启“添加题前讲解”（`include_explanations=true`）加入这些内容。此开关不移除作答所需的题干条件、场景或数据，也不关闭答案解析；题目的难度计划与复核照常执行。学习讲解不受该开关影响。旧材料不会被自动修改，导出仍使用已保存版本；导出时是否包含答案与解析是另一项独立设置。

`difficulty_plan` 和题目中的 `difficulty` 记录用户要求的**目标档位**，不是已经测量的难度。`assessed_difficulty` 记录模型根据题目实际要求作出的判断。认知过程、评分要点和模型结论均不能代替教师评审或学生作答数据。

### 难度校准与候选保留

1. 首轮按原始目标生成并检查；严格匹配即可交付草稿，不必执行完三轮。
2. 若候选仅因难度不匹配而未通过，且该工作流的其他质量检查通过，则保留候选并继续修订，最多进行三轮。不会只修改难度标签来伪装达标；难度候选的保留与下文格式兼容分别记录。
3. 三轮结束后仍未严格匹配，复用已通过其他质量检查的候选。先考虑与目标相邻的档位；没有相邻候选时才接受任意档位。多个候选先比较最大档位差，再比较总差距和模型置信度，同等条件下采用较新的候选。该选择在本地完成，不继续无上限调用模型。
4. 较早的合格候选不会因后续候选出现质量问题而丢失。若有可保留的候选，系统交付草稿并明确标注目标与模型判断的差异；逐题 Agent 会继续处理后面的题目。

上述候选保留只放宽难度匹配。固定题数、题型、引用归属、资料支持、歧义和答案检查继续执行。Agent 的 Native 与 Harness 新任务均在答案复核完成后才把候选放入可保留集合；旧的整批流程仍使用其已有的资料可答性与歧义复核，不能据此声称已完成与 Agent 相同的独立答案检查。当前 `confidence` 是联合质量判断，不是独立的难度置信度，因此低置信度候选不参与难度放宽。

### 普通修复、格式兼容与继续修正

新 Agent 任务保存 `configuration.repair_policy`，普通尝试预算为 `max(3, AGENT_MAX_REPAIRS + 1)`：默认至少三轮，提前通过即可继续下一题。旧整批文字流程也先执行三轮普通尝试。无效结构会占用普通尝试次数，因此三轮不保证必定收到三份有效模型复核。缺少 `repair_policy` 的旧 Agent 检查点保留其原普通预算。

普通尝试耗尽后，纯格式问题可自动进入兼容处理。系统优先对已保存的原作者响应重新解析，保留原文与转换记录；兼容后继续资料检查、独立解题与答案复核，不把“能解析”当作“答案正确”。旧整批流程继续其原有整批复核，不因此获得 Agent 的独立解题能力。题型错误、非法引用、重复题、缺少作答条件或答案错误不作为单纯格式差异接受。

| 默认作者格式 | 兼容方式与仍保留的要求 |
| --- | --- |
| 选择题默认四个选项 | 核心存储／编辑模型接受 2–26 个不同的非空选项；六个选项可完整保留，不截成四个。答案必须映射到实际存在的 A–Z 选项。 |
| 答案使用选项字母 | `(B)` 等无歧义表示可以规范为 `B`，原始响应保留；不存在的选项不能凭空接受。 |
| 作者概念列表最多六项 | 兼容模型不以六项为上限，七项及更多概念可保留；非空、类型及其他有效性检查仍执行。 |

格式兼容阶段不另外设置“三次”或“六次”失败即终止的截止线，但沿用现有单任务与每日调用额度、上下文和服务限制。若兼容后发现实质内容问题，仍需重新修正，不能持续降低答案正确性要求。普通预算耗尽且没有可交付候选时，系统保留失败槽位与全部尝试；拥有完整检查点的任务可由用户点击“继续修正”，为未通过题目增加三轮尝试，已通过题目和原输入保持不变。续修沿用同一任务，累计调用数不归零，不绕过额度。

网络或提供方失败不会因为存在候选而自动绕过原有中断处理。调用、上下文和每日额度限制继续有效，不能保证任何失败都会产生材料，也不会为达到第三轮突破配置的调用上限。

### 状态、证据与版本

| 字段／状态 | 含义 |
| --- | --- |
| `configuration.difficulty_policy` | 新任务冻结的策略版本、三轮上限、放宽层级及不放宽其他质量检查的声明。 |
| `configuration.repair_policy` | 新 Agent 的普通尝试下限、用户继续修正的轮数及格式兼容版本；不授权忽略内容质量检查。 |
| `attempt.format_compatibility` | 本次候选采用的格式兼容记录；原作者响应保留，成功交付时内容配置也记录所选兼容结果。 |
| `slot.repair_extensions` | 用户明确继续修正时增加的轮数、开始轮次及授权时间；不删除既有尝试。 |
| `difficulty_acceptance.status = strict` | 交付候选的模型判断与全部目标档位一致；`strict_passed=true`。 |
| `difficulty_acceptance.status = adjusted` | 至少一题采用放宽结果；`strict_passed=false`，不能统计为严格难度控制成功。 |
| `acceptance_reason` | `target_matched`、`adjacent_level` 或 `any_level`。 |
| `items` | 分别保存每题目标、模型判断、置信度和是否严格匹配；Agent 汇总还记录每题轮次及所选候选轮次。 |
| `rounds`／`accepted_attempt` | 实际尝试轮数与被采用候选的轮次。Agent 总结的 `rounds` 为各题最大轮数，不是模型调用总数。 |

任务证据与内容配置均保存 `difficulty_acceptance`；Agent 还保留每个槽位的决定、原始复核结果和失败尝试。`passed` 的槽位状态表示该槽位已完成并可用于组卷，是否严格难度匹配须读 `strict_passed`，不能只看完成状态。界面分别展示目标与模型判断，放宽结果显示“难度已调整”。保存后仍是待用户审核的草稿。

新进度记录区分格式、内容、依据不足、重复题及难度差异，并显示格式兼容的开始与完成。简洁与详细视图使用同一任务状态和恢复操作；支持续修的失败任务显示“继续修正”，不再要求用户从空白表单重建任务。历史记录保持原措辞，不补造新分类。

“内容与审核”只显示当前课程的记录，各记录用对应类型的图标和文字标签区分。状态筛选、标题搜索、待审核计数以及运行中／失败任务均限制在该课程；切换课程时清空搜索并将状态筛选恢复为“全部”。

编辑内容会产生新版本，原版本的严格／放宽判断不能自动作为新版本结论。教师逐题评价、整体评分和真实学生作答指标继续与模型复核分开记录。

已有 Agent 检查点若没有 `difficulty_policy` 或 `repair_policy`，分别保留对应的旧难度流程或普通尝试预算，不因代码更新重新解释旧证据。提供方错误或中断的步骤可按原检查点继续；内容未通过但保留了完整失败槽位及拒绝记录的任务，可通过用户明确操作增加三轮修正。缺少可恢复记录、未完成的探索流程或已经耗尽的调用预算不会因此自动恢复。

### 失败后恢复输入

生成任务失败或证据不足后，可使用“返回修改 / Edit request”恢复已保存的课程、学习目标、材料类型、难度与分配、学习者基础、题型、数量、语言、资料选择、“添加题前讲解”和相关生成设置，再修改后提交新任务。已经确认的追问上下文用于恢复请求，不复用已消耗的准备令牌。

恢复入口使用 `GET /api/jobs/{job_id}/generation-request`，只允许任务所属账号读取，且仅接受生成任务。读取和回填不调用模型；再次点击生成才提交新任务。这与“继续生成”或“继续修正”不同：后两者沿用原 Agent 任务与检查点，保留已完成题目、历史尝试和累计调用数。中断的上游请求可能已经计费。

### 调用成本与验证边界

- 旧的整批文字工作流：正常题目生成需一次作者调用与一次整批复核；三轮均执行有效复核时为六次文字调用。检索、嵌入、重排、探索和资料索引另计。
- 逐题 Agent：通常每题包含作者、独立解题与答案复核三个角色调用；单题三轮均走完时为九次基础角色调用。规划、结构化题目说明、允许的响应结构重评、格式兼容后的检查与再生成、用户继续修正、检索和探索可增加调用，不能把九次当整个任务的固定上限。
- 本地选择难度候选或规范格式不增加模型调用；兼容后的独立解题、答案复核或再次生成会计入原任务预算。实际尝试、失败、耗时、token 用量和平台费用以任务证据为准；调用次数上限不是货币预算，缺失平台费用不等于零费用。

离线预设模型响应用于验证分支、候选选择、预算约束和恢复逻辑。它们不是新的真实模型实验，不证明题目正确率、难度判断能力或学生学习效果提升；历史真实实验结果保持原值。格式兼容与修复的验收范围见[更新记录](ops/format-repair-20260920/README.md)，前一轮难度校准验收另见[原记录](ui/difficulty-export-polish-20260920/README.md)。

### 原题要求与解释边界

原始《CEG 311 FYP选题介绍 AY2026-2027.pdf》第 27 页，项目 **AI-Powered Multimodal Content & Assessment Generation for Educational Applications** 的摘要要求生成 quizzes and assignments，并具有 “precise control over difficulty levels”。同页 CA1 要求为文献综述、系统设计及含核心文本生成与 RAG 的初步功能原型。原题没有规定难度档数、混合比例、某档最低题数或学生答对率区间。

因此，本项目采用以下可验证解释：教师明确目标学生和难度要求；后端精确执行题目数量与分配；记录生成、模型复核及教师逐题判断，报告控制成功与失败。三档划分和下面的评分要点数量属于本项目的操作定义，需要结合具体课程与导师反馈修订。

CMU 的 [Bloom 分类说明](https://www.cmu.edu/teaching/designteach/design/bloomsTaxonomy.html) 用学生可展示的行动描述教育目标；其 [rubric 指南](https://www.cmu.edu/teaching/assessment/assesslearning/rubrics.html) 强调用标准、描述和等级表达评分期望。本项目据此明确认知要求与审核依据。这是设计方法的应用，不是把 Bloom 分类转换为已校准的学生难度量尺。

本地 [CA1 文献综述](ca1/Literature_Review.md#intended-demand-versus-observed-difficulty) 已区分目标认知要求与实际难度。Cheng et al. 的目标对齐生成工作支持明确记录教育目标；Park et al. 的难度估计工作说明学生群体能力与难度判断相关。这些文献都不能直接证明本系统已经实现精确的学生难度预测。

### 教师如何设置

| 设置 | 行为 |
| --- | --- |
| 统一难度 | 选择简单、中等或困难，全部题目使用该档。例如选择困难、5 题，计划为 `0 / 0 / 5`。 |
| 按题数分配 | 直接填写三档的非负整数题数，允许任意一档为 0；合计必须等于总题数。总题数为 1–10。 |
| 全部简单／中等／困难 | 快速把全部题数分配给指定档，其余档为 0。 |
| 修改总题数 | 自定义分配不会重新平摊；合计不符时不能提交，教师需要同步调整各档题数。 |
| 学习讲解 | 只选择讲解深度，不生成题目，也不携带题目难度分配。 |
| 目标学生与已学基础 | 默认“已学习所选课程资料的本科生”；教师可填写更具体的课程基础，生成与复核使用同一背景。 |

题目顺序按简单、中等、困难展开，形成固定槽位 `q1` 至 `qN`。统一难度同样生成逐题计划。API 的 `difficulty_distribution` 存在时，以它生成的计划为准，全局 `difficulty` 不会覆盖自定义分配。后端拒绝负数、小数、布尔值、缺失档位及总数不符的分配；不会通过取整或补题悄悄改写请求。

### 三档操作性定义

| 档位 | 实际要求 | 允许的认知过程 | 简短评分要点 |
| --- | --- | --- | --- |
| 简单 `easy` | 识别或解释资料中的一个明确知识点；条件完整，无需选择复杂策略。 | `remember`、`understand` | 1–2 个 |
| 中等 `medium` | 在具体情境中应用已学概念，或比较、分析相关概念及关系；不能只改写定义。 | `apply`、`analyze` | 2–3 个相关联的要点 |
| 困难 `hard` | 在课程资料范围内综合概念、处理具体情境约束，并论证判断或设计。 | `analyze`、`evaluate`、`create` | 3–6 个关键要点 |

每题包含 `slot_id`、`difficulty`、`difficulty_design.cognitive_process`、`concepts`、`expected_steps`，并保留简短的 `difficulty_reason`。`expected_steps` 是可向教师和学生展示的答案评分要点，不是模型隐藏思维链。列出更多步骤、使用更长题干或写上“分析”两个字，都不能单独证明题目更难；困难应来自题目本身要求完成的任务。

认知过程与难度没有一对一关系：本量表的中等和困难均允许 `analyze`，区别还包括情境约束、知识整合及论证要求。评分要点数量用于保持设计可检查，不作为模型复核或人工评价的唯一判断标准。

### 生成与模型复核

1. 后端保存学生背景、固定题目计划、提示版本及量表版本；检索并保存课程来源。
2. 生成模型逐题按计划出题。确定性校验检查数量、槽位和顺序、难度标签、允许的认知过程、非空概念与评分要点，以及既有的题型、选项和引用规则。
3. 对结构有效且资料充分的测验／作业，通过单独的文字 API 请求复核整份题目。复核输入只含题干、选项、答案、解析、来源、学生背景及完整量表，不提供教师目标分配、生成模型的难度标签、设计字段或难度理由。
4. 复核逐题返回 `assessed_difficulty`、`confidence`、简短依据、是否能依据资料作答和是否不存在影响作答的歧义。任何档位不匹配、低置信度、不可答或存在歧义，都不会按通过处理。
5. 生成结构失败或格式有效的复核不通过，共用一次重新生成机会；重新生成后再次校验，并在适用时再次模型复核。两轮仍不满足要求则任务失败，不保存为成功材料，不改标签凑配额。

网络、上游 HTTP、预算／配置失败，以及复核响应 JSON、结构或槽位无效，均不会自动重试。资料不足时保留拒答原因，不通过降低难度完成请求。纯讲解没有题目复核调用。

“单独调用”指使用独立请求、上下文和不含作者目标的复核输入；当前生成和复核仍使用同一个 `deepseek-flash` 文字模型。因此这是模型辅助盲审，可能与生成模型存在共同偏差，也可能误判题目质量。模型复核只是筛查，仍需教师确认；复核通过不等于教师审核完成，不等于学生实测难度，也不证明引用的事实支持已被可靠验证。

### 版本、人工评价与导出

原始生成稿可显示模型复核状态。保存编辑后创建新版本，状态显示需要重新复核；原稿的模型判断不冒充当前版本结论。没有逐题计划与复核记录的历史材料继续可读，并显示尚无相应验证记录。教师批准内容也不会凭空创建模型复核结果。

教师可以给当前版本的全部题目分别选择 `easy`、`medium`、`hard` 或 `uncertain`；一组逐题评价须覆盖全部题目且不能重复。原有整体正确性、资料支持度和 1–5 难度匹配评分继续保留。

系统分开记录目标档位、生成标签、有效的模型判断和教师判断。教师与目标一致率等于“相符题数 / 可比较题数”；`uncertain` 和缺少历史目标的题目不进入分母，另行保留已评、可比较、相符和无法判断的数量。没有可比较题目时一致率为空，不是 0 或 100%。该值不是学生答对率。普通详情页的人工评分不能直接称为盲评；正式实验应在评审给出档位前隐藏目标与模型结论，并记录评审过程。

| 导出 | 内容 |
| --- | --- |
| `GET /api/jobs/{job_id}/evidence` | 请求、计划、来源、生成与复核尝试、失败诊断及脱敏调用记录，包含失败任务。 |
| `GET /api/contents/{content_id}/evidence` | 内容及版本证据、相应复核状态。 |
| `GET /api/difficulty/evaluations/export` | 单独的逐题难度 CSV，区分目标、生成、模型和教师档位，保留内容版本。 |
| `GET /api/evaluations/export` | 原有整体人工评分 CSV。 |

### 额外调用与费用

一次测验／作业正常生成现在需要一次查询嵌入、一次文字生成、一次整批题目复核，共 3 次 API 尝试；如果首轮语义复核不通过，重生和复核可再增加 2 次，总计最多 5 次。复核对整份题目批量进行，不是每题额外调用一次。讲解正常为 2 次，允许的结构修正可增加至 3 次。资料建索引的嵌入调用另计。

标准 CA1 smoke 的当前 14 片段样例，预期从历史流程的 9 次变为 11 次：1 次索引，4 次查询嵌入，4 次生成，另加 quiz 和 assignment 各 1 次复核；允许的修正全部发生时最多 17 次。实际尝试次数取决于失败位置，必须以运行证据为准。失败尝试和复核也计入调用上限，增加延迟和潜在费用；次数上限不是货币预算，缺少平台费用字段时不能按零费用计算。

2026-09-12 已保存的 `education-v2` [真实验收记录](ca1/evidence/live-20260912T040126795872Z/results.json) 仍然是实际 9 次调用的历史结果。它没有执行本轮新增的模型复核，不能作为 `education-v3` 的通过证据，也不会被改写。

本轮 [Python 全套 106 项自动化测试](ca1/evidence/difficulty-tests-20260912.xml)通过，失败、错误和跳过均为 0；三个 `frontend*.test.mjs` 的 33 项前端测试通过。`education-v3` 的 [真实验收结果](ca1/evidence/difficulty-20260912T042551358609Z/results.json) 使用隔离运行目录和自编资料，完成 14 片段索引，并分别请求全难 `0/0/3` 与混合 `1/1/1`。两份最终草稿的实际分布均与请求一致，6 道最终题目均通过模型复核，`technical_checks_passed=true`。

本次实际使用 9 次 API 尝试：索引 1 次、全难请求 5 次、混合请求 3 次。全难首稿的 `q1` 和 `q3` 被模型判断为中等，触发 `difficulty_assessment_failed`，没有直接保存为成功材料；重新生成后再次复核通过。混合请求首轮通过。首次拒绝及完整两轮结果保存在 [全难任务证据](ca1/evidence/difficulty-20260912T042551358609Z/all_hard-job-evidence.json)，混合结果见 [混合任务证据](ca1/evidence/difficulty-20260912T042551358609Z/mixed-job-evidence.json)。这 9 次属于本轮两个难度案例，不能与上节标准 CA1 smoke 的预期 11／最多 17 次，或历史 `education-v2` 的实际 9 次混同。

隔离 mock 浏览器环境另验证了全难 `0/0/5`；把总数改成 6 后提示缺 1 题并阻止提交；讲解深度独立且切回测验保留原分配；`1/2/2` 生成后逐题显示和 `model_checked` 状态；教师只评部分题目时阻止提交，全部选择 `uncertain` 并注明隔离测试后成功保存。这些是界面与业务检查，使用模拟模型响应和测试评分，不构成真实教师评价。

证据中的 `manual_quality_verified=false`、`student_difficulty_calibrated=false` 保持不变。此次观察证明分配约束及模型复核、拦截和重生路径在这些样例上实际运行，不能推出模型已准确识别全部题目难度，也不代表教师或学生已经确认题目质量。

[最终验证汇总](ca1/evidence/difficulty-verification-20260912.json) 保存测试结果、浏览器检查范围、真实调用证据入口、本地服务更新和代码校验值。

正式难度校准还需确定学生群体、收集答题结果，并采用适当的分析与研究设计。后续报告应分别给出结构通过率、模型复核结果、教师与目标一致率、失败／拒答比例及适用范围，不能合并成一个未经验证的“难度准确率”。
