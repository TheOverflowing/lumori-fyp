### P1：冻结当前版本并完成一次完整演示验收

建议选定一门有使用权限的计算机本科课程，包含中英文材料，用同一版本串起：登录 → 上传 → 解析 → 索引 → 讲解/测验/作业 → 引用核查 → 编辑/审核 → 学习视图。增加全难题、混合难度与证据不足拒答案例。保存请求、配置、输出、来源、失败、耗时和实际返回的 usage/cost；无费用字段不能按零计算。

新的验收应标明使用 FYP 研究仓库还是 Lumori 部署仓库及提交号。两者已是独立 Git 仓库，部署调整不会自动回流。现有 `scripts/ca1_smoke.py` 已适配登录/CSRF，可作为新验收入口；建议使用默认隔离数据模式，不覆盖原演示数据。真实调用后仍须检查材料内容。

### P1：形成可追溯的人工内容审核

现有 `Manual_Review_Form.csv` 只有表头；本机当前数据库的 `evaluations` 有 0 条记录，`contents` 有 3 条。历史真实验收文件均记录 `manual_quality_verified=false`。这说明当前查到的材料中尚无已完成的生成内容人工审核证据，不排除用户在系统外另有记录。

建议先做一轮小样本审核，例如 10–20 道题，加至少一份讲解，覆盖中英文及不同目标难度。该数量是工作量建议，不是学校要求，也不是统计充分性的证明。由熟悉课程的人记录正确性、引用是否支持答案、可作答性、歧义、目标难度适配、修改前后内容；写明审核身份，不能将助手或模型评分称为教师评分。有条件再安排第二人复核。

没有学生作答数据时，可以报告目标分配遵从与审核者难度判断，不能宣称已实现经验校准的题目难度或学习效果提升。人工审核是提高展示可信度的建议，不是从任务书原句推导出的额外硬门槛。

### P1/P2：把实验整理成与问题对应的证据

已有 R1–R5 与文档解析研究，无需为 CA1 无限增加候选算法。先说明研究问题、基线、控制变量、数据来源、开发/保留集、指标含义、结果与最终选择。

- R4 保留集答案跨度命中率为 97.02% → 97.02%，MRR@5 为 0.8868 → 0.9524：支持排序改善，不能写为召回率提升。
- R5 未支持默认开启查询翻译；保留失败与负结果，不能只列正向子组。
- MLQA 使用公开人工答案跨度，但不是计算机本科课程专属相关性金标。真实课程材料的切分审计不能替代课程检索相关性标注。
- 图像集成目前只有小规模开发样例；完成率、OCR 质量、图框检出与图意准确率不能混用。

若论文主张面向计算机本科课程的检索收益，后续应建立经过人工审核的课程 query→evidence 标签与独立保留集。这是正式研究结论的重要补强，不是“初始功能原型”必须先跑完的大规模实验。
