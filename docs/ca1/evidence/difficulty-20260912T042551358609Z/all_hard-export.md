# 检索流程、引用支持、嵌入兼容性与审核版本综合测评

状态：draft

## 检索流程与质量边界

根据参考资料，检索为生成器提供支撑材料，但检索到内容不等于结论正确。自动草稿不能仅凭引用标识通过验证就宣称获得人工批准，人工观察与评分字段应由人工填写，自动化测试应保持空白。证据边界被跨越时，应报告证据不足，而不是编造内容。

## 嵌入兼容性与版本约束

嵌入兼容性关注存储文档向量与查询向量的关系。向量必须具有相同维度才能比较坐标；即使维度相同，不同模型也可能使用不同语义空间，不能假设查询与另一模型生成的段落兼容。索引版本变化需要重建或更新受影响的存储对象。

## 审核记录、导出与本地运行限制

保留评估记录应包含初始草稿、实际检索文本、不含凭据的生成设置及后续修订。生成证据导出比学生讲义更详细，可包含检索段落、配置签名、修订历史与提供商调用用量。凭证不得出现在讲义、证据包或截图中。每日调用限制约束所有尝试，包括失败尝试。本地演示不实现认证角色、安全考试或课堂访问控制。

## 1. 假设你负责审核一份利用课程本地应用生成的测验草稿。该草稿的引用标识全部通过了自动验证，系统因此将其标记为“已准备好用于教学演示”。作为审核者，你需要判断：(1) 自动验证通过能否等同于人工批准？请引用依据；(2) 若后续发现其中一个引用标识指向了确实存在但与该题结论不相关的文档，这属于哪类问题？自动验证为何不能发现？(3) 请给出两条具体且可操作的整改措施，并说明每条措施如何匹配参考资料中的要求。

目标难度：困难



参考答案：参考答案：(1) 不能等同。根据片段 c7b355510d134e91833f092eec3c72ed 和 3aefdf9d56844b0087c9ad5a103275cb，自动草稿不得仅仅因为引用标识通过验证就被描述为人工批准。(2) 这属于结构验证与人工审核之间的缺口。自动验证只能确认引用标识存在，但不能判断引用是否在语义上支持题目结论，因此不能替代人工对相关性的审查。(3) 可行措施包括：① 由人工审核者填写观察和评分字段，自动化测试保持空白（依据 3aefdf9d56844b0087c9ad5a103275cb）；② 记录初始草稿、实际检索文本、不含凭据的生成设置及后续修订（依据 5caef4b8eff94d05a4294501bf115e26）。每条措施都需对引用的片段负责。评分时应检查学生是否区分自动验证与人工批准，是否指出引用相关性问题，以及整改措施是否可操作且引用具体片段。

解析：本题要求学生在审核情境中综合自动验证、人工审核和引用相关性的概念。学生需要理解自动验证只能检查引用标识存在性，而人工评价和证据相关性需另外判断。评分重点在于能否分步论证并给出有依据的整改措施。

## 2. 某课程团队决定更换嵌入模型：旧模型生成 768 维向量，新模型同样生成 768 维向量。同时，一门已审核课程的教学文本被修改。该课程使用本地检索应用。假设存储系统中保留了旧模型的文档向量和旧版审核记录。请分析：(1) 仅维度相同是否足以保证旧文档向量与新查询向量兼容？为什么？(2) 更换嵌入模型后，哪些存储对象需要重建或重新索引？(3) 教学文本修改后，除了向量问题，审核版本相关的哪些对象需要处理？请给出一个考虑上述约束的更新方案，并论证每一步的必要性。

目标难度：困难



参考答案：参考答案：(1) 维度相同不足以保证兼容。片段 c7b355510d134e91833f092eec3c72ed 指出，向量必须具有相同维度才能比较坐标，但维度相同不代表语义空间相同；不同模型可能使用不同语义空间，因此旧文档向量与新查询向量不能假定兼容。(2) 需要重建或重新索引所有使用旧模型生成的文档向量，使其与新查询向量在同一语义空间中；索引版本也必须同步更新，否则检索会使用不兼容的向量。(3) 教学文本修改后，已审核状态应重新审查；相关的审核记录、导出材料中的版本标记（如“当前文本是草稿还是已批准”）需要更新。更新方案示例：先建立新嵌入模型配置并生成新向量，重建索引，再更新审核记录和导出版本标记；每一步的必要性分别来自嵌入兼容性、索引版本和审核状态要求。评分要点应覆盖三步骤及其依据。

解析：本题围绕嵌入兼容性与版本更新设计情境，学生需要分析维度相同不等于兼容的原因，并设计一个覆盖向量重建、索引更新和审核记录更新的方案。评分重点在于是否理解语义空间差异，以及方案是否完整处理文本修订后的审核痕迹。

## 3. 某本地开发应用准备向教师展示一门课程的生成证据导出包。该导出包将包含检索段落、配置签名、修订历史和提供商调用用量。课程负责人还计划将同一份导出包用于学生 handout，并可能在未来支持多用户访问。假设你被要求审查该计划，请完成以下任务：(1) 指出将生成证据导出包直接用作学生 handout 的至少两处风险，并说明依据；(2) 针对“是否支持多用户角色与课堂访问控制”给出一个评价性结论，并引用资料说明当前应用能做什么、不能做什么；(3) 给出一个既能满足师生不同需求、又能维持当前隐私与审核要求的导出方案，并论证每一步如何匹配资料中的约束。

目标难度：困难



参考答案：参考答案：(1) 风险一：生成证据导出包比 student handout 更详细，可能包含检索段落、配置签名、修订历史等不宜向学生公开的内容（依据 5caef4b8eff94d05a4294501bf115e26）。风险二：凭据不得出现在讲义、证据包或截图中；若导出包未清理配置信息，可能泄露凭据（依据 5caef4b8eff94d05a4294501bf115e26）。(2) 评价性结论：当前本地演示尚未实现经过身份验证的角色、安全考试或课堂访问控制，因此不能将本地应用直接扩展为多用户教学平台（依据 5caef4b8eff94d05a4294501bf115e26 和 e9cd2063c2024317800235d50fd44e44）。(3) 方案：分别提供学生讲义版和生成证据版。“学生讲义版”仅保留教学文本和必要的出处元数据，去除凭据、详细检索段落和配置签名；“生成证据版”保留检索段落、配置签名、修订历史和调用用量供教师审核，但须确认其中不含凭据。每一步均需引用片段说明依据。评分时检查学生是否区分两类导出的目的、识别凭据与访问控制约束，并给出可操作的方案。

解析：本题要求学生在导出包使用和多用户访问两个情境约束下，评价现有应用的能力边界，并设计分类导出方案。学生需要引用片段说明生成证据导出与学生 handout 的差别，以及本地演示对认证和访问控制的限制。评分重点在于能否处理好隐私、审核和功能需求之间的平衡。
