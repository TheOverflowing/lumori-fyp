# 详细进度与阶段计时

日期：2026-09-20。本记录接续同目录的初版进度页记录，保留前一版本的设计与验证结果。

## 布局与选择

“设置 → 进度显示”增加“简洁 / 详细”原生单选控件。新默认值为详细，已有融合偏好正常保留；偏好按账号保存于当前浏览器。只改变显示，不进入生成请求，不增加模型调用。当前进度页可直接切换；刷新保留选择。跨账号不会沿用另一账号的选择。

详细版采用阶段导航与过程详情的双栏工作区：

- 顶部显示当前任务状态和累计处理时间。
- 左侧列出实际阶段、状态和耗时；点击阶段可以回看。
- 右侧按阶段显示检索资料、规划、编写检查、保存、语音、图片等不同的矢量场景，以及真实处理记录。
- 默认跟随当前步骤；用户主动选择历史阶段后保持选择，可点击“跟随当前步骤”恢复跟随。
- 手机使用横向阶段导航，只在首次进入和跟随切换步骤时滚动导航使当前步骤可见，不滚动整个页面。
- 完成后保留“查看结果”；动画停止，时间冻结。

场景使用局部透明度、位移和缩放反馈，属于装饰动画，不表示已经生成了图中文字、音频或图片。没有百分比、预计剩余时间或虚构的思考文本。减少动画、减少透明度、高对比模式有对应样式。

轮询更新尽量保留现有元素：时间变化不重建阶段按钮或动画；其他阶段的新事件不重绘用户正在阅读的历史阶段记录。阶段导航和滚动记录区支持键盘操作。

## 记录的含义

过程记录是程序实际观察到的工作与决策摘要，而不是模型内部思维链：选取资料片段数量、融合应用或按确定原因回退到原查询、规划题数、题目开始、检查通过/未通过、实际开始下一轮修正，以及保存、中断、恢复。

记录采用固定事件代码和允许的整数/枚举参数。示例：

```json
{"code":"retrieval_selected","data":{"selected":6}}
{"code":"fusion_fallback","data":{"reason":"ambiguous_input"}}
{"code":"question_rejected","data":{"number":2,"attempt":1}}
{"code":"question_repair","data":{"number":2,"attempt":2}}
```

这些仅为格式示例。后端不会把模型推理、提示词、课程正文或任意原因字符串写入该展示接口。`question_rejected` 与 `question_repair` 分开：最后一次检查未通过后可能直接停止，不能称为仍在修正。记录保留最近 120 条，超出时明确提示；原有审核证据不受此展示上限影响。

## 计时契约

继续使用兼容的 `job-progress-v1`，不删除原有字段。每个阶段增加：

| 字段 | 含义 |
| --- | --- |
| `started_at` | 首次观察到开始的时间；旧记录可为空。 |
| `finished_at` | 实际观察到停止的时间；崩溃造成未知时为空。 |
| `elapsed_ms` | 已记录的活跃执行区间累计毫秒；未知为空。 |
| `timing_complete` | 是否完整记录了该阶段执行时长。 |

顶层 `elapsed_ms` 累计已知阶段时长，另有 `timing_complete`、`events`、`events_truncated`。时间由服务端的单调时钟和进程标识计算，防止系统时钟调整或重启后的时钟原点变化误算；内部时钟数据和进程标识不返回浏览器。

同阶段多次执行或显式续做累计真实工作区间，等待恢复、排队和离线不计入。完成和失败后停止增长。崩溃只能保留已持久化区间，未知尾段明确标记为不完整，页面用 `≥` 表示已记录下限；旧任务用 `—`，不反推或补造历史时间。

累计处理时间不等于端到端墙钟时延，也不等于模型 API 时延；它包括实际阶段内部的本地处理与等待提供方响应。显示到秒，存储到毫秒；不能把快速阶段显示为 `0:00` 理解为绝对零耗时。阶段计时本身没有额外模型请求。

## 验证边界

前端 **116 passed**，其中 **25 项进度测试**；覆盖详细模式阶段选择、计时更新不重建按钮、其他阶段事件不重建历史记录、导航自动定位、终态、记录白名单与翻译。设置测试另覆盖账号隔离、旧偏好迁移、刷新保存和显示选项不进入生成请求。

后端相关回归 **244 passed**；随后增加一项时钟异常用例，最终进度专项 **41 passed**。两组有重叠，不应相加。测试覆盖实时累计、终态冻结、重复更新、同阶段再次执行、暂停后恢复、崩溃丢失尾段、旧记录、安全字段投影、事件上限和最终拒绝语义。进度写入、读取或时钟异常只降低展示完整性，不改变业务生成结果。

本轮没有使用真实模型，也没有增加模型调用种类。真实提供方性能、模型质量与真实读屏器兼容性不属于本轮验证结论。语音/图片沿用现有任务执行逻辑；视频只有可扩展展示场景，生成服务仍待后续实现。
