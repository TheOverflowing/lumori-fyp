日期：2026-09-20。范围：生成任务的状态展示、完成入口和媒体扩展；不改变生成模型或检索算法。

## 页面位置与交互

生成任务被后端接受后，进入 `#progress/{jobId}`。追问后的提交和直接生成走同一入口。页面归属现有“任务记录”，不增加主导航项；运行中或失败任务可从任务记录重新查看，成功任务保留直接打开内容的入口。

页面使用居中的状态图标、轻量环形活动动画和纵向步骤。动画只表达处理仍在进行，不模拟百分比或剩余时间。任务完成后动画停止，展示“查看结果”，由用户主动进入内容核查。失败原因默认折叠，只有可恢复任务才出现“继续生成”。

阶段与实际工作流一致：

| 工作流 | 阶段 |
| --- | --- |
| 学习讲解、普通逐题生成 | 检索资料 → 生成与检查 → 保存结果 |
| 带主规划器的逐题生成 | 检索资料 → 规划内容 → 生成与检查 → 保存结果 |
| 已审核文字的语音任务 | 生成语音 → 保存结果 |
| 已审核文字的配图任务 | 生成图片 → 保存结果 |

编写、答案核对、复核及修正均属于“生成与检查”；标题显示当前活动。逐题计数仅统计通过既有检查的题目，全部题目通过也不提前展示结果按钮，必须等待任务成功保存。模型检查仍不能代替教师审核。

## 状态与扩展接口

`GET /api/jobs/{id}` 在既有权限检查之后返回附加的 `timeline`，既有任务状态、`result`、逐题恢复 `progress` 和审核证据保持原有含义。

```json
{
  "version": "job-progress-v1",
  "recorded": true,
  "stages": [
    {"id": "retrieval", "kind": "retrieval", "status": "completed"},
    {"id": "writing", "kind": "writing", "status": "active"},
    {"id": "saving", "kind": "saving", "status": "pending"}
  ],
  "active_stage": "writing",
  "activity": "reviewing",
  "completed": 1,
  "total": 3,
  "unit": "questions",
  "updated_at": "2026-09-20T03:00:00+00:00"
}
```

以上是接口示例，不是一次实测任务。展示状态独立保存在新增的 `job_timelines` 表；刷新页面只读取已有任务。旧任务没有记录时返回 `recorded: false`，不补造历史阶段。服务重启会按已有中断处理记录失败；显式续做保留通过检查的题目。业务终态优先于陈旧的活动状态，展示写入失败不会反转已经保存成功的业务结果。对存储记录进行校验并只返回允许的展示字段。

前端可见期间每 2 秒读取状态；离开页面后停止、丢弃迟到响应，终态停止轮询。断连保留最后收到的状态、暂停活动动画并提供刷新入口，连接恢复后继续显示。不是 token 流式输出，也不据此推算预计完成时间。

多模态使用同一阶段协议。当前音频、图片任务已接入；前端有视频图标、文案与通用未知类型回退。未来加入视频时，后端需要注册实际阶段、活动标识及生成逻辑；此改动本身没有实现视频生成。未执行的媒体步骤不占位。
