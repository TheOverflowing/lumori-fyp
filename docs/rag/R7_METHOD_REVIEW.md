# R7 分级口语查询实验：独立方法审查

日期：2026-09-20。性质：执行前的方法审查，尚非实验结果或最终冻结协议。审查依据为 R6 协议、结果和当前拟议的 R7 设计；未调用项目模型 API，未修改生产代码。下列已采纳决定由主执行者确认，最终以联网前保存的协议为准。

已采纳：L4 单列歧义轴；L0–L3 以首阶段 Hit@5、MRR@20 为主算法指标，在 dev 选择一个全局策略；逐档最佳只描述、不用人工档位路由；每条 L0–L3 输入采用四臂候选并集的共享重排，各臂取自己的至多 20 候选；对 429/502/503/504 最多统一重试一次，并保存首次状态与恢复状态；120 条输入均比较两种改写器，96 条可恢复输入做共享重排。L4 不以原作者的隐藏单一意图指标选择策略。

## 1. 建议保留四个策略，但拆成两个研究问题

拟定的 original、conservative、normalize、dual 足以支持本轮，不建议再添加大量提示词或模型。original 为原文；conservative 沿用 R6 保守同语言简化；normalize 允许将描述映射为标准计算机术语，但禁止凭空补充实体、条件或答案；dual 合并原文与 normalize，去重后总候选上限仍为 20。

应分别回答：

1. **用户意图可恢复时，口语表达怎样影响排序，哪种查询策略更稳健？** 对应 L0–L3。
2. **输入本身不足以唯一确定意图时，模型是否能识别需要澄清？** 对应 L4，并以 L0–L3 为负例测误报。

L4 不只是“更强的口语”。信息缺失或多义性属于第二个因素：极口语但描述充分的句子可以明确，十分书面的句子也可以含糊。因此图表可以保留 L0–L4 的便于阅读顺序，但不能把 L4 原作者意图命中下降全解释为语言风格影响。

AmbigQA 将一个含糊问题的多种合理解释及各自澄清问句分别建模，说明单一隐含答案可能不足以评价有歧义输入。这里借鉴的是评价问题的划分，并非复现该研究数据或训练流程。[Min et al., EMNLP 2020](https://aclanthology.org/2020.emnlp-main.466/)

## 2. 有限、可实现的数据方案

12 个新课程问题族 × 2 种语言 × 5 档 = 120 条输入。L0–L3 的 96 条进入检索比较；L4 的 24 条主要进入歧义识别诊断。中英两种语言、同一问题族和不同程度变体不是独立样本。

| 档位 | 构造标准 | 必须保留的东西 |
|---|---|---|
| L0 | 清晰的教材术语和完整问法 | 原问题的所有必要条件 |
| L1 | 语气词、任务包装、句式口语化 | 术语和语义限定不变 |
| L2 | 主要术语替换为日常描述 | 足够辨认目标概念的性质或条件 |
| L3 | 多处替换、隐喻、迂回说法，但仍可从输入恢复意图 | 至少一组足以排除主要相邻概念的限定 |
| L4 | 至少两个合理、实质不同的解释，或缺少不可推断的必要参数 | 不再假定原问题是唯一真实意图 |

构造时应保存被替换术语、替换片段、保留条件和预定歧义类型。不能只以字数、术语数量或作者主观评价把样本分级。L2/L3 应主要改变表达，而不是同时增加更多检索子目标。每个 L4 至少存两种可行解释，以及一句能够区分这些解释的澄清问题；其中一种解释可以是原问题，但不能作为默认正确解释。

在调用前由另一位审阅者只看具体输入，检查 L0–L3 是否仍支持唯一目标、L4 是否确有多个解释。该审阅者不看作者标注的标准术语、原问题、答案段落或检索结果，以减少被原意图锚定。AI 编写和 AI 复核均明确署名，不能称为人工金标、真实用户行为或客观口语强度测量。审阅发现的缺陷可以在冻结前修订；冻结后只能标记并做敏感性分析。

同义语料或中英翻译可能使小库过易。语料应包含自然存在的相邻概念，如死锁/饥饿、栈/堆、进程/线程、哈希碰撞/散列聚集等，不能根据某策略已经出错才专门新增干扰段。所有语料和相关性标签先冻结。

## 3. 防止划分和策略选择泄漏

以来源连通分量为单位划分：同一问题族的全部语言及 L0–L4 属于同一分量；引用相同来源文档、重复文本、相互译本或共享已知证据的问题族连起来。正文和 PDF 的同一资料别名应归并，不能通过不同 URL 制造表面独立。L4 如实际标注了多个来源解释，应在分量构建中一并考虑其关联。

先报告最终独立来源分量数，再决定是否适合 dev/test。12 个 family 不一定是 12 个独立来源。若仅来自 2–3 本相互关联的教材，随机拆成 4 个 dev family 和 8 个 test family 不能宣称来源独立留出；这种情形应报告为探索性先导实验，固定策略作全量比较，或另找更多独立来源。即便有足够分量，本轮样本仍不适合训练复杂路由器。

推荐至少有 6 个来源分量时，按预先保存的哈希排序，约三分之一分量为 dev，其余为 test；保存精确分组和分母。在 dev 上只选择一个**全局策略**，锁定后再计算 test 指标。L0–L3 等权、两种语言等权、family 等权，防止一个题族因复制更多变体占更大权重。若结构完全平衡，简单均值与此一致；缺失调用不能被删除来维持平衡。

每档最高读数可以展示，但属于诊断。拿人工已知的 L0/L1/L2/L3 标签直接选择每档最优策略，是利用运行时不可用信息的 oracle 上界，不能称为产品条件路由的效果。实际路由器只能读取运行时可用的原始输入和已明确给出的课程上下文；需要单独冻结、评估分级错误和调用成本。它不属于本轮必要范围。

## 4. 先评首阶段排序，再评最终上下文

R6 的候选 Hit@20 达到上限，因此 R7 首阶段应同时保存完整的候选排序，优先报告以下指标：

- 首阶段 Hit@1、Hit@5、Hit@20、MRR@20。MRR 基于第一条完整已知证据的位置；若证据必须跨片段联合覆盖，应另报覆盖而不悄悄改变 MRR 定义。
- 最终 Top5 命中、MRR@5、1024-token 预算内证据命中、实际上下文 token。
- 同一 family/language 下，相对其 L0 的指标下降量，以及每档相对 original 的增损。
- 非穷尽证据标签继续称已知证据 Hit，而非严格 Recall；一条片段碰巧包含某关键词不能视为证据完整命中。

首阶段指标不依赖远端重排，可直接回答改写是否把证据提前。最终预算命中仍是产品目标。本轮为直接研究查询策略并避开重排服务混淆，主执行者采纳首阶段 Hit@5、MRR@20 作为算法比较及 dev 选择指标，最终预算命中作为次指标；若最终命中仍饱和，不能隐藏该事实，只能说明这轮排序改善未转化为已测上下文收益。

为保持改写消融可解释，所有策略的重排查询继续使用同一条原始用户输入，固定 chunk、embedding、混合策略、候选 20、Top5、上下文 1024。这测量的是首阶段查询策略，不能称为已测量“全链路都使用改写文本”的效果。dual 不能把重排候选增到 40；原文与 normalize 候选交替去重的顺序也应事先固定。

## 5. 避免把 503 差异算成算法收益

最精简的受控方案是：对同一输入，合并四臂候选，针对同一原文查询做一次共享重排评分，然后各臂只取自己至多 20 个候选的分数排序。并集最多 80，实际常因重合更少。同一次共享请求失败时四臂最终结果同时按失败记录，因而不会出现 R6 那种只因某一臂恰好 503 而产生的净增益。四臂使用同一候选的评分也减少重复请求。

但必须标注：这是**共享候选评分的受控实验**，实际请求可能超过生产的 20 个文档，不是四条独立生产请求的端到端测试；不能把共享耗时除以四当作每条策略延迟。每臂的候选上限仍为 20，但服务端评分的并集预算另行披露。Qwen3 文献描述其 embedding/reranking 模型设计，并不证明当前第三方托管端点在不同 batch 大小下完全一致；不应未经核验就作出该保证。[Zhang et al., 2025](https://arxiv.org/abs/2506.05176)

本轮已选定共享评分。对 429/502/503/504 最多统一重试一次，首次响应与重试响应均保留，最终同时展示首次可用率、恢复后的可用率及重试耗费。实际调用次数预算必须包含重试次数，不能只对去重后的逻辑请求计数。若端点不能返回所有并集候选分数，应先停止并修订协议，不应看到结果后悄悄改成逐臂独立调用。共享请求失败不产生臂间不对称，仍需注意改写/编码失败可能造成先前候选分支的不同回退。

rewrite 的网络失败、结构/约束失败、主动需要澄清、embedding 失败、rerank 失败必须分开。需要澄清不等于网络失败。若用原文回退，记录实际走的分支；“模型请求成功”与“有效改写被采用”不是同一件事。

## 6. 歧义诊断的最小指标

L4 不参与基于单一原意图 Hit 的策略胜出判断。可以展示它在原意图标签下的检索结果作为敏感性诊断，但要写明其他合理解释未被这一分数奖励。

对 conservative 与 normalize 的 `needs_clarification`，在所有 120 条输入上报告：L4 识别率、L0–L3 误报率、precision/recall/F1、非歧义样本的自动处理覆盖率。失败输出单独计数并采用预先约定的保守动作；不能把失败都当成正确澄清。original 没有澄清模块，报告“未实现”，不要把它与一个带澄清模块的策略合并成一个莫名其妙的总分。

仅返回一个布尔值，只能证明“预测需要澄清”，不能证明澄清问题有效或用户能顺利继续。若实际生成澄清问题，应另审是否指出关键分歧、是否暗示某一答案、是否不必要地询问已有信息。真正完成澄清后的检索效果需要用户回复或预先独立标注的回复，本轮不自动编造回复再宣称人机体验改善。

## 7. 最小选择规则与论文结论边界

主执行者已采纳：dev 上按 L0–L3 的宏平均首阶段 Hit@5 选择；完全相同时比较首阶段 MRR@20；仍相同时建议按 original → conservative → normalize → dual 的低开销优先顺序决定，并在最终协议确认。最终重排和上下文指标不反向改变胜者。澄清能力单独选择和报告，不通过人为权重与检索 Hit 相加。为防止一个净小增益掩盖大量意图损伤，同时列新增/丢失命中和改写语义审阅，但不要在看到 test 后临时创造淘汰阈值。

test 报各档各语言及总体点估计，并按来源分量配对 bootstrap；分量内所有语言和档位一起抽取。独立分量很少时，区间仅探索，不能用 96 条相关变体获得虚假的大样本置信度。至少报告分量级净增损，便于发现结果是否全由一份教材贡献。多策略、多档展示没有多重比较校正时，不使用显著性语言。

本轮能够选择“这一冻结基准上的最佳候选”，无法单次证明“最强策略”或为生产默认开启提供普遍保证。若预算命中无提升但排序提升，可以准确记录排序进展；若某档有增益且另一档受损，可以确定下一轮路由研究方向，但不能使用 test 标签拼出一个已验证的路由器。

## 8. 调用、费用与保存要求

保存预调用的数据/提示/代码/模型/配置哈希、请求去重键、原文及改写、触发回退原因、候选 ID 与次序、重排结果、分层指标、dev 选择锁和 test 逐题变化。响应和日志不记录凭据。

120 条输入、两种改写器的理论改写上限是 240 次；若预先排除 L0 改写或缓存重复请求，必须在协议中提前约定，不能看结果后节省某臂调用。为严格比较 L0 是否被错误改写/过度澄清，建议保留其调用。文档与查询向量分别计数，按完整输入和模型签名复用，不能只凭模型名称复用。

费用报告区分实际发起调用数、去重命中数、成功数、失败数、已报告金额、缺金额条数和 token。未知金额不是零。设置调用总数、输出 token、并发和预算阈值；预算中止应作为未完成实验，不得静默缩小 test 分母。阶段耗时及共享评分耗时与生产端到端延迟分别标注。

该实验新增为 R7，不替换 R6 的负结果。R6 与 R7 的语料、口语强度、评价方案不同，不应把两个数值直接相减写为同一基线下的召回率提升。
