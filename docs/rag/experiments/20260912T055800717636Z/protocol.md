# R2：公开人类标签与真实材料的首次比较协议

日期：2026-09-12。所有候选、输入转换和参数在本轮外部数据首次排名前确定。本协议不改写 R1 的数据或记录；新运行保存本文件、数据与完整检索源码的 SHA。

## 数据来源与实验边界

1. **MLQA CS 中英子集**：官方 CC BY-SA 3.0 Wikipedia 段落，英文众包问答、专业译者翻译问题并标注中文答案。保留原文、答案位置和官方 dev/test；计算机主题白名单、每篇最多 3 个英文/中文配对问题 family，按原问题 ID 的 SHA 排序选择。已冻结 81 个片段、92 条查询（dev 12、test 80；46 个双语 family），数据 SHA `f086a455ca1f2638f789e7d7675af284438fbaed9cfbb854fb9b87c4a8bec21e`。
2. **T2Ranking CS 补充子集**：使用可追溯到原人类判断的 C-MTEB 二值 positive/negative 版本。原始四级分数不可恢复，不捏造等级。仅按计算机主题选择，保留每条查询的全部已发布正负片段，输出筛选记录及具体数据 SHA。该集是网页检索补充，不称课程讲义；本地 dev/test 不冒充官方 test。
3. **Hello 算法 / OpenDSA**：12 篇真实教学材料及 80 个可追溯片段另行保存。缺少既有人工检索 qrels，因此只进入人工标注准备包；在人工完成前不计算课程 Recall 或将模板标作 human_reviewed。

公开数据的派生任务彼此分开运行、分开报告，不混算不同分母。MLQA 中同一问题的两个已知答案段落作为正例，位于一个可替代证据组；T2Ranking 已知正例也视为可替代来源。因此这些派生组的 all_evidence@k 与 Hit@k 相同，不能解释成完整多跳证据。未列出的片段是未判定，不等于人工确认的不相关。报告的 Recall 是已知正例覆盖，不是穷尽的真实相关性召回。MLQA 在混合语料中检索，未强制只检索另一种语言，不能声称测得纯跨语言检索效果。

## 固定候选与优化假设

保留 R1 的 dense_v1、bm25_v1、hybrid_rrf_v1、hybrid_mmr_v1，新增 **hybrid_dense_lexical_v1**。旧四种方法的排序公式不变。优化假设来自 R1：等权 RRF 过分偏好双路重合的候选，可能挤走没有字面匹配的高相关语义来源。

新方法仍取 dense 与 BM25 各前 20 的并集，按 `cosine + 0.05 * BM25 / max_BM25` 排序；无词法匹配时回退 dense。词法最多增加 0.05 分，因此候选之间大于 0.05 的 cosine 优势不会被字面匹配颠倒。0.05 是在本轮首次排名前选择的有界小扰动，不是在本轮 test 上调出来的最优值；不声称这就是最优融合方式或置信度概率。

固定：每路候选 20、RRF 常数 60 等权、MMR 在融合前 20 中按权重 0.7 重排；BM25 k1=1.2、b=0.75。分词仍为 NFKC/casefold + 汉字 unigram/bigram + 英文代码术语，不移除 stopwords。并列按冻结输入顺序。输出前 10，再取 k=1/3/5/10 前缀；原始 score 字段继续表示 cosine，选择分数单独记录。不改切片、不改写／翻译查询、不做题目生成，不根据标签预筛正确主题。

## 运行、比较与失败记录

所有方法复用同一批 Qwen `qwen/qwen3-embedding-8b` 原始返回向量，输入格式 `raw_text_v1_no_query_instruction`。每批最多 16 文本，MLQA 预计 12 次嵌入、上限 14；T2 以冻结数据的预检查为准，首次运行上限 50 次。只调用嵌入，单批失败不自动重试；完整缓存之后离线重放新增调用为 0。

分别报告每个数据集 dev/test 的已知正例 Recall@5、MRR@5、nDCG@5，并提供各 k、逐题排名与差值。主要判断新方法相对 dense 是否有收益，同时观察相对失败的等权 RRF 是否恢复；不能只与较弱基线相比。新旧语料与标注不同，不能把 R1 与 R2 的原始百分比相减作为提升。

沿用 2,000 次、种子 20260912 的 query-level 配对 bootstrap，仅为探索性读数。MLQA 双语问题共享 family，T2 样本也小；这些区间不满足把每条查询视为独立总体样本的解释，不用于显著性或因果结论。逐 family 与逐查询的得失应一并检查。参数不根据 dev/test 的本轮结果修改；看过的测试数据后续只能作探索性开发数据，确认性评估另设保留集。

缺失排名仍保留为零分并单独计失败；排序失败状态 completed_with_failures，整体嵌入失败状态 failed。保留全部预声明策略、退步结果、调用记录、源码、数据、原始向量和分数。排序耗时只覆盖成功完成计时的查询，不包含嵌入网络耗时。生产默认保持 dense_v1，本轮不自动替换。
