## 可复查实现

[实现快照清单](implementation-final-v2/manifest.json)包含 52 个运行时及部分测试文件，总计 760050 字节。清单中的 SHA-256 与归档时实际源码核对一致。此快照不含凭据、用户课程、环境或模型权重，也不是完整部署包；完整测试需使用项目工作区。早期运行若代码散列不同，不得用最终快照追溯声称当时具有后续修复。

当前流程：预算内完整正文解析与切分 → 嵌入任务私有临时索引 → 按缺口混合召回 → 用剩余片段预算补同小节后邻块、前邻块 → AI 选择实际正文片段编号 → 控制器核验原文坐标 → 已有向量连同资料晋升到课程库 → 最终上下文检查与生成。

临时和正式向量沿用 SQLite 持久化、应用内混合排序；没有额外部署独立向量数据库。单份探索资料最多 100 片段，每个缺口原始召回 4 片段，候选输入合计最多 24 叶片、48 段、每段 900 字符、总 24000 字符；超预算明确停止，不静默把资料开头当全文。

## 后续 DNS 兼容修复

ZH06 找到了候选网址，但六个网址均以 `private_address` 拒绝读取。实际系统解析同时返回 `198.18.0.72` 及 `::ffff:0:c612:48` 等虚拟地址对。历史 IPv4-translated 地址形式见 [RFC 2765 §2.1](https://www.rfc-editor.org/info/rfc2765/)；这里引用其地址定义，不把该历史文献称为最新部署建议。

修复只让精确的 translated Fake-IP 形式触发现有固定 TLS DoH 重新解析，仍要求得到真实公网地址，保留 `_public_ip` 的原有拒绝规则。`system` 模式、私网混合结果、其他 mapped/NAT64/translated 地址仍拒绝；不会直接连接虚拟地址。

[真实网络探针](dns-translated-probe.json)确认公开原文下载成功：83885 字节，SHA-256 与此前 D2L 原文一致。本探针未调用模型，不算完整生成成功。

后续代码归档为 [implementation-dns-v2](implementation-dns-v2/manifest.json)：53 文件、803519 字节，原始邻块快照保持不变。策略额外冻结 `dns_policy=public_address_pinning_v2`。页面现在会单独提示“已找到参考网址，但当前网络无法读取正文”，不会把全部下载失败描述成没有检索到资料。
