# R8B 协议 v2：接口格式修正

日期：2026-09-20。实验设计、数据、角色信息权限、评分、预算和失败分母沿用 [v1](R8B_PROTOCOL_V1.md)，并将该全文另存为每次运行的 `protocol-base-v1.md`。本补充与代码在新的有效运行前冻结。

第一次运行 `20260920T020110436365Z` 的128条文字请求全部HTTP400；另一次独立诊断请求确认原因：`response_format=json_object`要求提示中出现JSON字样。原四角色提示只要求确切对象字段，未出现JSON，属于客户端请求格式错误，尚无任何有效模型输出、嵌入或检索评分。

修正只在每个角色系统提示前加 `Respond with valid JSON.`，不改数据、决策规则、条件或示例。调用前机械检查所有提示含JSON。对400/401/402/403/404/422这类永久错误停止整批，不让同一格式或认证问题继续消耗完整队列；并发中已经发出的请求仍保留账本，不声称瞬时撤销。

原失败运行完整保留。重新冻结到新的时间戳目录，不清理旧账本，不把129次失败解释为模型改写/澄清失败率。缺少金额和token计量的400仍报告未知，不能宣称免费。新运行继续使用与v1相同的256逻辑文字/512文字尝试/24嵌入尝试上限，历史失败开销另列。

数据保持SHA256 `5dc1410823ae785435be8192986854030b80ede01042eebedaa00ec3aada9324`。数据审核所核对的v1研究设计不变；v2变更理由仅为已观察到的接口契约错误，没有读取成功模型结果或检索结果后调参。

格式依据：[DeepSeek 官方 JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode)，核验于2026-09-20；实际错误响应见失败运行的 `diagnostic-400.json`。论文与总报告应同时列出失败尝试和有效运行。
