# R8B：选择性追问实验的方法审查

日期：2026-09-20。本文是首次远程实验前的方法审查建议，不是结果报告。正式冻结协议及实现若与本文不同，应逐项说明；本文不声称已经完成任何新实验或产品接入。

## 1. 建议收窄的研究问题

研究问题是：在固定中英文课程语料及首阶段检索器下，根据用户实际提供的信息选择保留、改写或追问一次，是否有助于恢复用户指定目标的证据，同时避免对清楚的问题增加无必要交互？

本轮只评价首阶段检索和单次追问过程，不评价最终答案、不使用重排、不声称完成端到端教育任务。这样可以避免把澄清回复用于所有实验臂的共享重排而导致信息泄漏，也避免使用原始模糊问题重排所有臂而人为压低澄清收益。

原文、强制守约改写和选择性追问应固定为三种政策。不要在看完这个小测试集后挑选提示词、阈值或最优混合权重，再把同一组数据称为独立验证。

## 2. 数据结构与盲区

建议固定 8 个新信息需求，每个交叉构造 2 种语言、2 种表达风格、2 种信息充分性，共 64 条。表达风格与信息充分性是独立维度：专业措辞仍可有歧义，日常措辞也可以包含完整条件。

每个信息需求包含三份分离的对象：

1. **可见输入**：用户真正提交的 query 及语言；是否口语、是否有歧义等标签只供评估使用。
2. **用户情境档案**：用户想了解的对象、已经知道的机制、能够回答的约束，以及明确未知的信息。不包含答案、证据、文档名、相关性标签或标准查询。模拟用户可以读取；决策器、直接改写器及追问后改写器不能读取。
3. **评估对象**：目标证据 span、目标文档、合理的其他意图说明、风格和充分性标签。这些只进入本地评分及独立数据审核。

“新”只意味着本轮新构造的需求和问题。若仍使用已有教材或同一语料库，不能称作未见教材、真实学生流量或领域外泛化。两种语言和多个表达属于同一个需求的相关观测，独立需求数是 8，不是 64。

信息不足的输入至少应存在两个可解释的目标，并明确缺少哪项区别条件；仅因没有标准术语不能标成有歧义。完整输入必须已经包含区分目标所需的信息。输入作者和审核者均不得根据检索结果反向修改测试问题。

## 3. 三臂固定行为

| 政策 | 可见信息 | 行为 | 失败与未知处理 |
|---|---|---|---|
| original | 原始 query、语言 | 直接检索 | 保留失败及分母 |
| guarded_normalize | 原始 query、语言 | 尽量改善检索表达，禁止添加未给出的条件、答案、唯一意图；信息不足时保持原文 | 机械校验失败回原文；不追问 |
| selective | 原始 query、语言 | 选择 keep / rewrite / ask；最多一个问题 | ask 后仅将真实模拟回复与原 query 交给解析器；仍不足或失败则回原文，并保留 unresolved 标记 |

不能把真实的充分性标签作为路由器输入。模型判断 needs_clarification 与评估标签是两个独立对象，不能由标签直接触发追问。

guarded_normalize 的角色是“在相同输入信息下，尽量忠实的无交互改写”。即使发现不足，也只能保留已有信息，不能暗中调用用户档案。如果它为每条输入调用一次模型，成本仍按实际调用计，不能因为输出与原文一样就算没有调用。

选择性政策应同时记录初始 action、问题、模拟用户回复、解析器状态和最终检索文本；不要只保存最终文本。ask 后回原文仍是一次真实追问和未解决案例，不能改写成 keep。

## 4. 模拟用户的必要约束

模拟用户只能看原始 query、一次实际提出的问题和自己的情境档案。其职责是答这一个问题，不是主动把整份档案或标准查询交给检索系统。

建议使用结构化输出：简短的 answer、answerable、support_quotes。support_quotes 必须逐字来自档案，但这只证明引用存在，不能证明 answer 完全受支持，仍需内容审核。模型不能因问题中提供了错误选项就默认选最接近的一个；不在档案中、用户不知道或前提不成立时，应回答固定的本地化“我没有提供这项信息／我不清楚”。

具体约束：

- 回复仅给出被问到的区别条件，不自动补充未被询问的技术名称。
- 档案不能含待求结论。例如正在问运行代价时，档案不应直接告诉模拟用户复杂度；正在辨认数据结构时，档案不应把结构名直接作为隐藏答案。
- 问题可以提供容易理解的选项，但不得在选项中加入待求知识答案后让用户确认。应优先问机制、场景和限制条件。
- 无支持引用、JSON 失败或远程失败时，不可把档案直接拼到回复里作为恢复策略。
- 用户的未知回复可以直接结束为 unresolved 并回原文，避免无意义的后续调用；若交给解析器，也不能把未知当作任意一个选项的确认。
- 一次追问后仍不足就结束本轮交互，保留 unresolved。不要无限重问或另造一个更有利的回复。

本轮模拟用户与政策可能来自同一模型家族。这会引入语言风格一致、服从格式及问答配合偏好，不能声称已经测得真人可回答率或真人满意度。

## 5. 评分：分清信息充分性与隐含目标

### 5.1 信息完整组：正常检索质量

按首阶段 Hit@5、Hit@1、MRR@20、Hit@20 评分；对三臂使用相同语料、总候选上限、证据 span 与分词方式。MRR 应明确是首个完整覆盖已知证据 span 的候选排名倒数，不当作语义质量评分。

信息完整时发生 ask 属于额外交互，不应从检索分母移除。可以分别报告回复后最终候选的质量和无必要追问率；不能只报告成功澄清后的子集。

### 5.2 信息不足组：指定目标条件下的检索效用

可以给所有政策计算作者指定用户情境下的目标证据命中与 MRR，因为这是同一个隐含用户状态下的效用对比。但必须命名为 **目标条件下检索效用（target-conditioned retrieval utility）**。

原文输入可能合理指向其他目标，因此未找到作者预设目标不能直接解释成模型犯了事实错误，恰好找对也不能解释成模型已理解用户。这个指标衡量“在这组预设用户状态下，策略拿到了多少目标证据”，不衡量模糊输入只有一个标准正确理解。

不要把完整组与不足组直接合为一个无说明的“准确率”。如提供总体描述值，必须同时给出 32/32 的人工平衡比例，不能当作真实产品流量的期望收益。

### 5.3 交互与失败指标

至少按语言和充分性报告：

- 追问次数及比例；不足组追问率和完整组无必要追问率。
- 问题可回答、回复有支持、回复提供区分条件、最终 resolved 的数量和比例。
- unknown、unsupported、格式失败、API 失败、fallback 数量；所有案例保留原始分母。
- 追问后改善／相同／受损的逐题数量，并同时报告未追问案例。只分析已追问子集可以作为诊断，不能替代整体政策比较。
- 明确区分“检索命中”与“澄清成功”：unknown 后偶然命中目标不能计为解决了歧义。

## 6. 统计与选择边界

在任何远程调用前固定主次指标、三种政策、提示词、输入及证据哈希。建议主要报告两个分层终点：完整组的 MRR@20 是否退化，以及不足组目标条件下 MRR@20 是否改善；Hit@5 仍完整报告，注意延续 R7 的天花板问题。

本轮没有新策略选择所需的独立开发集时，应定位为冻结政策的探索性比较，不宣布已经选出普遍最佳政策。差值可以按 8 个信息需求配对 bootstrap，语言／风格／充分性一并成组抽样；如果需求共享支持文档，还需优先按共享文档连接分量分组。报告实际独立分量数，明确小样本与多指标、未做多重校正的局限。

可以报告交互负担与效用的二维结果，不建议事后随意选一个“每次追问扣 0.1 分”的综合分数。在真实用户容忍度未知时，这个扣分系数没有经验依据。

## 7. 公平检索与成本

每臂使用同一冻结检索器和同样的最终 20 个候选上限。clarified query 中的新信息只能用于 selective 臂，不能泄露给其他臂或共享打分查询。若重用向量，必须按完整实际输入、模型签名、维度和文件哈希核验。

当前建议不使用重排，所以本轮没有 rerank 费用或端到端答案质量。在后续做完整流程时，应让每臂用它自己合法获得的 query 及上下文重排；增加的计算成本必须独立记录。

64 条输入的逻辑文字调用上限为：64 次 guarded_normalize + 64 次路由 + 最多 64 次模拟用户 + 最多 64 次回复后解析 = 256 次。一次允许的 HTTP 重试意味着文字 attempts 上限为 512；实际统计不得混淆逻辑调用、尝试次数和成功次数。若批量嵌入去重，批量时间也不能冒充单用户在线延迟。

复用 R7 的明确重试规则、缺失金额处理、原始响应保留和本地预算门禁；记录每步顺序延迟和实际 token，而不是仅给最终检索时间。模拟用户成本单列：它是实验成本，真实产品交互中由真人回答，并非自动发生同等模型调用。

## 8. 上线前仍缺少的证据与最小控制

本实验可判断是否值得继续研究，不能单独证明应该默认上线追问。最小离线控制应覆盖：

1. 路由器和解析器的请求体中没有 profile、gold、canonical、label、文档路径或隐藏意图。
2. 模拟用户回答未知字段时返回 unknown；不给支持引用时不得通过。
3. 模拟用户的错误选项、问题前提不成立、空回复、超时不能变成已解决。
4. 解析器在未知回复下不能使用隐藏条件，且 unresolved 回原文。
5. 单轮追问限制、候选上限、所有失败留在分母、重试 attempt 上限。
6. 离线重放禁用网络，保留冻结文件并逐题复算政策输出到检索指标。

这些控制是代码行为验证，不能冒充新的真人实验或新的未知回复测量。实际回复应另外做 query-only 语义审核：审核者看到输入、问题、回复与最终改写；检查忠实性时可以在独立阶段核对档案支持，但不查看检索排名后再改标签。人工未参与则明确写 AI 辅助审核。

## 9. 首轮结论允许怎样写

允许：“在 8 个 AI 构造需求、64 条人工平衡的中英文输入中，固定策略的一次模拟追问使目标条件下证据排序出现某种差异，并产生某种交互负担。”

不允许：“追问提高了真实学生学习效果”“识别了所有用户真实意图”“原文歧义题未命中就是理解错误”“已找到普遍最强策略”“通过 AI 评估即完成教师人工审核”。
