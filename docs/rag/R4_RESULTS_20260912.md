# R4：文献候选的真实比较与后端采用

日期：2026-09-12。实际运行：[完整实验目录与结果](r4-experiments/20260912T072619024568Z/report.md)。

**本轮采用：256-token 递归切分、无重叠、标题编码、查询任务指令、有界混合召回 Top20、Qwen3-Reranker-8B 重排、Top5 种子和 1024-token 原文预算，不做父级扩展。** 已接入本地后端并重建两份原有演示资料的索引。选择来自开发集，保留集只用于验证预定升级门槛，没有根据保留集重新挑选冠军。

本轮成果是排序改善和可复现的策略选择；**新保留集的答案跨度命中率没有提高**。不能写成“全部方法中最强”、真实课程召回率提高或教学效果改善。

## 核心结果

| 数据与指标 | 原方案 | 选定方案 | 差异 |
|---|---:|---:|---:|
| 开发集：1024-token 预算下完整答案跨度 Hit | 88.04% | 98.37% | +10.33 个百分点 |
| 开发集：MRR@5 | 0.8053 | 0.9570 | +0.1516 |
| 新保留集：1024-token 预算下完整答案跨度 Hit | 97.02% | 97.02% | 持平 |
| 新保留集：MRR@5 | 0.8868 | 0.9524 | +0.0656 |
| 新保留集：平均原文上下文 token | 493.4 | 553.4 | +60.0 |

Hit 表示装配后的原文是否完整包含至少一个已知人工答案跨度，不等同于检索到全部相关片段的 Recall。MRR@5 使用叶片段首次完整覆盖答案的位置；正确证据越靠前，数值越高。未知相关原文仍为未标注，不能据此计算完整证据召回或真实幻觉率。

保留集 mixed 与强制跨语言 cross 的 Hit 分别为 97.62%、96.43%，两组均与原方案持平；MRR 分别从 0.8948→0.9583、0.8788→0.9464。中文查询 MRR 从 0.8341→0.9286，英文从 0.9395→0.9762。每个子组 84 个场景记录。

按 42 个双语 family 配对 bootstrap，2,000 次、固定种子 20260912：Hit 差异的探索性 95% 区间为 [−4.17, +4.76] 个百分点；MRR 差异为 [+0.0048, +0.1317]。样本少且经过主题筛选，没有多重比较校正，不据此声称广泛统计优势。

## 为什么选择这个方案

开发集比较了 16 个配置：12 个切分／编码／融合／扩展配置、本地 Qwen3-Reranker-0.6B 的两种上下文策略、云端 Qwen3-Reranker-8B 的两种策略。冻结规则先比较预算 Hit，再比较 MRR，再优先免重排和较小上下文。

云端 8B 在开发集的主指标最高。父级扩展没有增加命中和 MRR，却消耗更多上下文，因此按规则选择 `api8b_none`。本地 0.6B 开发集 Hit 为 96.74%、MRR 为 0.9248，平均约 9.14 秒一次 Top20 重排；云端约 0.70 秒。二者提示与运行平台不同，不能将差异解释为纯参数量消融。

新保留集中 `token128` 的 Hit 为 98.21%，高于选定方案，但开发集仅为 86.96%；它没有被事后替换成冠军。单独加入查询指令的保留集 MRR 为 0.9484，也很接近选定方案，且没有重排调用。这些读数保留在完整报告中，值得在新的课程标签集上验证成本与质量的取舍。

短切分不是必然更好；标题、任务指令和重排的组合也不能被归因为某一个模块的独立贡献。真正的 Late Chunking、Jina v3.5、多向量检索未参加本轮比较，仍是未比较方向。参考来源见 [文献审阅](research/CHUNKING_RETRIEVAL_REVIEW_20260912.md)。

## 数据与事先记录的规则

- 开发集沿用此前已见的 46 个 MLQA 双语 family，共 92 条查询；旧 test 已看过，所以本轮全部作为 dev。
- 新保留集为另 42 个 family、84 条查询，family 和完整原文与 dev 不重合；文章标题可能重合。
- 每条查询各测 mixed 和强制 cross：开发集 184 个场景，保留集 168 个场景。双语和场景有关联，不能当成 352 个独立样本。
- 原文为 CS 相关 Wikipedia，包含软件历史与搜索网页等，人工答案跨度来自公开 MLQA。不是大学课程专属人工金标；12 篇真实课程材料只用于切分结构审计，没有伪造人工相关性分数。
- 统一预算为冻结 Qwen tokenizer 对双换行拼接原文的 1024 token，不包含提示词和引用元数据，不等同于 DeepSeek 计费 token。256 token 是片段正文上限，标题前缀额外长度单独记录。
- 原协议、两次事先补充和选择锁均保留：因本地重排耗时及确认新的 API 可用，保留集只运行开发集胜出的重排模型。补充发生在保留集排名前；本地 0.6B 未跑保留集，不将其填成 0 或当成失败。

对应文件：[原协议](R4_PROTOCOL_V1.md)、[补充 1](R4_PROTOCOL_AMENDMENT_1.md)、[补充 2](R4_PROTOCOL_AMENDMENT_2.md)、[选择锁](r4-experiments/20260912T072619024568Z/selection-lock.json)、[升级判断](r4-experiments/20260912T072619024568Z/decision.json)。

## 失败、开销与复现

保留集相对基线有 5 个场景新增命中、5 个丢失命中、158 个持平；MRR 有 24 个改善、5 个退步、139 个持平。丢失命中的 5 个场景中，4 个是重排接口失败，另 1 个是成功返回但未命中。“图表表示什么？”这类依赖上下文的短查询也说明该公开 QA 子集与真实课程学习目标存在差异。[逐题失败分析](r4-experiments/20260912T072619024568Z/test-failure-analysis.json)保留全部增损。

嵌入调用 42 次、53,140 输入 token，已报告 cost 合计 0.00053140。重排包含 352 次数据集请求及 1 次探测，已报告费用合计 0.29345620 USD；dev 有 3 次失败、test 有 4 次失败，均按空证据计 0 命中，没有自动重试。7 次失败没有费用字段，因此该合计不等于已核对完整账单。

云端重排 test 的 p50 为 598.4 ms，p95 为 1026.0 ms，平均 700.1 ms，包含失败请求，并发为 2。这是重排 HTTP 往返和推理耗时，不含前置查询嵌入与最终出题时间。原始响应保留服务实际返回的模型标识，不能把在线模型别名当作不可变权重版本。

使用冻结代码、嵌入向量与重排响应完成了零新增 API 的离线重放；14 个保留集配置共 2,352 条逐题记录，排名、上下文与质量指标全部一致，只排除本地重新测量的排名耗时。[复现校验](r4-experiments/20260912T072619024568Z/replay-verification.json)。复现不增加独立实验样本。

## 应用验证与下一轮

后端采用上述策略，原有两份自编演示资料从 21 个字符片段升级为 20 个 token 片段。先在数据库副本中索引与测试，随后原子替换索引；3 门课程、2 份资料记录、8 个历史任务、3 份内容及版本和引用快照均保留。准备过程另用 6 次真实 API 调用，全部成功，已报告费用合计 0.00095247，与研究实验成本分列。

中英文检索验证分别使用 805 和 387 个原文 token，引用坐标与原文逐字一致。服务重启后两份索引均为当前版本；文字模型继续为 `deepseek-flash`。升级配置下 [534 项自动化测试](r4-active-profile-tests.xml)通过；本轮没有重新调用文字模型生成教学材料，不能据此宣称新策略的出题质量已通过真人评审。[运行状态](r4-experiments/20260912T072619024568Z/activation-service-verification.json)、[原子迁移记录](r4-experiments/20260912T072619024568Z/activation-promoted.json)、[接入设计](R4_RUNTIME_DESIGN.md)。

应用标题来自上传文件名与可识别标题路径，MLQA 标题来自文章元数据，二者存在分布差异。后续优先完成中英文真实课程的人工必要事实组标注，并在新保留集上比较当前完整方案与便宜的查询指令方案；另行预先定义失败重试或降级策略及成本上限。不要继续调参后把本轮保留集作为未见测试集。
