# R3：可追溯的递归切分

本轮把切分从 `app/pipeline.py` 的固定窗口提取成 `app/chunking.py` 的纯函数。`legacy_char_v1` 保留原生产文本输出，`recursive_v1` 为新方案；两者均可显式配置并纳入实验。没有增加框架或模型依赖。

## 新的导入流程

```text
PDF 按页提取／UTF-8 文本解码
  → 识别显式标题、代码围栏和 Markdown 表格
  → 在各章节内按段落、中英文句末、换行、词边界逐级细分
  → 仍超过上限才按字符拆分
  → 在同章节内打包，按完整尾部单元保留有限重叠
  → 保存原文位置、标题路径、来源校验值和关键词
  → 仅将片段正文送给嵌入 API
```

递归按边界逐级细分、为无空格语言补充标点的思路可参见 [LangChain 官方说明](https://docs.langchain.com/oss/python/integrations/splitters/recursive_text_splitter)。本项目自行实现页码、原文坐标、结构保护和确定性标识，不声称与该库输出完全相同。

默认最大长度 **1200 个 Python Unicode 字符**，重叠预算 **最多 120 个字符**。两者都不是模型 token 数。重叠保留完整的末尾段落／句子／行，长度不合适时少重叠或不重叠，不为凑够 120 字符从句中开始。不同标题、不同 PDF 页之间不重叠。

不超过上限的标准 Markdown 代码围栏（最多三个前导空格）和表格完整保留；MkDocs 等格式的深层嵌套块不在当前保证范围内。超长代码／表格仍必须切分，优先按行退化，并显式记录 `protected_block_split=true`。所有片段长度严格受上限约束。普通段落先按空行拆，长段落再考虑中英文句末；没有更合适边界时最终回退字符切分。

## 元数据与引用

| 字段 | 含义 |
|---|---|
| `page`、`chunk_index` | 一基页码、零基文档片段序号 |
| `page_char_start` / `page_char_end` | 原文半开区间 `[start,end)`，递归模式下原页切片必须等于片段正文 |
| `coordinate_system` | 区分原始解析页坐标和旧版移除 NUL／strip 后的坐标 |
| `source_page_sha256` / `source_document_sha256` | 解析原页和上传文件原字节的校验值 |
| `heading_path` | 从显式标题取得的章节层级 |
| `keywords` | 最多 8 个来自原文／标题的关键词候选 |
| `language` | 字符规则判断的 zh / en / mixed / und，非语言模型分类 |
| `split_reason`、`protected_block_types`、`protected_block_split` | 边界来源和受保护块的退化记录 |
| `chunking_version`、`chunking_config`、`parser_version` | 可复现的切分参数及解析器版本 |

PDF 坐标对应提取的文字页，不是 PDF 页面上的像素坐标。Markdown／TXT 坐标对应 UTF-8-SIG 解码后的文本。旧切分模式单独保存归一化坐标及原页边界映射，含 NUL 的旧片段不能不加说明地当作连续原文切片。

纯切分结果的 ID 由源页、区间和切分参数决定；写入应用前再加 document_id 命名空间。相同文件上传到不同课程不会产生全局主键冲突。旧材料中的 sources 是保存时的完整快照，重新切分不会改写旧材料或伪造旧引用的新元数据。

元数据使用新增的 `chunk_metadata` 与 `document_chunking` 表保存，保留旧 chunks 六列结构。旧数据库自动增加侧表，原课程、草稿、版本、调用记录不变。`GET /api/documents/{id}/chunks` 返回可核对的元数据；生成证据也保存完整来源。给文字模型的来源只附加章节路径，不加入关键词分数、偏移诊断或向量。

## 关键词怎样参与检索

提取顺序为章节标题、反引号术语、加粗术语、正文中的英文高频词，去重且过滤常见英文停用词。中文优先采用原有标题／显式术语，不自动拼出一长串无意义字对。词条只是检索信号，不是人工标注、知识点金标准或事实正确性证明。

默认检索保持 `dense_v1`；元数据已保存并可用于章节引用。需要实验元数据词汇加分时配置：

```dotenv
RETRIEVAL_STRATEGY=hybrid_dense_lexical_v1
RETRIEVAL_METADATA_WEIGHT=0.25
```

正文 BM25 与标题／关键词 BM25 分别按当前语料最大分归一化，再以 `0.75 × 正文 + 0.25 × 元数据` 合成。标题和关键词之间重复的 token 仅计一次；总词汇加分仍不超过 cosine 的 **0.05**。当前语料没有元数据匹配时回退原正文加分。`metadata_weight=0` 保持 R2 的排名、配置和诊断不变；非零权重仅允许上述有界混合策略。参数不改变嵌入正文，因此单独切换元数据权重不需要重建向量。

## 重建与恢复

```dotenv
CHUNK_STRATEGY=recursive_v1
CHUNK_MAX_CHARS=1200
CHUNK_OVERLAP_CHARS=120
```

新上传资料立即使用当前切分配置。已有资料在调用“建立索引”时检查保存的切分配置；有变化就读取存档原文件、核对 SHA 后重新切分。全部嵌入批次完成并校验向量、配置一致性后，在一个事务中替换旧片段和向量。失败／中断会保留旧索引，同一文档的重复索引任务串行执行；配置和现有有效索引都没有变化时复用，不重复调用 API。

原文件缺失或校验不符时拒绝重新切分。重新导入完全相同的原文件可凭内容 SHA 恢复该文档的原文件，保留 document_id 和旧索引，不创建重复资料。嵌入配置在索引过程中发生变化时，拒绝把不同模型返回的向量标成同一个索引版本。

`index_current` 继续表示向量与当前嵌入配置匹配；新增 `chunking_current` 单独表示切分参数是否匹配。尚未重建的旧索引可以继续使用，证据中保留它自己的来源状态，不谎称新策略已应用。

## 本轮评测与边界

实验规则在 [R3 协议](CHUNKING_PROTOCOL_V1.md) 中预先固定：同模型、同原查询，分别比较旧 1200/120、新 1200/120、新 800/80；在同一新切分上另做有界混合与元数据权重的消融。通过原始人工答案跨度重映射证据，报告 Top 5 和相同的 6000 原文字符预算；不能把旧父段落正例标签复制给每个子片段。

以原文区间评价切分而不是依赖变化的 chunk ID，参考 [Chroma 的切分评测研究](https://www.trychroma.com/research/evaluating-chunking)。其报告使用 token 级指标和自动生成的评测数据；本项目使用原人工答案的字符坐标，指标与数据口径不同，不能直接横向比较论文数值。

目前还没有模型 tokenizer 的严格预算、语义向量切分、父子检索或 PDF 版面识别。标题仅识别明确的 Markdown ATX／Setext 形式，不猜测 PDF 的视觉标题。RST 指令、教材宏、数学公式、图片和扫描 OCR 不做语义展开；将原始 RST 直接交给该 Markdown 结构识别器时，波浪线标题可能误认成围栏，因此本轮教材统计中的保护块标签不能当作代码质量指标。过多短标题会产生小片段；这些问题及逐项结果见 [R3 报告](CHUNKING_RESULTS_20260912.md)。

已有 MLQA 查询在 R2 已使用，R3 只能报告探索性已知答案跨度覆盖，不能称为新的保留测试集，也不能等同于找齐解题理由或全部教学证据。12 篇真实教材继续只报告结构变化，教材专属真人标签仍待填写。
