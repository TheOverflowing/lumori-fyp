## 全部输入的逐 family 审核

以下每行均检查了该 family 的 8 条实际输入、两个 canonical 问句和两个 profile。S 表示 sufficient 的四条，U 表示 underspecified 的四条。U 的判断只表示“不足以唯一恢复该模拟用户的目标”，不等于必须向每一名真实用户追问。

| Family（各 8 条） | S 是否保留所需信息 | U 缺失条件与至少两种合理解释 | Profile 是否含被询问的答案 | 证据与边界 |
|---|---|---|---|---|
| `binary-boundary-update` | 是：升序、闭区间、中点比较结果均有 | 比较结果未给；小于与大于目标需要不同更新，相等也可直接结束 | 未含应更新哪一端或新下标 | 精确 span 给出所需比较分支和边界更新；可直接给三分支通用规则，因此 U 不是普遍不可回答 |
| `hash-quadratic-offset` | 策略已给，但初稿的口语“每次跳多远”与 formal 的 offset 不严格同义 | 探测策略未给，线性与平方探测均合理；还可能有其他开放寻址策略 | 仅指定用户已知的策略，未给偏移数列或公式；策略名字含 quadratic/平方不视为答案泄露 | 原教材明确列出平方数，但“相对原冲突位置的偏移”与“相对上一位置的增量”需要区分；冻结前统一措辞 |
| `avl-rotation-case` | 初稿不充分：`+2/-1` 未声明平衡因子符号约定；需补充后再通过 | 失衡节点和相关子节点的状态未给，至少 LL 与 LR 情况不同；通常一次追问可同时询问这两个数值 | 给出的因子值属于已知状态，不含旋转顺序；补充符号定义也不回答旋转问题 | 初稿精确命中单独表格行，但行内没有列标题；应纳入表头语境，避免将不自解释的残片当完整证据 |
| `quick-stack-limit` | 是：递归栈目标、严重不均衡划分、最差空间界。初稿口语版额外明确“不改基准数”，建议 formal 同步 | 优化目标未给，改基准数改善时间与控制递归栈均合理 | 无“递归较短一侧”、空间复杂度或解决步骤 | span 支持递归较短子数组与对数栈界；原文外部实现未展开，不能据此声称完整迭代实现已被文本证据验证 |
| `stack-push-capacity` | 是：动态数组栈、容量已满、单次操作，避免把均摊分析当单次成本 | 容量是否已满未给，扩容与有空余容量的单次操作不同 | 无复杂度，也没有扩容/复制步骤 | span 支持“触发扩容、该次 O(n)”；未展开拷贝细节。具体内存分配器或实时系统差异不在本教材层面的任务范围 |
| `graph-cover-components` | 是：整图覆盖目标、起点遍历已结束仍有遗漏。口语版未明说无向，但该证据适用于有向和无向图 | 只遍历起点可达部分与覆盖整张图是不同任务 | 无“另选未访问顶点”等下一步动作 | span 直接支持从另一未访问顶点继续；句子“遍历整图”的常见默认含义会使某些读者无需追问，因此必须保留条件意图解释 |

## 初审需修订项目

1. **划分规则不一致。** 初稿数据元信息按 `SHA256('r8b|' + '|'.join(sorted(document_ids)))` 排序，并有完整匹配的八个 hash；初稿协议却写 `SHA256('r8b-split:'+component)`。必须在调用前统一规则，并同步 family、query 和 component 的 split；不能运行后择优选划分。
2. **AVL 符号约定。** 左高减右高与相反约定均存在。初稿四条 S 和 profile 仅有 `+2/-1`；在另一约定下，指定左孩子甚至不是应检查的较高一侧。应补充约定或给出等价的左右高低状态。U 仍应保留未提供状态的真实信息缺口。
3. **平方探测偏移的参照点。** 平方数偏移与连续探测位置间的差不是一回事。应将四条口语输入与其余输入/profile 统一为相对初次冲突位置的偏移；否则可观测差异混入题意改变。
4. **证据表示元数据。** merge 的金标实际来自内嵌伪代码，必须如实声明，不应写成纯 prose 证据。
5. **非阻断的风格控制。** quick 的口语充分版独有“不改基准数”限制；宜同步到正式版。graph 的口语版省略无向条件，虽然不影响该证据适用性，也宜同步以减少表达风格之外的差异。

## 机械检查及语义边界

初审机械核验：64 个查询 ID 唯一；每个 family 的 8 个组合齐全；32 条 S、32 条 U；8 个 span 的 Unicode 半开区间均与 `document.text[start:end]` 精确一致，每个 span 在对应全文恰出现一次。初稿八个 split hash 均按其数据声明规则正确，但与协议规则不同，故仍须统一。精确子串匹配不等于完整相关性判断或生成答案正确性验证。

初审 16 份 profile 均未发现被询问的旋转顺序、公式、复杂度、代码动作或解释原因。`不知道…` 明确区分用户已知条件与正要学习的答案；模拟用户不能把“知道任务名称”升级为“知道该任务的定义或结论”。实际回复仍需检查是否只回答追问，不能用 profile 原文引用存在来代替语义蕴含审核。

U 查询均至少容许两种实质不同的用户目标/状态，但均可能由条件式答案覆盖；尤其 quick、graph、insertion、merge 的自然语言本就容许通用解释。因此 `requires_clarification` 应理解为实验中恢复单一隐藏目标所需的信息，而不是产品场景的绝对真值。R8B 协议已采用 target-conditioned evidence alignment、单列交互负担的口径，应在结果中延续。

这套设计能检查“正式但信息不够”与“口语但信息足够”，不能把口语化当作歧义的替代变量。每类只有 8 个信息需求；英文/中文翻译、同 family 的风格变体并非独立题目。全部教材来自两个已有项目来源，不代表跨课程、真实学生输入或新领域普适表现。
