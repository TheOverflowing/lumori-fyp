# R8B 查询与追问输出的 AI 语义审核

日期：2026-09-20。有效运行：`20260920T020637637502Z`。

## 审核范围与限制

本次输出审核只读取该运行的 `query-only-audit-inputs.json`，逐条核对 130 条输出：64 条 normalize、64 条 selective、2 条 resolver。未读取检索排名、指标、证据、隐藏用户档案或回复支持审核文件。resolver 按其实际可见的原问题、追问和模拟回复判断。

这是一轮 AI 辅助审核，不是教师人工金标。审核文件的记录 ID 仍显露 family、语言、风格和充分性命名，审核者此前还参与过协议和代码审查，因此不能称为完全盲法或外部独立人工评价。本轮判断不使用 ID 中的标签作为真实意图证据；尤其不能因为作者预设一个具体目标，就把其他合理解释判为错误。

完整逐条标签、说明、输入哈希与覆盖检查保存在 [query-semantic-audit.json](r8b-experiments/20260920T020637637502Z/query-semantic-audit.json)。覆盖 130/130 个唯一记录。审核后不删题、不改变检索分母、不修改已冻结策略或模型输出。

## 内容忠实性

| 角色 | 条数 | 未发现明确内容问题 | 其余情况 |
|---|---:|---:|---|
| normalize | 64 | 55 | 条件遗漏 3；添加不支持条件 1；待求目标改变 2；轻度范围警告 2；答案提示 1 |
| selective | 64 | 55 | 条件遗漏 2；添加不支持条件 1；待求目标改变 1；轻度范围警告 1；未经支持的解决方向收窄 1；答案提示 1；追问 2 |
| resolver | 2 | 1 | 另一条使用了实际回复，但延续了追问引起的目标转移 |

“未发现明确问题”是本次审核判断，并非证明严格语义等价。条件遗漏的影响也不同：删除明示的平衡因子符号定义属于中等风险；把“已经走完一个分量，现在问下一步”压缩成“遍历全图”保留了总体目标，但丢失进度，列为较低风险。两条追问单独审核，不把没有 query 的追问误计成改写失败。

最明确的例子：

- **任意顺序变成近乎有序。** `insertion-small-input-en-colloquial-underspecified:normalize` 将 “arrays can start in any order” 改成 “nearly sorted arrays”。这是直接添加甚至改变已给前提，不能归入恢复术语。
- **单次代价变成摊还代价。** `stack-push-capacity-en-colloquial-underspecified:normalize` 把 “very next push, just that one” 改成 “amortized cost”。它替换了用户要求的度量口径。
- **改写提前给方法。** 英文口语快排栈问题的 normalize 与中文对应问题的 selective，加入尾递归优化、先递归小分区等待求方法；两条合计为 2 个答案提示案例。其中中文输出理由声称保留“不换基准数”，但实际 query 没有这项约束。
- **擅自选择单旋转。** 英文口语 AVL 问题的 selective 添加 “single rotation”，原文没有提供足以排除双旋转的条件。
- **继续遍历变成可达性。** 英文口语图遍历问题的 selective 把“任务是否完成／是否继续”改问“其他分量是否可达”，改变了问题目标。

这些判断仅来自输入输出对比，不表示它们已经造成多少检索损失；需要后续将冻结标签与评分关联，但不能据评分反过来改审核标签。

## 是否应追问：不能只看有没有改写错误

64 条 selective 输出的 query-only 决策审核为：

| 判断 | 条数 | 含义 |
|---|---:|---|
| 对可见请求而言合理 | 32 | 在可见条件下，保留或改写的基本决策合理；不等于改写文字绝无缺陷 |
| 具体实例仍缺区别条件却未问 | 14 | 例如当前二分比较结果、这个 AVL 失衡实例、当前栈容量状态或遍历任务范围未给出 |
| 可先检索一般规则，追问可选 | 7 | 例如未指定方案的开放寻址、一般快排优化；直接检索综述不应必然判错 |
| 个性化判断需要更多情境 | 4 | 插入排序对“我的数组”是否适合需要规模等信息，也可以先提供条件化的一般比较 |
| 子过程范围仍不确定，但检索合理 | 4 | 归并排序空输入可能指外层入口，也可能指 merge 子过程；不能用隐藏目标否定其他解释 |
| 追问有用但不完整 | 1 | AVL 追问只明确问节点及左重／右重，没有明确索取子节点状态 |
| 追问选项偏离目标 | 1 | 图遍历追问把覆盖范围选择换成连通性判断 |
| 未获支持就选择解决方向 | 1 | 快排通用优化被收窄到 pivot selection |

其中 14 条“未问区别条件”保留原文的案例不能叫文本编造；它们仍可检索一般规则，只是尚未确定用户所问具体实例。另一方面，“可搜索”也不等于“条件完整”。现有理由经常混淆这两点。

这份 query-only 判断故意不等同于实验作者的二分类标签，因此不把“有歧义标签且没问”全都当成语义错误。产品若允许先给条件化解释，追问必要性的判准会与必须单独定位一个隐藏目标的模拟实验不同。

## 两次追问与两个 resolver

**AVL。** 追问失衡节点以及左重／右重的方向有价值，但单看问题没有完整索取区分单旋与双旋的信息。实际可见回复另外包含左孩子的平衡因子；resolver 使用了这些已实际提供的数值和方向，没有自行加入旋转答案，判为忠实于实际问答。回复是否主动提供了档案里不该透露的内容，应由独立回复支持审核判断，本审核不读档案。

**图遍历。** 原文已经说明图分成多块，询问“这算完成还是继续”。追问给出的第二个选项却是“判断整个图是否连通”，偏离更自然的“只覆盖起点可达范围，还是需要覆盖全图”。实际回复选择了连通性措辞，又说任务要求访问所有顶点。resolver 因而把最终查询写成通用连通性判断，遗漏原来的非连通状态和是否继续的任务。

这里不能称 resolver 独立猜出了隐藏意图：连通性确实出现在实际回复中。应记录为追问—回复—解析的目标转移风险，并与回复支持审核联合解释，不能将 `resolved=true` 当作人工确认已正确解决歧义。

## 对结论的影响

本审核支持继续保留忠实性防护及必要时澄清的研究方向，但没有提供默认上线的依据。高排序得分不能抵消答案提示或条件改变，低追问次数也不能证明没有歧义。报告应分别呈现首阶段检索效用、追问负担、条件遗漏和语义风险；这些审核标签仅用于解释，不用于重新选择最有利子集。
