# 生成前需求检查：产品接入与开发验证

日期：2026-09-20。当前提示版本：`query-clarification-v2-20260920`。本文记录本地产品行为与开发检查；不是新的 R8/R9 独立算法评测，也不改写历史实验结果。

后续同日界面精简及默认关闭的融合设置见[可选查询融合与精简设置](QUERY_FUSION_RUNTIME_20260920.md)。下文保留首次接入时的界面与功能状态；既有两轮模型检查数据不变。

## 实际功能

生成页面默认勾选“生成前检查是否需要补充信息”，用户可以关闭。启用后，先用当前文本模型判断能否按原学习目标继续；有必要时提出一次追问。问题充分或只是要求通用讲解、例题时可以直接生成，不要求用户先把自己想学习的答案写出来。

| 检查结果或用户操作 | 实际处理 |
|---|---|
| 可以继续 | 保持原学习目标，提交原有生成流程 |
| 需要补充 | 展示原学习目标、一个追问及零至三个可选回答；用户可自由填写，也可点击选项填入后修改 |
| 补充并生成 | 保存真实用户回答；确定性拼接原目标、实际问题、回答和曾提供的有序选项后用于执行。选项只帮助理解“第二个”等指代，不自动成为已选条件 |
| 不确定，按原输入继续 | 检索主题保持原文，并告知生成阶段没有新增信息；必要时给条件式说明或报告资料不足，不宣称已经完成澄清 |
| 检查暂不可用 | 显式让用户选择按原输入继续或取消，不把模型故障伪装成“意图清晰” |
| 关闭检查 | 直接提交原有生成流程，不增加本次需求检查调用 |
| 提交前取消或按 Escape | 退出补充对话，保留页面上的原表单；取消浏览器交互不保证已经发出的远端检查请求未计费 |

补充回答最多 2000 字符。修改生成条件后要重新检查；过期、已使用、请求不匹配等情况会提示重新开始。请求提交失败时保持原请求的重试信息，避免把同一次生成变成两个任务。内容标题仍使用原始学习目标，不把整段澄清对话放进标题。

## 信息与状态边界

检查模型只看到当前 `topic`、材料类型、学习者基础和语言；看不到课程正文、检索结果、隐藏意图、答案金标或另一个改写版本。当前接口兼容 `deepseek-flash`，运行时沿用服务端文本模型配置，不在这个模块内私自切换模型。

一次新的有效检查最多发起一次文本调用，无自动重试。调用进入账号的现有用量台账。服务端为这次检查设置 45 秒本地等待超时；这不是远端取消或费用上限的保证。准备结果自创建起有效 15 分钟，绑定账号和生成参数，最多关联一个生成任务。原请求的准确重试可以返回同一任务；无法拿一个账号或一组参数的检查结果去提交另一个账号或另一组生成参数。

已完成的检查结果和关联关系保存于数据库。尚未完成的检查遇到进程重启会标为中断，需重新检查。已经接受的生成任务继续执行时，会从其原始参数及保存的真实回答重建相同执行上下文；15 分钟期限约束新的提交，不撤销已经接受的任务。修改主题、课程、资料、语言、难度等实质条件不能沿用旧检查。

当前没有模拟用户，没有让模型再整理真实回答的 resolver，也没有自动把原文替换成术语改写。普通词法/向量混合检索保持原配置；R8A 研究中的原文与改写查询融合没有作为这个功能的一部分接入生产。检索排序能帮助选择已有候选，不能从缺失的信息中确定用户真正想要哪一种意思。

## 通用提示规则与口语理解

这项功能不需要穷举“排队买饭→队列”“叠盘子→栈”之类的口语词典。预训练模型已有语言和领域知识，提示词约束它保留条件、否定、比较和符号，区分“我不知道算法答案”与“系统不知道我问的是哪种情况”。代码负责检查返回结构、长度、原文锚点、账号与请求关系；这些通用规则不是逐个算法或逐个口语替换词的映射。

这种设计可以处理提示中没有列举过的表达，但没有在本项目中训练出一个新的泛化模型，也不保证理解生僻比喻、方言、混合语言或含糊指代。模型可能漏问、问错方向或一次索要过多细节。问题和选项始终是待用户确认的内容，不能因格式校验通过就当作事实。

Ma 等的 [Query Rewriting in Retrieval-Augmented Large Language Models，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.322/) 提出 Rewrite–Retrieve–Read，并研究以语言模型生成/学习检索查询来弥合自然输入与检索知识的差距。这提供了使用模型处理查询的概念依据，但其改写训练和 QA 实验不是本次单轮需求检查的实现，也不能证明当前方案最强或已经提升召回。

两轮使用相同的六条开发时挑选的输入，每轮调用六次。调用返回模型均为 `deepseek-flash`，12 次 HTTP 200；v1 为 4,829 tokens，v2 为 5,555 tokens，合计 10,384 tokens。接口未返回金额，实际费用未知，不能记为零。没有执行检索、生成学习材料或用户学习效果测量。各文件的代码 SHA 反映该次检查时的实现，不将随后请求兼容性或界面修复冒称为同一代码快照。

| 开发输入 | v1 实际行为 | v2 实际行为与仍存限制 |
|---|---|---|
| 中文排队类比，明确要求入队/出队讲解 | 直接继续 | 直接继续；这一例不要求用户先提供“队列”术语 |
| 英文盘子类比，明确顶端加入/后进先出 | 直接继续 | 直接继续；这一例不要求用户先提供“栈”术语 |
| 中文通用二分查找讲解与举例 | 直接继续 | 直接继续，允许作者设计教学例子 |
| 中文“当前这一步该留哪一半” | 追问查找变体并给一般主题菜单；没有取得当前比较状态，偏离实例问题 | 改为询问当前元素、目标与比较结果，并可补充边界/数值；更接近实例所需信息，但所列细节可能多于判断保留方向的最小需求 |
| 中文 AVL 节点“歪了先往哪边拧” | 只问失衡节点及哪侧更高；不足以区分同侧的单旋/双旋情况 | 询问结构、插入/删除位置、祖先失衡与子树高度，信息更完整；仍可能负担偏大，且不应把所有列举信息都视为必需 |
| 英文非连通图是否还要继续遍历 | 返回 ready，与预设 smoke 期待的追问不同 | 仍返回 ready；理由是可解释起点可达范围与整图覆盖的区别。条件式讲解可以合理，因此这不是自动成立的模型错误，也不证明已恢复某个隐藏用户意图 |

v2 基于 v1 开发观察修改通用提示：实例问题应询问当前状态，不应改成课程主题菜单；若单个性质不足以区分情形，在同一个追问中补充相关条件。两轮的 ready/追问分布都是 4/2，变化在问法而非这一组标签数量。原记录中的期待标签只是开发预期，不能据此报告独立准确率或把两轮算成 12 个独立信息需求。

这六条已见输入不能建立新的召回率、MRR、澄清成功率或跨领域结论，也不能与 R7/R8 的冻结测试集拼接成提高曲线。没有真实用户回复或下游检索，尤其不能宣称 v2 已解决 AVL 或二分查找问题。

## 工程验证与后续证据

最终验证记录为后端 262 项、前端 81 项测试通过，其中包含 50 项规划相关、27 项准备流程集成及 15 项新增前端测试。旧检查点缺少新增默认字段时可兼容恢复，实际配置改变仍会被拒绝，相关回归均通过。本地 8765 服务已启动，准备接口路由、静态资源及匿名访问返回 401 均已验证，没有额外模型调用。这些检查验证接口与状态处理，不测模型理解正确率，不作为上述 12 次真实文本调用的新增样本。

主任务用可控的 mock 服务完成浏览器交互检查：中文补充回答及选项修改后生成、英文“不确定”按原文生成，均在内容列表出现 mock 材料；模拟检查接口失败时显示英文 unavailable 对话，明确选择按原文继续后也创建 mock 材料；提交前按 Escape 后原始输入和语言保留。浅色补充窗口约 576 像素宽的布局已目视检查。这些是状态流与界面验证，与上述真实接口的 12 次检查分别计数；不是实际模型端到端教育质量或教师核验。

后续正式比较需要重新冻结独立输入，覆盖清晰口语、正式但缺条件、未知表达、错误选项、部分回答、冲突回答与 unknown；分别报告误追问、漏问、问题可回答性、交互负担、语义保留和最终检索效果。当前产品接入和开发检查与 [R8B 实验结果](R8B_RESULTS_20260920.md)分开保存，不修改其负结果或分母。
