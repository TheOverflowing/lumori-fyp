# RAG 检索试点：运行前冻结的比较协议

协议 ID：`cs-rag-pilot-v1-retrieval-protocol-v1`。记录日期：2026-09-12。本文件在首次读取本数据进行实测排名之前固定；这是项目内预登记，不是外部注册，也不是对实验结果的陈述。

## 研究边界与问题

现有基线使用单个学习目标文本作为查询，对当前课程片段按向量余弦相似度排序并取 Top 5。本轮只比较检索方法，不同时改变生成模型、难度控制、提示、切片、课程权限或后续生成流程。问题是：在固定自编中英计算机本科课程片段上，词法、混合排序及多样性重排相对 dense 基线怎样影响相关来源和必要证据覆盖，哪些查询改善，哪些查询退步？

不预设任何方法一定提升，不设置必须得到正向结果的成功门槛。应用默认继续使用 dense。即使试点均值较好，也不能据此默认启用新方法或宣称真实课程教学效果提升。

## 固定方法

| 方法 ID | 固定规则 |
| --- | --- |
| `dense_v1` | 同一组文档和查询向量；归一化后按 cosine 排序，返回前 10 个供不同 k 取前缀。 |
| `bm25_v1` | BM25，`k1=1.2`、`b=0.75`；只保留正分结果，返回前 10 个；作为 hybrid 的词法路时最多 20 个候选；零匹配为空。 |
| `hybrid_rrf_v1` | dense 与 BM25 各最多 20 个候选，取并集；按两路倒数排名之和排序，常数 60。 |
| `hybrid_mmr_v1` | 使用相同两路候选与 RRF 相关性，在融合排名前 20 个候选上迭代 MMR，`lambda=0.7`。 |

所有方法报告 `k=1,3,5,10`，从同一轮排名取相应前缀；不为每个 k 重新选参数。任何完全同分均按冻结文档输入顺序（`input_order`）打破，ID 不进入评分。hybrid 每路最多 20 个候选，融合并集最多 40 个；MMR 进一步仅使用融合前 20 个，不能用 qrels 补回遗漏片段。

词法分析器版本固定为 `nfkc-casefold-cjk-unigram-bigram-code-v1`：先 NFKC 与 casefold，中文汉字保留 unigram 与相邻 bigram；英文、数字和代码标识符保留并提取组成部分；不做 stemming，不移除 stopwords。将实际分析器实现与代码 SHA 保存到运行清单。中文分词和中英词法覆盖属于此方法的一部分，不能把由 tokenization 造成的差异全部归因为嵌入模型。

RRF 对文档 d 的得分为 `sum(1 / (60 + rank_r(d)))`，路内名次从 1 开始；没有进入某路候选的文档对该路贡献为 0。倒数排名融合通过名次结合多路信号，而不要求原始分数处于同一尺度；本轮采用的常数 60 在运行前固定，不依据本集合选择。[Cormack, Clarke and Büttcher, SIGIR 2009](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf)

MMR 使用 `relevance(d)=RRF(d)/max_candidate_RRF`，冗余项为 `max(0, max cosine(d,s))`，其中 s 为已选片段，尚未选择时冗余为 0。每一步选择 `0.7 * relevance - 0.3 * redundancy` 最大的未选片段。该方法在相关性与已有结果的重复程度之间取舍；相似片段可能包含不同必要条件，减少重复不保证增加证据覆盖。[Carbonell and Goldstein, SIGIR 1998](https://www.cs.cmu.edu/~jgc/publication/The_Use_MMR_Diversity_Based_LTMIR_1998.pdf)

两种 hybrid 在 BM25 没有正分候选时明确回退到 dense 排名，并记录回退原因；此时不把无词法贡献的输出描述为混合信号的收益。不添加根据本集合选择的拒答或余弦阈值。无词法匹配不等于资料没有答案；高向量相似度也不等于资料能够回答。

## 嵌入、缓存与调用预算

固定嵌入输入配置为 `raw_text_v1_no_query_instruction`：直接发送原始 passage/query 文本，不增加查询 instruction、改写或翻译。使用当前配置的同一 OpenRouter 嵌入模型 `qwen/qwen3-embedding-8b`；记录请求配置中的模型名、endpoint signature、输入 SHA 和实际返回维数；签名覆盖地址、路径、模型和额外参数，API 固定 float encoding，不在实验记录中展开地址与额外参数，不假定供应商名称不变就意味着模型从未更新。

文档与查询共 72 条输入。默认每批最多 16 条，本轮无缓存时预期 5 次 embedding 尝试，预算为最多 6 次；实际发送方式和次数由清单记录，失败不得隐匿。此预算是次数上限，不是货币费用上限。没有获准的额外请求，不因失败或结果不理想无限重试。本实验不调用文字生成或额外 reranker API。

缓存保存供应商／模型配置签名、输入配置、完整有序输入的 SHA，以及逐文档／查询 ID 对应的原始向量；四个方法重用完全相同的文档和查询向量，不能为同一比较重复付费生成不同向量。保存原始返回浮点数，再另行归一化进行评分；校验条数、索引、维度、有限值和非零范数。原始响应若包含密钥或不必要的请求头必须排除，但不能把手工生成的替代数值称为 API 原始输出。

当前应用管线即使选择 BM25 也仍会获取查询嵌入用于 cosine 诊断；所以应用端的 BM25 模式不能被描述为无 API 调用。纯 benchmark 的 BM25 排序本身不需要新向量，但本轮统一提前缓存供其他方法与诊断重用，不产生每方法额外嵌入费用。应用延迟与纯排序耗时应分开报告。

## 指标与分母

主要读数是 **Recall@5** 和 **All-evidence@5**。先分别报告 test 与 dev，不把合并后更好看的结果替代 test；全部可答查询的汇总仅作补充。给出每类需求、查询语言与 multi-evidence 子集结果，同时标明样本数。

| 指标 | 运行前定义 |
| --- | --- |
| Recall@k | 检索到的正相关片段数 / 全部正相关 qrels 数，grade 1 与 2 都计为相关。 |
| Precision@k | 前 k 个位置中的正相关片段数 / k；少于 k 个结果的空位置计为未命中。 |
| MRR@k | 前 k 个结果中首个正相关片段的倒数名次；无命中为 0。 |
| nDCG@k | gain 为 `2^grade-1`，折扣为 `log2(rank+1)`；用当前 qrels 的理想排序归一化。 |
| Evidence Coverage@k | 被至少一个已返回文档满足的必要组数 / 必要组总数。 |
| All-evidence@k | 所有必要组都至少命中一个允许来源时为 1，否则为 0。 |
| Empty-result rate, unanswerable | 4 条资料外查询中返回空结果的比例；同时保留每条是否空和返回片段数。 |

组内来源可替代，组间要求同时满足。Passage Recall 反映全部相关片段覆盖，不能把它等同于找齐所有必要答案部分；部分背景片段即使有正 qrel，也未必属于必要组。

不可答查询没有 qrels 或必要组，Recall、MRR、nDCG 和证据组指标不进入可答均值，也不通过空集逻辑计为满分。保留这些查询返回非空上下文的情况；empty-result 指标仅描述检索行为，不能当成可靠拒答率、幻觉率或生成正确率。任何阈值或拒答检测器评测需要独立协议。

## 不确定性与比较

保存每条查询上每对方法的指标差，主比较为三个替代方法分别减去 `dense_v1`。同时报告改善／相同／退步条数、绝对差以及原始分母，不能只挑改善样例或只记录均值。

query-level paired bootstrap 仅作探索：固定随机种子 `20260912`，2,000 次有放回抽样，每次给被比较方法使用同一组查询下标，对均值差取 2.5% 与 97.5% 百分位区间。按相应 split／可答子集抽样，不把不同方法的独立抽样误称配对。不把该区间作为总体显著性或因果结论；同 family 查询仍相关，数据也由同一助手编写。类别样本极少，应优先展示逐题观察，不能根据多种指标挑选一个显著结果。

本轮不调参。dev 用于确认软件是否按协议工作；一旦任何 test 排名或指标被查看，该 test 集也已暴露，后续算法调整只能称探索性开发，并需要新版本、重新标注或真实课程 holdout 才能开展新的确认性比较。

每次运行使用独立目录与 `run_id`，不覆盖此前目录。清单至少保存：

1. UTC 起止时间、数据文件副本与 SHA、协议文件副本与 SHA、运行命令、代码 revision 或相关文件 SHA、依赖锁文件、Python 与平台版本、方法配置及 tokenizer／embedding 输入配置。
2. 原始文档和查询嵌入及逐输入映射、缓存命中与来源、请求配置中的模型名与签名、实际返回维数（未保留供应商响应的模型版本字段）、调用数、耗时及已提供的 token／费用字段。费用缺失标作未知。
3. 保存各策略每条查询最终 Top 10 的排序及诊断：两路名次与分数、融合总分、MMR 选择顺序／评分、最终各 k 前缀、回退原因。全部候选分数可用冻结源码、文本和向量重算；不宣称 rankings.json 已转储完整候选池。
4. 逐题 qrels、必要组命中、各指标、子组／split 汇总、配对差及探索性区间、方法耗时；明确排序耗时与首次嵌入等待时间是否分离。
5. 失败尝试、解析／向量检查错误、中止位置、缺失查询与已完成部分。排序失败作为缺失排名计 0 分并保留错误记录，不能静默处理或从均值分母中删除；含排序失败的运行标为 `completed_with_failures`，嵌入等整体失败标为 `failed`，修复后新建运行。排序耗时仅统计成功完成计时的查询。

记录负向或持平结果，并说明原假设与实际观察。修复实现 bug 时记录原因和受影响输出，不在原目录内覆盖成看似首次成功。所有参数和数据修改必须有时间顺序，后于结果暴露的变动不能追记成预注册内容。
