# 难度旁路观察与自动返工候选协议

2026-09-26：新增 `review_v2`，采用盲解题、内容与求解核验和宿主决策，作为新任务的默认协议；本地开关继续为 `off`。详见 [新版评委说明](../review-v2/README.md)。下文的 v4.1 初评与语义复核是 `legacy_v1` 历史协议，保留用于旧记录与实验重现。

## 行为

生产模块位于 app/difficulty_shadow.py；v4.1 评委和语义复核器已移至 app 下，旧实验命令通过兼容导入继续工作。旁路在原生成流程完成选题、正确性检查及组装校验之后、草稿提交之前执行。它不修改草稿内容、不覆盖原判级、不触发修题，也不放宽原质量门槛。由于会等待有界的旁路调用，它会增加保存前的等待时间。

首版按顺序观察前 1 道已接受题，最多额外 2 次调用：一次 v4.1 评审、一次语义复核。采用配置的文本服务直接 JSON 请求，thinking off、temperature 0；初评最多 6000 输出 tokens，复核最多 3000。主生成可以继续使用 DeepSeek Harness；旁路没有通过 ACP 包装调用，也没有通用执行工具。实验中的二分执行证据没有假装成为所有题目的运行工具。

可选的第三、四次调用只在原评委和第一次旁路评委均不支持目标难度、且第一次理由复核无发现时重复难度评审，并复核第二次理由。相同模型与提示的两次判断属于重复稳定性检查，不是独立教师校准。宿主还会记录一次**不执行**的自动返工候选判断；详细条件见 [自动返工协议](AUTO_REWORK_PROTOCOL_20260925.md)。

## 配置与回滚

当前本地研究后端的 `.env` 已设为 `DIFFICULTY_SHADOW_MODE=off`（2026-09-25）；以下是需要重新启用时的示例，不代表当前运行状态。

```dotenv
DIFFICULTY_SHADOW_MODE=shadow
DIFFICULTY_SHADOW_PROTOCOL=legacy_v1
DIFFICULTY_SHADOW_MAX_CALLS=2
DIFFICULTY_SHADOW_MAX_QUESTIONS=1
DIFFICULTY_SHADOW_TIMEOUT=30
DIFFICULTY_SHADOW_REPEAT_DISAGREEMENTS=false
```

代码和 .env.example 默认 off。设置 shadow 后新创建的任务会冻结协议指纹、上限、超时及采样策略。mode 改为 off 并重启服务可停止未开始的旁路；其它旁路参数改动不会增加旧任务的冻结额度。旧检查点没有旁路配置则保持无旁路，不新增付费调用。

如需采样重复分歧，须把 `DIFFICULTY_SHADOW_REPEAT_DISAGREEMENTS` 显式设为 true，并把 `DIFFICULTY_SHADOW_MAX_CALLS` 至少设为 4；默认不增加调用。这个配置仍只观察，不触发自动返工。

旁路也受 AGENT_MAX_CALLS 和本地每日限额约束。只使用主生成完成后剩余的额度，不为旁路增大总额度。上限不足、上下文超限、上游失败、格式错误均记录为旁路未完成，原草稿照常提交。取消请求仍遵守原任务取消规则；进程中断时，已写下调用意图的阶段不会自动重发。未知是否计费的调用只能标记为中断，不按成功计算。

## 数据与可见性

- 新任务 configuration.difficulty_shadow 保存冻结配置。
- evidence.difficulty_shadow 保存每个阶段的输入、请求散列、原始回复、校验结果、调用账本 ID、错误类别和时长。
- /api/jobs/{id} 增加 difficulty_shadow 摘要；完整原文和计量可从原有 /api/jobs/{id}/evidence 导出。
- 输入来自最终学生可见的资料、学习目标、题干和选项。逐题资料仅传对应题的部分；作者答案、解析、设计理由、目标难度和私有检索块不进入旁路初评。
- 摘要分开记录原模型的 assessed_difficulty 与目标/发布标签，避免把作者目标当成独立判级。
- 审核页对当前版本展示目标与旁路意见的分歧、边界或不可用提示；旧版本旁路结果在题目编辑后标记失效。旁路不据此自动发布或返工。

默认每题只有一次旁路初评，不能据此称“多次一致”。可选重复若启用，也仍不等于准确性验证。no_issue_found 是本次**评委理由**语义复核未发现问题，不是题目或参考答案正确性认证。由于默认只采样最前面的题，结果不能代表整个题集。

## 验证

本地检查覆盖旁路关闭、草稿不变、无答案泄漏、上游/格式/超时失败隔离、总预算和每日预算、旧任务恢复、已冻结预算、取消中断后不重复调用、逐题材料隔离和重复生成请求。

scripts/difficulty_shadow_live.py 经真实 FastAPI 账号、课程、资料上传、索引、生成、任务、内容和证据接口执行两道题；嵌入、检索与 DeepSeek 调用不使用 mock。仅省去 HTTP 监听器，用 ASGI 在进程内调用同一应用和工作队列。使用隔离账号/数据库，不改既有用户课程，属于本地真实任务验收，不是远程生产部署。

真实验收每任务总调用上限 14、旁路最多 2，两个任务与索引合计设总上限 30；原始失败也保留。具体完成情况、调用用量和边界见本目录实测报告。

内容详情接口也提供摘要；内容证据导出包含完整观察，并标记 observed_content_version 与 matches_current_content，编辑后不会被视为当前版本的验证。实际接入与启用情况见 [验收报告](ROLLOUT_20260924.md)。
