## 逐题检查

- **R3 数据库原子性，简单选择题：失败。** 计划阶段的一条要求同时引用真实资料编号和一个未提供的 `context_4b1d5e9f`；控制器按来源范围拒绝计划，未创建题目或旁路评审。随后增加了只针对“一个陌生编号混在有效引用中”的一次重新规划路径。重新规划必须重新通过完整来源、结构、数量和难度校验；整条要求只有陌生来源时仍直接失败。该路径已通过本地测试，但 R4 的首次计划直接有效，因此尚无真实调用证明这条恢复分支成功。
- **R3 xv6 中断与锁，困难简答题：成功生成，不能用于自动返工。** 原评 hard、旁路候选 medium，但旁路理由复核发现其分析部分把断言 A 写成“成立”，最小答案又写成“不成立”。复核状态为 `correction_required`，重复评审未启动，离线决策为 `manual_review`。我的非盲教师式检查还发现：在多 CPU 场景下，断言 A 的“某个线程”未限定为本 CPU 持锁线程；若持锁线程在另一 CPU，参考答案对 A 一概判错就不成立。题目和参考答案需先澄清这一条件，不能将旁路 medium 当作可靠难度真值。
- **R4 PostgreSQL 原子性，简单选择题：成功生成，暂不返工。** 原评和旁路均为 easy，理由复核未发现问题，离线决策为 `no_difficulty_rework`。我的非盲教师式检查认为其主要任务是把资料中的“全有或全无”应用到已给的转账失败情境，简单级别合理。选项 A 中“没有 COMMIT，任何已执行更新都不会生效”措辞偏宽；在题设的故障无法完成条件下可理解为“不会形成已提交结果”，正式使用前宜明确这一点。此意见不是独立教师金标准。

两批共 3 个提交任务、2 道完成题。严格离线重放确认 **0 个自动返工候选**。`REVIEW_20260925_R3_R4_V2` 先提供仅含学生可见题目和学习者背景的难度评审材料，之后提供答案与引用资料核查材料，最后才是模型对照页。我的非盲开发意见单独写入 `ai_difficulty_review.csv` 和 `ai_answer_review.csv`；两份独立人类教师表仍为空，不能记为已获得独立人类复核。

## 本轮改动与验证

- 计划提示要求完整复制资料编号；仅在一个无效编号混于有效引用时，允许 Harness 最多重新规划一次，保留首次失败与第二次输出证据。没有自动修改错误引用，也没有放宽最终校验。
- 评审包增加答案、解释与已保存引用节选的单独核查页，以及题目有效性、答案正确性、来源支持的空白评审表。它与难度盲评页分开。
- 本地相关测试：199 通过、2 条第三方弃用警告。R3、R4 的保存内容与旁路输入散列在生成评审包及离线重放时再次匹配。

正式小范围自动返工仍需：新数据中的可用分歧候选、独立的题目/答案/来源及难度校准、费用与延迟的完整测量，以及在只记录决策阶段观察误返工和漏返工。当前开关仍是旁路，`enforcement_enabled=false`。
