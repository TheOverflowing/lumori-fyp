# 按需语义复核 v1

## 目标与范围

格式和原文编号合法仍可能伴随语义错误。本模块核查已有 AI 评审中的任务理解、样例答案和判级理由，重点处理五类缺陷：可选方法被说成必选、无依据结论、遗漏必需要求、事实与解法混淆、内部矛盾。

它不重新给难度，不因“我觉得应当中等”而否定初评。只对具体可定位的问题给发现和局部修改建议。复核可用同一提供方模型的独立上下文，但不因此成为独立人类验证，也可能共享系统性偏差。

## 输出与门槛

- 每项发现同时引用题目与初评的原文编号；宿主还原题目文本和初评 JSON 路径，拒绝未知/重复编号。
- 区分 definite 与 uncertain，不把可疑问题直接当确证。
- 明确问题返回 correction_required；仅不确定问题返回 review_required；没有发现返回 no_issue_found，而不是“正确认证”。
- audit_gate 只应用于已选中接受复核的任务：复核缺失、失败或提出问题时保留为待复核；没有发现也不会把原来的待复核/弃判升级。
- 原始难度与评审记录保持不变，建议不能悄悄替换原文。问题修订后需要重新判断难度，而不是沿用旧等级作为新结论。

当前新增的是实验复核模块和门槛函数，尚未接入正式 Agent。它没有自动选择所有任务进行收费复核；应优先处理已经暴露的依据矛盾或输出分歧，不能将任意标签分歧当作语义错误。

## 验证设计

固定 6 个评审版本，来自 3 道已见开发题，每版本两次，共 12 次调用。两组为真实观察到的错误及局部修正版；一组为原评审与注入错误因果说法的版本。对照只改变局部评审文字，题目、学生背景和难度候选不变。标签和变更状态不进入复核提示。

这些控制用于诊断检测行为与误报，不能估计全题库准确率。校正版本也可能有其它缺陷：复核若指出不同问题，必须逐项核对，不能简单算误报或自动算发现成功。原始结果、控制结果、依据和重复分歧全部归档。

## 初轮暴露的问题与聚焦修正

初轮复核器在一个修正版上把自我撤回的怀疑仍输出为 definite：解释与建议已经说内容正确、无需修改，但状态却要求纠正。另一条还包含错误的二分执行判断。这说明不能仅凭复核模型的布尔结论否决结果。

追加 v2 只针对二分样例：宿主为固定已知程序提供 [1,2]/2 的重复状态不终止、[1]/2 返回 0 而规定答案为 1、[2,3]/2 正确返回 0 三组执行证据。用固定解释器执行，不执行来自模型的代码。要求简短、最终确认的发现；对“无需修改”却仍标为错误的输出做协议拒绝。

这是一组同时改变提示、字段长度和执行证据的聚焦修正，不是单因素证明。追加 4 次调用单独保存于 SEMANTIC_WITNESS_20260924，不覆盖初轮。此类执行证据只适用于匹配的程序，不能代替文本题的语义评审。
