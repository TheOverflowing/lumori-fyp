# 本轮优化：把语义复核建立在具体证据上

## 交付

新增独立语义复核模块，检查原评审是否误读任务、混淆条件与解法、遗漏要求或自相矛盾。每项发现同时定位题目原文与初评 JSON 字段，建议只作局部修正，不重新给难度、不覆盖原标签。

新增保守门槛：被选中复核的任务，如果复核失败、缺失或指出问题，就保留待复核；没有发现也不能把原本待复核的任务升级为通过。该门槛已做本地测试，尚未接入正式 Agent 生成链。

## 初轮：复核模型自身也会出错

固定 6 个版本、每版两次，共 12 次真实调用，11/12 结构有效。方法误读、二分非终止与因果说法的错误都被指出，但预设类别完全匹配只有 4/6；其中部分问题被归到其它类别，不能简单当作未检出。

更重要的是，二分修正版有一条结构有效的误报：复核在解释里已承认内容正确、建议无需修改，却仍标 definite。另一条同类输出过长，协议拒绝。初轮的原二分复核还给出不正确的例子解释。不能把这些结果宣传为可靠裁判，原始失败及误报均保留在 SEMANTIC_AUDIT_20260924。

## 聚焦修正：4 次追加调用

给二分题提供由宿主固定解释器产生的三组事实：

| 输入 | 实际程序行为 | 题目规定的结果 |
|---|---|---|
| a=[1,2], t=2 | 重复同一状态，不返回 | 应返回 1 |
| a=[1], t=2 | 返回 0 | 应返回 len(a)=1 |
| a=[2,3], t=2 | 返回 0 | 应返回 0 |

不执行模型生成代码，仅检查题目中的固定已知程序。复核输出改为简短的最终结论，已撤回的怀疑不应继续作为错误发出；建议以“无需修改”开头的错误项会被协议拒绝。

| 聚焦样例 | 两次结果 |
|---|---|
| 原解释声称“循环不前进但返回 0” | 两次指出内部矛盾 |
| 局部修正版正确区分不终止和错误返回 | 两次未发现问题 |

追加 4/4 输出有效，无重试，无离线补字段。这个结果只支持针对当前样例的修正；提示、长度约束和执行证据同时改变，不能归因于其中单一因素，更不能估计全题库准确率。

## 对既有结果的具体影响

PROPOSED_GATES.json 对三个真实原场景演示了门槛效果（仅报告，不改生产状态）：

- 奇数和同义背景：原本已有难度分歧，继续待复核；另标记“可选归纳法被称为必须使用”的理由错误。
- 二分基础背景：虽然两次难度都为 hard，至少一份初评答案存在执行行为矛盾，因此从“AI 暂定一致”转为待复核。标签一致不能替代答案与理由正确。
- 因果题熟练背景：复核未发现具体问题，保留原有 AI 暂定一致；不提升为人工认证。

这解决的是“错误依据不能仅凭一致标签被接受”的流程问题，不是为初评强行换一个难度等级。修订建议与原始记录分别保存。

## 用量与验证

初轮 12 次 / 39,418 tokens；追加 4 次 / 16,049 tokens；合计 **16 次 / 55,467 tokens**。费用均未返回。54 项本地测试通过，归档数据、计划与代码散列已核验，未包含已配置凭据。正式 Agent、.env 和原评审档案未被覆盖。
