# v4 精简评委协议

## 改进依据

上一轮 v3 的失败包括漏填必需字段和把题目事实当作解法支持；v2 还发生引文改写。v3 继承全部 v2 字段，又增加同义审计条目，重复输出增加了出错机会。本轮以冻结 v3 作同场对照，采用相同 8 道开发诊断题，不把它们宣传为未见测试集。

## 新结构

v4 输出只保留六项：可评状态、状态理由、认知要求、任务核对表、简短样例答案、判级决定。

任务核对表分别存储：

- request_ids：题目要求学生做什么；
- condition_ids：题目给定的事实、数据和约束；
- solution_ids：已经给出的解法、解释方向、结论或证明；
- residual_work：仍需学生完成的工作；
- mode：复现、熟悉应用、选择调整、构造论证或不可完成。

原文先由宿主拆成有固定编号和偏移的片段。模型引用编号，宿主还原原文；未知编号、重复编号均拒绝。这个方法防止引文改写，不自动证明模型选对片段或给对角色。

判级决定包含候选等级、困难依据对应的任务序号和理由。只有一个候选时才能给出明确等级；多个候选自动归为 uncertain，保留具体边界；题目不可评时候选必须为空。困难候选必须对应真实存在的未被标为复现/不可完成的任务。缺字段不能自动补默认等级。

## 简单／中等边界

检查最小合格答案是否只是重述已经给出且学生有准备理解的论证，还是需要题干未完成的证据选择、应用或解释。不能只因要求“解释所有情况”就升级，也不能仅因提供了解法就全部降级。已有知识不一定等于熟练理解新论证；资料不足以区分时允许保留相邻候选。

这是待验证的操作约定，不是学生实测阈值，也不是把之前 AI 给出的标签强行写入提示。

## 对照与汇总

同一 DeepSeek 配置、off、temperature 0、max_tokens 6000；8 题 × 2 方法 × 2 次重复，上限 32 次，无自动修复或重试。代码/数据/请求在调用前冻结。

报告不仅统计格式有效率和重复标签一致，还报告明确等级覆盖、多候选比例及候选集合的一致性。若两次都 uncertain 但候选集合不同，不计为候选集合一致。协议更简洁是否提升稳定性，以实测报告为准。

CONSENSUS.json 使用保守合并：任一次失败或等级分歧均待复核，不回退到单次成功答案。AUDIT.md 显示系统还原的事实/解法引用及剩余任务，供逐题查看。正式 Agent 和 .env 暂未修改；所有结果仍为 AI 开发证据。

## 试验后的容量修复

原始 v4 在线有效 12/16，其中 4 次失败全部由引用列表上限 5/6 触发。v4.1 将三个引用列表上限调整为 64，保留所有其它约束。离线验证时加载冻结 v4 校验器并重现原始结论，确认 schema 只变化了这三个 maxItems；固定回复在新校验器下达到 16/16 有效。没有新增 API 调用；不是新 schema 的在线复测。

原始在线结果与离线重验分目录保存，详见 V4_COMPACT_20260924/RESULT.md。原文编号合法不代表其角色分类或判级语义正确。当前实现仍在实验路径；后续验证应冻结新协议后采用新的题目家族，不把本轮事后修复表现当作未见题准确率。
