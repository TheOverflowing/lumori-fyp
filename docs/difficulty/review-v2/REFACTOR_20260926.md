重构已接到原有观察入口，完成协议、运行时、API、界面及历史评审材料适配。**自动接入的质量验收尚未通过；本地开关保持 `off`。** 当前没有自动放行、自动改题或自动返工。

## 重构内容

1. 先盲解：仅传入学生可见文本和学习者背景，隐藏目标难度、旧判级、参考答案与来源。区分已给解法与学生剩余工作。
2. 再做六项核验：条件完整性、参考答案、作者解释、来源支持、盲解答案、难度依据。题目和解题器分别承担自己的错误。
3. 宿主分开保存明确判级、相邻边界、不可判级、内容问题、证据不足、调用未完成。只有必要检查通过且唯一等级明确，才给出难度返工建议；该建议不执行。
4. 证据由宿主编号并展开原文；模型不能改写引用。冻结输入、协议、模型、各阶段参数；恢复时不重发不确定的计费请求。保留全部失败和历史判断。
5. 界面与 API 显示判级覆盖率，旧内容编辑后评审失效。内容问题优先展示；当前发布等级与目标等级不混用。

## 真正暴露并修复的问题

- 最初的核验漏掉历史 TCP 题的边界措辞问题。v2.3 low 明确指出“缺口起点前”与答案取缺口起点冲突，给出不确定；v2.4 再次标为内容问题，但此次理由是冻结来源不支持完整 ACK 规则。**不能据此宣称缺陷理由已经稳定。**
- 证据只有来源而无对应主张，或只有分析而无学生文本。改为分角色必填证据，保留严格归属检查。
- 校准题 courier 的作者解释误写 `5+5=9`。low 核验发现它；独立枚举确认总和应为 10、最优容错方案仍为 8。原始数据/标签和原统计保持不动，单独发布[勘误](../../../benchmarks/difficulty_review_v2/ERRATA_20260926.md)及修正版，不能算作模型误拒。
- v2.3 把正确参考答案与错误盲解之间的不一致归咎于题目。v2.4 增加 `solution_correct`；后续两道正常复杂题的盲解错误都归入 `insufficient_evidence`，参考答案检查通过。
- 过小的证据数量和解答字符上限导致合法回答在结构阶段失败。最终任务最多 8 项、每角色证据最多 8 条、每项展开最多 32 条；解答硬上限 4000 字符，仍提示尽量控制在 1000 字符内。token 上限未随字符修复增加。

## 实验参数与本地配置

实际实验候选：盲解 `deepseek-flash`，非思考，2400 token；核验 `deepseek-v4-pro`，low 思考，12288 token，120 秒超时。服务返回的模型标识保存在各批 `calls.json`。接口支持的思考参数见 [DeepSeek 官方说明](https://api-docs.deepseek.com/api/create-chat-completion/)。

这些实验参数没有写入 `.env`。当前有效本地配置为 `mode=off`、`protocol=review_v2`、核验模型覆盖留空、`effort=none`、每任务最多抽样 1 题/2 次调用、30 秒超时。单次输出限制和两次调用预检不等于跨并发任务的总 token/费用预约。改 `.env` 也不会热更新已启动的服务。
