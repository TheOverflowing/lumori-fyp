# 独立求解配置优化：配对实验与新题验证（2026-09-26）

## 结论

**复杂题的独立解答在本批得到改善，正式自动判级/返工仍未达标。旁路保持关闭。**

保持 v2.4.1 的题面、学习者背景、提示、结构与核验配置不变；把分析端从 Flash 非思考改为 Pro low。两道旧难题各重复两次，经另一位 AI 审查者结合完整枚举核对，完整解答正确数由 **0/4 → 4/4**。这是两种配置组合的比较，同时改变模型、思考模式和输出额度，不能归因于单一因素。

核验并非总能完成或给出唯一等级。候选组最终只有 1 个明确等级、1 个相邻边界；另 1 个因难度依据不充分弃判，1 个核验输出用尽 token。**解答正确性、评审完成率、内容审核和难度准确率分别报告。**

## 本轮代码改动

- 新增 `DIFFICULTY_SHADOW_ANALYST_MODEL`、`DIFFICULTY_SHADOW_ANALYST_EFFORT`，与核验阶段分别配置、冻结和逐调用检查。两者默认仍为原模型/非思考，未扩大默认调用成本。
- 非思考上限 2400 token；思考模式 12288 token，隐藏思考不传给下一阶段。输入预留改为最终 JSON 的有界估算，实际发送前仍严格检查大小，超限弃判而不截断。
- 评测脚本支持分析端配置、阶段耗时、调用 ID、结构错误类别；单独揭示“内容检查全通过，但最终因评委错误弃判”的潜在漏检，避免弃判掩盖内容问题。
- 新增只读配对比较脚本，拒绝未结束或控制条件不一致的实验。
- 新建四题及可执行参考答案校验程序；数据哈希在调用前冻结，原题库和历史报告未改。

相关回归测试 **241 项通过**，`git diff --check` 通过。另有两条既有依赖弃用警告。本轮未改界面，未把实验配置写成默认设置。

## 两道旧题各重复两次

两组均采用 Pro low 核验、12288 token 上限。基线分析为 Flash 非思考/2400 token；候选分析为 Pro low/12288 token。输入协议指纹与数据指纹完全相同，由比较工具验证。

| 指标 | 基线 | 候选 |
|---|---:|---:|
| 独立核对的完整解答正确 | 0/4 | 4/4 |
| 双阶段结构有效 | 3/4 | 3/4 |
| 明确单档判级 | 0/4 | 1/4 |
| 合法相邻边界 | 0/4 | 1/4 |
| 内容被误报为错误 | 0/4 | 0/4 |
| 真实调用 | 8 | 8 |
| token | 68,994 | 104,684 |
| 每题中位耗时 | 92.7 秒 | 166.5 秒 |

候选 token 比基线增加约 51.7%。耗时是本次并行实验中的观测值，不能直接推广为部署性能。两组各有一次核验达到 token 上限；这些失败保留在分母中。

独立审查把数值、方案、证明分别核对：原组有一份最小值 5 正确，但实际排程违反设备互斥，因此不算完整解答通过。升级组正确处理了设备约束，也覆盖了此前漏掉的费用 4 路径。候选一份证明中的省略按“另一条不同路径”的上下文理解成立，审查记录保留了措辞说明。

审查者知道分组和参考答案，**未读取核验者意见**，并用有限枚举核实构造与最优值。因此属于 AI＋可执行证据，不是盲教师金标准，也不是总体准确率估计。

## 已定位的下一处问题

1. **求解改善后，瓶颈转到难度依据。** 同一道正确排程，分析端可能给 medium，也可能给 medium/hard；核验者指出“允许枚举/反证”不能证明已经熟练掌握。因此一份仍转为证据不足。需要独立的难度锚点、准备程度标注和争议裁决，不能靠强制选择 hard 修复。
2. **核验资源与时延。** 当前复杂题每次仍需两次模型调用，核验偶有 token 用尽；升级组合在本批更慢、token 更多，尚不适合作为所有任务的默认配置。
3. **正式流程仍欠全覆盖和返工闭环。** 当前观察器抽样、不自动改题，创建任务时不保证预留后续返工及再核验额度。
