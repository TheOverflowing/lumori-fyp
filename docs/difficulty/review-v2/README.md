# 新评委：独立解题、内容核验与宿主决策

本地开关仍为 `off`。新版已经接入现有生成完成后的观察位置；是否具备模型质量上线依据，须看独立的运行报告，不能由代码测试通过推定。

最新结果见 [独立求解配置优化与新题验证](SOLVER_OPT_20260926_REPORT.md)：在冻结评审协议下比较分析端配置，分别报告独立解答正确性、核验完成率、难度分歧和资源消耗。

## 协议

1. **盲解题**：只接收学生可见题目、讲解和学习者背景。隐藏目标等级、作者答案、旧评委结果与私有资料。输出可答性、简洁解答、必要任务、可见提示消除了哪些工作、剩余独立工作和难度候选。学习目标不等于学生已经掌握的技能。
2. **内容核验**：接收同一题面、盲解结果、参考答案/解释及本题引用的冻结资料。全文按原顺序分段，每个证据片段标注程序分配的编号；间隙、换行也保留，拼接后与原文逐字一致，避免重复发送正文和证据目录。逐项检查条件充分性、参考答案、解释一致性、来源支持、盲解答案正确性、难度分析是否成立。六项必须明确通过/失败/不确定，并定位依据。盲解与参考答案不一致时分别核对，不能把解题器的错误记到题目头上。允许使用某方法不等于学生曾经练习该方法。
3. **程序决策**：题目内容失败优先标记内容问题；盲解错误、缺阶段、无效响应、缺证据转待审核；难度边界保留相邻候选。只有六项通过且唯一等级明确时，才比较目标并给出返工建议。评委不修改目标或题目，不执行返工。

这两步提供不同检查任务和不同信息。它们仍可能共享模型错误；即使用不同型号也不能代替教师金标准或实测学生难度。

## 接入控制

`DIFFICULTY_SHADOW_PROTOCOL=review_v2` 选择新协议，`legacy_v1` 用于重现旧观察器。新任务冻结模型、输入构建版本、提示、结构、程序决策规则、输出上限和每题两阶段策略；旧任务保留创建时版本，不因部署变化增加调用。

`DIFFICULTY_SHADOW_ANALYST_MODEL` 和 `DIFFICULTY_SHADOW_VERIFIER_MODEL` 分别选择盲解题模型和核验模型；留空时各自沿用配置的文本模型，也可显式指定同一供应商的型号。更换分析模型不会隐式更换核验模型。每次调用前重查冻结签名、关闭开关、取消和资料权限。无效或变化的可选评委配置会跳过旁路，不阻断已经通过原有检查的主任务。

`DIFFICULTY_SHADOW_ANALYST_EFFORT` 和 `DIFFICULTY_SHADOW_VERIFIER_EFFORT` 分别控制两个阶段，默认均为 `none`：非思考、2400 token；`low/high/max` 启用相应思考强度，上限 12288 token，不发送 temperature。需要模型服务支持这些参数；本轮采用 DeepSeek 的 [Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion/)。思考模式的上限包含推理输出，不代表最后 JSON 的长度。超时范围仍是 1–120 秒，使用思考模式时需显式给足时间。超时/格式错误/中断不自动重发可能计费的请求。

开始某题前检查两阶段所需剩余调用额度和已知输入大小，额度不足时零开跑。该检查不是跨并发任务的整轮原子预约；每日额度若被其他任务消耗，供应商账本仍拒绝越额，审核记录为未完整完成。总预算不会因核验模型切换而扩大。

计划输出上限为两个阶段之和：4800、14688 或 24576 token；它不是已消耗量或 token 总额度预约。任务创建时尚未保证为审核和返工保留额度。验证输入只接收最终分析 JSON，隐藏思考不会进入下一阶段。预检继续采用 `min(分析输出上限×4,16000)×2` 字符估算；倍数 2 保守预留 JSON 转义和证据分段信息，不再代表重复发送两份全文。16000 是依据当前有界结构的规划估算，不是硬上界。实际发送前仍严格检查输入字符上限，超限弃判、不截断。

新摘要记录全部题数、抽样题数和明确判级题数；未采样和弃判都不表示通过。内容编辑后旧判断失效。历史证据优先读取当时保存的决策，避免新规则改变旧记录的含义。费用、token、失败记录与质量判断分别报告；缺失费用不能视为零。

## 验证层级

- 工程测试：权限、预算、取消、恢复、版本、输入隔离、未知证据与输出契约。
- 冻结 AI 诊断：开发最小对照、历史错误、不同题目家族的留出题；标签为事前 AI 预期，报告所有失败、误放和弃判。
- 正式自动决策校准：单独取得独立教师盲评及争议裁决；冻结阈值与留出集，测内容错误漏放、误返工、覆盖率、耗时和费用。当前材料不具备这一证据层级。

诊断数据及事前门槛见 `benchmarks/difficulty_review_v2/README.md`。`scripts/difficulty_review_v2_eval.py` 默认为干运行，期望标签、目标与分组元数据不会进入模型提示，整批有调用硬上限。即使小样本全部通过，脚本也不会自行打开正式发布开关。

程序的旧 `ai_diagnostic_gate_passed` 字段只表示结构化结果是否满足事前 AI 单档预期，不拥有上线授权；合理的相邻边界不能仅因此被判成错误。新统计把核验者报告的盲解正确性、内容核验是否漏放、最终是否给出等级分别列出，评委自身的弃判不能遮住内容漏检。求解构造和证明仍需独立枚举或人工审阅，教师准确率保持未知。

## 运维边界

修改 `.env` 不会热更新已经启动的服务；重新启动后需核对实际生效配置，进程环境可能覆盖文件。当前抽样上限是每任务前 5 题，不能把摘要当成整份测验的放行证明。自动返工还需要另建全覆盖策略、任务创建时的预算保留、返工后的完整复核及回退路径。
