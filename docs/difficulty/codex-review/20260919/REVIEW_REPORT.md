# Codex 回顾性评分：D1 与 v2 契约验证

评审日期：2026-09-19。主评审为本会话 Codex 助手；逐题阅读、难度判断和最终维度分由主评审给出，辅助代理只提供事务事实核查与调度计算。共覆盖 **42 个请求、39 道可用题**；另 3 个请求无可评输出，按协议计零。未新增模型 API 调用，未修改原题、旧评审或正式应用。

## 如何理解这份分数

本次是**隐藏条件标签的回顾性 AI 复核**。评审者参与过提示设计并见过上轮结果，且认识此前的调度错误案例，因此不称完全独立盲评或人工专家金标。Q003 的生成解释还自行提到了“评分要点先行”，存在文本内残余标签泄漏；这也已写入 manifest。

先固定 [评分协议](../../CODEX_REVIEW_PROTOCOL_V1.md)，再准备随机顺序题包。主评审在隐藏映射下阅读39道题，记录四维子分、难度和可核查理由；根据计算修正草稿后冻结 [ratings.v1.json](ratings.v1.json) 的哈希，随后才揭示策略和目标并计算组分。本文不声称精确服务端模型快照、温度已固定，也不声称评分者是“当前最强模型”。

满分100：难度匹配40，答案正确性30，资料支持10，可作答性10，清晰度10。相邻档位只获20分，跨两档或无法判断为0。四项质量各按0–4分评分后换算。**这些权重是项目自定义，综合分不是准确率。**

另报严格达标：难度完全一致、置信度不低、正确性/资料支持/可作答性均满分、清晰度至少3/4。参考答案存在错误即不能严格通过。总分允许部分得分，不能用它替代严格通过门槛。完整材料是否符合应用格式也单独统计。

## 错误与评审分歧

D1 的34道可用题中，本次评审把13道的正确性评为0–2分（实质错误），4道为3分（局部问题），17道为4分。严格达标为16/36；按目标难度分开是 easy 11/12、medium 5/12、hard 0/12。由于三个档位分别绑定三个主题，这不能解释为所有课程的hard档普遍为0。

**10道实际生成的CPU调度题都有实质性答案错误。** 已通过 [确定性调度核算](cpu_checks.md) 保存不同时间片、切换规则下的时间线与指标。缺失入队规则的题保留两种条件结果，没有自行补条件后冒称唯一答案。代表例子：

- Q032 原答案认为 q=3 同时满足响应上限4与开销上限4；实际最大响应为8。三个给定候选均不可行，最终推荐改变。
- Q025 明确规定提前完成后的转换免费，答案却仍计费；正确R4平均响应10/3、平均周转9。
- Q023 未给切换耗时，固定首次运行时刻与可行性无法直接决定；即使额外取耗时0，不同任务之间切换次数也应为10/5/3，而非原答案13/7/4。

事务题的代表问题：Q018前提自相矛盾，Q039把首次读取前提交的新值误判为不可见，Q020忽略自身写入。Q019需要的RR同行写冲突规则没有包含在给定资料中；实际PostgreSQL会拒绝更新，不能直接得到答案中的80。外部官方文档用于揭示资料缺口，不能被悄悄算成学生已经获得的知识。[PostgreSQL 17：Repeatable Read](https://www.postgresql.org/docs/17/transaction-iso.html#XACT-REPEATABLE-READ)

完整事务事实核查见 [transactions_checks.md](transactions_checks.md)。没有运行真实PostgreSQL实例，证据是题内材料、时序分析和官方文档核对。

与旧Qwen在相同34道题上的难度标签相比，本次有12处分歧，原始标签一致22/34（64.7%）。该一致率**不是任何一方的准确率**。例如本次将有明确数值交错的规则应用通常判medium，不因三个子问就判hard；没有具体应用的重试规则复述则判easy。边界题的难度判断仍需要课程教师校准。

旧Qwen将这34道题的四个质量布尔值全部判true，而本次发现了上述可验证答案错误。只能将有证据支持的具体错误称作漏检；不能把所有主观难度分歧都宣布为Qwen错、Codex对。新增细分评分与旧布尔评分标准也不完全等价。

这批评分可用于开发集的错误分析和工具设计，不能又被包装成新方法的独立最终测试。后续实验继续使用固定协议、先评题再揭示分组、记录每次评分版本；若据此优化提示，要另设冻结的最终评测与教师样本。

优先改进应是“生成—可执行答案检查—针对错误修订—再次核查”的有界流程。调度题先生成结构化任务与调度规则，由程序给出参考值；事务题用明确事件表和作用域约束。将这类正确性改善与单纯提示词改写分开实验，仍按相同调用/token预算比较。不以增加评审模型声誉替代正确性证据。
