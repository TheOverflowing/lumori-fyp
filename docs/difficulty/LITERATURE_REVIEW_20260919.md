# 难度可控出题与提示词优化：文献调研及候选实验

调研日期：2026-09-19。研究对象：基于课程资料的中英文计算机本科出题。本文是研究与实验设计记录，**没有在本文中报告本项目的实测提升**，也未为此次调研运行模型 API 或下载模型。

## 1. 结论与证据边界

提示词实验不应只比较“有无正反例”。可将改进分成四层：

1. **生成前的设计**：明确学习者背景、分解难度维度、先确定答案与证据、控制题目给出的支架。
2. **生成时的结构控制**：用具体的约束、方法选择、边界情况或逆向构造调整认知任务，避免只增加字数。
3. **生成后的选择与修订**：盲评、检查可作答性、针对失败项修改、同预算下多候选筛选。
4. **跨实验的提示搜索**：以开发集失败记录为反馈，优化下一版提示词；最终测试集和最终评审器始终冻结。

下面的“项目改编”是本项目提出的待检验假设，并非原论文的完整复现。没有一篇本文阅读的论文直接证明它在本项目的 **DeepSeek、RAG、中英文计算机本科、三档难度** 组合中有效。论文中的难度经常指故事信息整合、模型解题成功率或竞赛难度，它们不能直接替代真实学生的作答难度。

源码核对：当前 `app/difficulty.py` 已有三档 rubric、逐题计划、认知过程和简短评分要点的结构检查，以及隐藏生成者难度标签的复核输入。因此“新增 rubric”应理解为**细化现有标准的操作方式**，不能把已有功能重新算作新贡献。现有说明已明确：Bloom 层级和步骤数量不能单独证明实际难度。

## 2. 十二类候选方法

调用量均为**项目改编的粗略预算**，不是论文实测。`G` 为一次出题调用，`J` 为一次评审调用，`P` 为一次规划调用，`R` 为一次修订调用；一次调用可以处理一批题，题数与输入长度必须另行记录。最终独立评测成本应对各组一致计入。

### M01. 难度维度与认知任务分解

- **来源**：Yadav et al., *From Recall to Creation: Generating Follow-Up Questions Using Bloom’s Taxonomy and Grice’s Maxims*，ACL Industry 2025。[论文及书目](https://aclanthology.org/2025.acl-industry.93/)，[全文](https://aclanthology.org/2025.acl-industry.93.pdf)。阅读：方法 §2、评估 §3。
- **原方法**：围绕固定种子问题生成不同认知层级的追问，并分别评价一致性、信息量、相关性与清晰度。研究场景是车载助手，不能直接视为学生难度校准。
- **项目改编**：把笼统的“困难题”展开为 `knowledge_integration`、`method_selection`、`transfer`、`constraints`、`justification`、`scaffolding`。要求题干真正触发相应任务，并给简短、可核对的评分要点；不索取隐藏推理链。
- **微调与开销**：提示生成不需微调；同一调用内附加设计要求，约 `G`，主要增加 token。
- **限制与优先级**：Bloom 只作为一个维度，不能简单映射为难度。优先级高，适合检验现有 rubric 的表述是否足够具体。

### M02. 答案与证据先行，再形成题干

- **来源**：Li & Zhang, *Planning First, Question Second: An LLM-Guided Method for Controllable Question Generation*，Findings ACL 2024。[论文及书目](https://aclanthology.org/2024.findings-acl.280/)，[全文](https://aclanthology.org/2024.findings-acl.280.pdf)。阅读：§3.1–3.2、实验设置。
- **原方法**：先生成含答案候选的计划，再根据内容及难度属性调整计划，最后生成问题。完整方法包含训练阶段的计划融合和问答生成模型训练；论文也研究了提示式迁移。
- **项目改编**：先固定 `answer_key`、`source_ids`、必要概念、可接受答案范围与简短评分点，再写恰好需要这些内容的题干。评审仍须检查计划本身是否正确。
- **微调与开销**：完整复现涉及训练；API 改编不需微调。单次结构化输出约 `G`；独立规划版本为 `P + G`，两种应分别命名。
- **限制与优先级**：原研究主要针对 FairytaleQA。计划可能把答案泄漏进题干，必须检查。优先级高；与原论文只共享设计思路时称 `answer-first inspired`。

### M03. 结构性复杂度与支架控制

- **来源**：Peng et al., *CoDiQ: Test-Time Scaling for Controllable Difficult Question Generation*，2026-02-02 预印本。[论文](https://arxiv.org/abs/2602.01660)，[全文](https://arxiv.org/pdf/2602.01660)，[作者项目](https://github.com/ALEX-nlp/CoDiQ)。阅读：§3.2–3.5、项目说明。
- **原方法**：用约束、抽象、逆向构造、状态复杂度及边界情况等策略增加题目难度，并分别检查难度与可解性。完整方案还包含训练的生成器和估计模块。
- **项目改编**：在课程范围内选择一种明确操作：困难题引入需处理的边界条件或方案权衡；简单题明确方法、提供中间步骤；中等题保留有限方法选择。降低支架不能变成遗漏必要条件。
- **微调与开销**：复现专用模型需训练；只借鉴操作菜单不需，约 `G`。逐轮进阶至少增加修订与验证调用。
- **限制与优先级**：原目标偏数学、代码竞赛及模型难度。不能把增加 token 当作难度控制。优先级高，尤其适合数据结构、算法、数据库与操作系统的情境题。

### M04. 跨难度对照与冲突筛选

- **来源**：Li & Zhang, *CrossQG: Improving Difficulty-Controllable Question Generation through Consistency Enhancement*，Findings EMNLP 2025。[论文](https://aclanthology.org/2025.findings-emnlp.151/)，[全文](https://aclanthology.org/2025.findings-emnlp.151.pdf)。阅读：§3–4、评估设置。
- **原方法**：生成不同档位题目，用其他档位的题作对照后重生，再做难度导向的交叉过滤。过滤用特定隐藏状态构造的表示；最终实验的难度分类器另有训练。
- **项目改编**：保留同知识点的三档对照，并明确区别在于任务要求、资料整合与支架。普通语义 embedding 不应直接当作难度 embedding。
- **微调与开销**：提示对照本身不需微调，约 `G` 加示例 token；完整原流程成本更高、依赖更特殊的表示与评审条件。
- **限制与优先级**：仅加入正反例不能称完整 CrossQG。其 §4.1 记录提示式 GPT-4 难度评估在该设置不足 65%，提醒我们先校准评审。作为现有对照组保留，优先级高。

### M05. 失败原因驱动的局部修订

- **来源**：Madaan et al., *Self-Refine: Iterative Refinement with Self-Feedback*，2023。[论文](https://arxiv.org/abs/2303.17651)，[作者项目说明](https://selfrefine.info/)。阅读：摘要与项目方法、停止条件说明。
- **原方法**：生成、给出可执行反馈、据反馈修订，循环至停止条件；无需额外训练。
- **项目改编**：反馈分类为偏简单、偏困难、资料不支持、答案歧义、干扰项失效等。仅修改失败题和受影响字段，保留已通过项与来源约束；最多一或两轮。检查通过也不能直接视为真实学生达标。
- **微调与开销**：不需微调。首稿 `G`；一轮为 `G + J + R + J`。必须保存修订前后版本，记录“越改越差”的比例。
- **限制与优先级**：同一模型的自评可能重复原错误。需要独立外部评审和正确性证据。优先级高，但与单次提示词组分开比较。

### M06. 多候选生成，先验题再筛选

- **来源**：Lin et al., *REGULAR: A Framework for Relation-Guided Multi-Span Question Generation*，IJCNLP-AACL 2025。[论文](https://aclanthology.org/2025.ijcnlp-long.5/)，[全文](https://aclanthology.org/2025.ijcnlp-long.5.pdf)。阅读：§3.3–3.4、实验设置与限制。
- **原方法**：生成多个问题，用问答模型所得答案与候选答案的一致性选择问题。其模型训练与关系图构建不能省略后仍称完整复现。
- **项目改编**：同一槽位生成三个候选，先排除错误、歧义和脱离资料者，再按与目标难度的距离选择。未选中的题也须保存，且不能用最终测试评审器帮助选择。
- **微调与开销**：原方法含训练；项目 API 版本不需。约 `3G + J`，也可一次生成三题，但两种采样方式需分别记录。
- **限制与优先级**：原论文是多答案跨度问题生成，并非难度控制验证。优先级中高，用作与局部修订的同预算比较。

### M07. ProTeGi：从错误样本产生提示修改方向

- **来源**：Pryzant et al., *Automatic Prompt Optimization with “Gradient Descent” and Beam Search*，EMNLP 2023。[论文](https://aclanthology.org/2023.emnlp-main.494/)，[全文](https://aclanthology.org/2023.emnlp-main.494.pdf)。阅读：§2.1–2.2。
- **原方法**：在小批数据上收集错误，把错误总结成自然语言反馈，生成若干提示修改，再用搜索和候选选择继续优化；不是权重梯度训练。
- **项目改编**：把开发集中的失败题、评审证据和当前提示一起交给优化器，只允许修改出题指令。修改理由必须对应实际失败模式，不能改评分标准或目标标签。
- **微调与开销**：不需微调。离线每轮需要反馈、候选提示生成及多个小批评测；部署获胜提示可保持 `G`。
- **限制与优先级**：评分噪声会误导搜索，需重复样本与独立验证。优先级中高；简化实现须称 `ProTeGi-inspired`，不能宣称重现全部搜索算法。

### M08. OPRO：利用提示与历史分数搜索新指令

- **来源**：Yang et al., *Large Language Models as Optimizers*，2023 预印本 / ICLR 2024。[论文](https://arxiv.org/abs/2309.03409)，[全文](https://arxiv.org/pdf/2309.03409)，[官方代码](https://github.com/google-deepmind/opro)。阅读：§2、官方 README。
- **原方法**：向优化器提供任务约束、历史候选及分数，让模型继续提出新候选并测试。
- **项目改编**：历史记录提供各语言、各难度的达标率与成本，而非只给总平均分；要求提出简洁通用指令。样本题仅来自训练/开发集。
- **微调与开销**：不需微调。离线约为候选数乘以评测集规模，部署仍可 `G`；费用应以实测 token 计算。
- **限制与优先级**：只看到分数不一定能定位歧义或知识错误，小数据上易过拟合。优先级中，适合作为与有错误文本反馈的优化方法比较的基线。

### M09. MIPROv2：共同搜索指令与示例

- **来源**：Opsahl-Ong et al., *Optimizing Instructions and Demonstrations for Multi-Stage Language Model Programs*，EMNLP 2024；DSPy 官方 MIPROv2 文档。[论文](https://aclanthology.org/2024.emnlp-main.525/)，[官方方法文档](https://github.com/stanfordnlp/dspy/blob/main/docs/docs/api/optimizers/MIPROv2.md)。阅读：论文摘要与官方方法三阶段说明。
- **原方法**：构建示例候选、依据程序与数据提出指令候选，再用贝叶斯优化寻找组合。支持只优化指令的零示例模式。
- **项目改编**：首先做只优化指令的版本，与纯手工指令公平比较；后续才加入经过审核的训练集示例，防止示例质量与指令改善混在一起。
- **微调与开销**：不需微调。离线提案与多次小批评测成本较高；部署 token 随示例数增加。
- **限制与优先级**：自动“通过”的示例不等于人工金标准。优先级中，适合评测数据和指标稳定之后。

### M10. GEPA：执行记录反思与多候选保留

- **来源**：Agrawal et al., *GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning*，2025 预印本，2026-02-14 修订；全文标注 ICLR 2026 Oral。[论文](https://arxiv.org/abs/2507.19457)，[全文](https://arxiv.org/pdf/2507.19457)，[官方项目](https://github.com/gepa-ai/gepa)。阅读：§3、算法 1–2、项目 README。
- **原方法**：依据执行记录、分数和文本反馈修改提示，保留在不同样本上各有优势的候选，按预算进行筛选与组合；模型权重固定。
- **项目改编**：归档规划、出题、检查各阶段的结构化输入输出与失败项，在离线实验中优化指定模块。只保留可核对的摘要与评分证据，不要求私有思维链。
- **微调与开销**：不需微调；离线成本由 rollout 上限控制，线上成本取决于最后选择的流程。
- **限制与优先级**：仅“反思并改写一次”不是完整 GEPA。评审器应冻结，不能随生成器共同变宽松。优先级中高，适合第二阶段正式提示搜索。

### M11. 分维度表格式盲评

- **来源**：Liu et al., *G-Eval: NLG Evaluation using GPT-4 with Better Human Alignment*，2023。[论文](https://arxiv.org/abs/2303.16634)，[方法全文](https://arxiv.org/html/2303.16634v3)。阅读：§2、对评审偏差的讨论。
- **原方法**：明确评审标准与检查步骤，使用结构化评分；原版还利用评分 token 概率。
- **项目改编**：让评审先检查答案正确性、来源支持、歧义与实际需要的认知操作，再独立判三档难度或“无法判断”。隐藏目标难度、方法名、生成者设计解释；输出短证据、置信度及标签。
- **微调与开销**：不需微调；约 `J`。若 API 不提供所需概率，使用离散评分并明确不是原版概率加权 G-Eval。
- **限制与优先级**：研究原任务是摘要和对话，评审仍可能偏好模型文本。优先级最高，作为所有生成方法共用、先冻结的测量工具。

### M12. 结构化标准转为可检查项

- **来源**：Chen et al., *Two-Level Meta-Rubrics for Evaluating Open-Ended Generation: GAMUT, a Benchmark for Factual Completeness*，2026-07-21 预印本。[论文](https://arxiv.org/abs/2607.19322)，[方法全文](https://arxiv.org/html/2607.19322v1)，[官方项目](https://github.com/facebookresearch/GAMUT)。阅读：§3、rubric 构建与人工修订流程。
- **原方法**：先表示答案内容的组合、顺序与重要程度，再转换成较易逐项判断的检查项。它研究事实完整性，并不提供教育难度等级标准。
- **项目改编**：将“需综合分析”展开为可观察条件，例如题干是否要求在两种方案间选择、是否给出影响结论的约束、评分点是否包含依据；同时允许多种正确方案，不能把开放设计题锁成唯一答案。
- **微调与开销**：不需微调；人工审核一次模板，之后约 `J`，逐项单独调用会进一步增费。
- **限制与优先级**：原 rubric 是专家核验的，不能照搬成模型自创自评的金标准。优先级高，适合改进评审的可解释性，并为多模态阶段预留接口。

## 3. 两项重要补充证据

### 难度不只是一张标签

Leite & Lopes Cardoso 的 *Advancing Question Generation with Joint Narrative and Difficulty Control*（BEA 2025）用模拟学习者作答和 IRT 估计难度，再训练联合控制模型。阅读了方法 §3；其结果也明确难度控制随属性变化，并非全部稳定成功。可借鉴“同时控制内容和难度”的实验意识，未来用真实学生数据校准；当前模型模拟结果只能叫模型代理指标。[全文](https://arxiv.org/html/2506.06812v1)

Tomikawa & Uto 的 *Difficulty-Controllable Multiple-Choice Question Generation Using Large Language Models and Direct Preference Optimization*（2025 初稿，2026-03-23 修订）是直接相关的训练路线。此次只阅读摘要和版本记录，尚不据此设计完整复现；它涉及 DPO，不能归类为只改 API 提示词。[论文](https://arxiv.org/abs/2510.19265)

### 自我检查不保证自我纠错

Huang et al., *Large Language Models Cannot Self-Correct Reasoning Yet*（ICLR 2024）研究没有外部反馈的内在自纠错，在其推理设置中观察到效果有限甚至下降。此次阅读摘要及研究范围；这个结论不能扩张为“所有新模型、所有反馈循环都无效”。本项目因此要保留首稿、复核稿与最终独立评分，允许报告负提升。[论文](https://arxiv.org/abs/2310.01798)

## 4. 优先实验矩阵

先做受控的少量条件，不把十二种方法机械叠加成一个超长提示。下列名称是研究条件建议，实际运行应以对应 manifest 的 strategy ID 为准。

| 阶段 | 条件 | 只改变什么 | 主要问题 |
|---|---|---|---|
| 第一阶段 | 当前单次生成 | 无新增策略 | 首稿基线是多少？ |
| 第一阶段 | 维度化 rubric | 更具体的难度设计要求 | 模型是否理解了“困难来自哪里”？ |
| 第一阶段 | 答案先行，同一调用 | 输出中先设计答案要点和来源 | 可作答性与难度能否同时改善？ |
| 第一阶段 | 结构与支架控制 | 允许的难度调整操作 | 能否避免“长题就是难题”？ |
| 第一阶段 | 跨难度对照 | 对照示例及差异说明 | 示例到底贡献多少？ |
| 第二阶段 | 最优单因素的组合 | 只组合有证据的互补项 | 是否互补，还是指令冲突？ |
| 第二阶段 | 独立答案规划 | 多一个规划调用 | 分步值得额外成本吗？ |
| 第二阶段 | 局部修订与多候选筛选 | 调用分配方式 | 同预算下修订或采样哪种更好？ |
| 第三阶段 | ProTeGi / OPRO / MIPROv2 / GEPA | 离线提示搜索算法 | 自动搜索是否超过人工版本，泛化是否保留？ |

第一阶段统一单次生成预算及最大输出长度；不能把同一调用内的计划和独立两次调用的计划混报。输出多出的规划字段只作为诊断材料，最终外部评审不看生成者自述的设计理由。

建议先做 **36 个分层开发条件**：3 个课程主题组 × 2 种语言 × 3 档难度 × 2 种题型。课程主题可从数据结构与算法、数据库、操作系统选取，具体每组材料先冻结。每个条件每次请求一题，首轮重复一次用于排查；此样本只作 pilot，不能据此声称普遍最优。正式比较提高独立主题数和重复次数，按主题分组划分开发集与保留测试集，避免相同知识点或翻译版本跨组泄漏。

## 5. 评测协议与归档字段

以下为项目实验设计建议，不是某篇论文的照搬。

### 评审先校准

- 先准备一批由课程专家核验的锚点题，覆盖各语言、题型及边界案例。尚无专家核验时必须标注 `ai_drafted / human_review_pending`。
- 固定学习者先修知识、允许的资料和工具。输入语言与材料语言分开记：中文资料配英文题是单独维度。
- 固定难度定义，生成器可以看到完整目标；最终评审隐藏目标与策略，只判断观察到的任务要求。随后由程序比较目标和评审标签。
- 评审器必须能输出“无法判断”。生成失败、格式失败和评审失败都保留，不能只计算成功输出。
- 同一模型不同上下文属于独立调用，不是独立模型。条件允许时用另一模型并以人工抽样核对；不能将 AI 评审称人工标注。

### 主要指标

`有效达标率 = 正确、可作答、无明显歧义且难度匹配的题数 / 预定生成题数`。

同时报告各档/各语言的匹配率、混淆矩阵、无法判断率、错误答案率、首稿到最终稿的变化、每道有效达标题的 token/费用/耗时。将难度偏差大小作为次级指标，区分简单误判为中等和简单误判为困难；不要让次级加权分数掩盖达标率下降。

用同一需求配对比较策略；多个题来自同一资料或主题时应保留分组，并以分组重采样估计置信区间。pilot 的小幅差异先作为候选信号，不能宣布赢家。提示搜索只能接触开发集；保留测试集只能在方案冻结后评价，不能把其失败记录再输入优化器而仍称“保留集”。

### 每次实验必须保存

| 类别 | 建议字段 |
|---|---|
| 数据 | 数据集版本、split、主题组 ID、来源许可/链接、资料快照 hash、题型、语言、学习者背景 |
| 提示 | 模板全文、版本与 hash、参考文献、与原论文的改编差异、固定 JSON schema |
| 模型 | 实际返回模型 ID、服务商、时间、采样参数、预算；不要保存密钥 |
| 流程 | 条件 ID、重复编号、规划/生成/评审/修订调用顺序、原始输出、失败类别 |
| 评分 | 隐去目标的评审输入、评审器版本、原始判定、程序计算的匹配结果、人工复核状态 |
| 成本 | 每次 token、重试数、总耗时、费用来源与计价日期；未知费用不要填零 |
| 报告 | 首稿和最终稿分别统计、负面结果、置信区间、样本选择与排除理由 |

## 6. 与 agent 的衔接

在线 agent 负责执行经过实验验证的有限流程；离线优化器负责提出下一版提示词。二者分开可以避免用户的一次请求触发无界搜索。

建议先保持明确动作：生成、检查、修改失败题、停止并标记待审核。在线不能修改最终评价标准，也不能因为检查困难而偷偷降低目标难度。多模态阶段可复用“结构化计划—工具调用—结果检查”的接口，但音频清晰度、图文一致性和视频时序应新增各自的标准，不能沿用文字难度分数代替媒体质量。
