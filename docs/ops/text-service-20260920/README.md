# DeepSeek 文字服务不可用：诊断与提示修复

记录日期：2026-09-20。此次事件发生在用户生成请求中，与难度三轮校准无关；模型尚未生成第一道题。

## 已核实证据

任务 `9882b631f5f842e9b8689bae4eed8ae1` 于北京时间 16:49:39 创建，16:49:49 失败：

| 操作 | 结果 | 用时 |

| 资料重排 | HTTP 200，成功 | 2360 ms |

检索保留了 5 个参考片段；Agent 在 `q1` 出题调用中遇到 `provider_error`，0 / 3 题完成。之前的需求检查也连续遇到 503，另有请求收到 HTTP 200 后超过45秒检查时限而失败；HTTP 200 不等于获得了完整输出。

只读模型列表探测返回200，模型包含 `deepseek-flash`。北京时间16:52:41进行一次最小JSON生成探测（最多32输出token、不含课程资料、不自动重试），171ms返回503。未进一步重试，也未重新执行用户任务。平台没有返回用量与费用，不能按零费用记录。用户随后也确认 DeepSeek 服务发生故障。

[DeepSeek 官方错误码文档](https://api-docs.deepseek.com/quick_start/error_codes/)将503解释为服务过载，并建议稍后重试。以上证据支持此次失败在上游文字生成服务；不能仅凭模型列表正常就宣称聊天生成恢复，也不对全平台故障范围作额外判断。

机器可读记录：[事件摘要](incident.json)、[单次最小生成探测](live-probe.json)。这些文件不含密钥、完整学习目标或课程正文。

## 本地改动

- ProviderError携带受限错误分类及HTTP状态，区分服务错误、超时、网络、认证、限流、余额和参数问题。503不再笼统建议核对模型编号。原始上游错误正文不保存、不展示。
- 需求检查返回白名单`failure_code`，使用固定中英文文案。服务不可用时说明正式生成同样可能失败；按钮为“仍按原输入尝试”。无效输出与服务故障分开；旧检查记录缺少分类时安全显示通用提示。
- 进度页通过精确匹配本应用生成的错误文本，兼容本次历史503记录：主标题和当前停止阶段显示“模型服务暂不可用”。可续做任务显示已保留进度及“继续生成”，同时保留“返回修改”。
- 不修改生成算法、不替换模型、不无限重试，也不将服务故障伪装为已成功。

- 无活动任务时按原参数重启了本地应用，启动成功；外部服务状态没有因本地重启而被认定恢复。

本次修复改善故障分类与用户提示，不代表已修复供应商故障。服务恢复后，用户可从原失败任务选择继续生成。
