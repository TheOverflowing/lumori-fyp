# Q2 干预记录：检查与修复契约

本轮在 Q1 归档完成之后修改产品。Q1 的源码快照、原始结果、失败任务及两阶段复核不变；Q2 真实运行使用独立目录，冻结后不再修改执行源码。

## 已实现处理

1. **工具检查适用性**：宿主依据实际工具请求和结果判断输入匹配是否适用。没有工具输入时保存 `not_applicable`，保留 reviewer 原始布尔值；不改变 `calculations_verified`、答案、解析、引用、歧义等否定结果。模型漏报需要计算仍然是模型能力边界，不能因此宣称已证明不需要计算。
2. **结构化题目检查**：新任务的 solver/reviewer 均返回 `question_checks`，包含具体条件缺陷和逐选项判定。宿主校验 MCQ 选项完整且有序、唯一可辩护答案、正确键及 solver 自身答案一致性；没有工具时还检查 solver/reviewer 选项分歧。reviewer 另列 `explanation_issues`。负面结论不能作为仅难度不符的候选保留。
3. **工具先行兼容**：请求真实计算的 solver 可以暂缓判断选项，避免尚未拿到结果就手算；实际工具执行后 reviewer 必须完成唯一性与正确键检查。CPU 确定性结果不能覆盖题目条件、解释或来源问题。
4. **通用出题约束**：要求明确影响答案的初值、存在性、顺序、比较关系和边界；允许有意设计的条件答案，但不能暗补条件。逐项核对干扰项解析；hard 要求真正的约束推理，不能把已给出解法的长题干当作难题。提示中没有加入基准参考答案、证据锚点或 case ID。
5. **native 一次 schema 重评估**：仅针对完整 JSON 对象的结构错误，重新根据原任务作答，不给错误输出或自动映射近义字段。保留两次调用和原始诊断；不修复传输/截断/无效 JSON，不把有效负面内容判断当作结构错误重试，所有调用仍受原上限约束。
6. **本地预算分类**：本地预检、每日额度耗尽及原子预约竞争使用 `LocalCallLimit`、`call_limit` 与 `resource_limit.scope`。每日额度恢复后可继续原任务，任务生命周期上限不能被恢复动作重置。真实 HTTP/网络失败仍按 provider_error 处理。
7. **兼容路径**：新策略与 prompt revision 在新任务配置中记录；旧检查点不自动启用新字段/重评估额度。Flexible 的补证据路径保留有效模型类型，并检查新负面结论；逐题修订保留新质量字段及原有修订要求。

## 文件与验证范围

- `app/question_quality.py`：质量契约、选项一致性和工具适用性函数。
- `app/generation_agent.py`：新任务 policy、角色 prompt/schema、确定性门控、原生结构修复、本地额度分类。
- `app/task_control.py`、`app/store.py`：可区分的本地额度异常和原子预约。
- `app/question_revision.py`：新旧审核契约及一次结构修复兼容。
- `tests/test_native_schema_repair.py`、`tests/test_generation_resource_limits.py`、`tests/test_q2_quality_adversarial.py`：结构、预算、负面判断、工具、旧检查点边界回归。
- 原有 Generation / Harness / Flexible / 单题修订测试同步正确的模拟响应和预算状态预期；这不等于真实模型质量测试。

更深层 Harness relay 的内部预约竞争仍有旧的通用 provider_failed 包装；本轮真实对照只运行 native，不声称修复所有后端的错误分类。

## 对照边界

Q2 将这组检查与修复契约作为一个组合干预。即使质量或交付改善，也不能把变化单独归因于某一条提示或某一个检查。配置、数据、顺序、192/12 调用上限、单题任务和真实 RAG 链路与 Q1 保持一致；不追加失败样本择优结果。

这些宿主校验只能验证模型报告的完整性和内部一致性。模型仍可能一致地犯错，来源正确也不保证推理正确；最终质量和难度由另存的匿名两阶段 AI 复核评价，且仍需未来教师/学习者证据。
