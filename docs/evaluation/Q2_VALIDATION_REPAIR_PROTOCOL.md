# Q2：检查与修复契约的有界配对对照

版本 1.0；预先制定于 2026-09-22。本文是运行协议，不是结果报告。实际运行、停止原因、变更文件及 AI 复核完成度以单独的 Q2 归档为准。

## 1. 问题、基线和证据边界

本轮研究：在相同资料、输入、模型、检索和预算下，修改检查与修复契约，能否减少误拦截，同时提高“交付且通过全部核心质量项”的比例？不会把“更多任务结束为成功”直接当作内容质量提高，也不会把测试通过当作模型正确性的证据。

基线为 [Q1-live-20260922](runs/Q1-live-20260922/manifest.json)，完整结果见 [Q1 报告](Q1_QUALITY_LATENCY_RESULTS_20260922.md)。冻结口径如下：

| 指标 | Q1 | 分母说明 |
| --- | ---: | --- |
| 计划 / 提交 / 实际检索 | 24 / 24 / 23 | 零调用预算预检失败仍属于已提交任务 |
| 交付 | 20 / 24 | 含 5 个调整后交付 |
| 已交付核心质量通过 | 13 / 20 | 两阶段 AI 辅助复核 |
| 交付且核心质量通过 | 13 / 24 | 本轮主指标的基线 |
| 已交付目标难度匹配 | 12 / 20 | 盲评结果，不是产品门控结果 |
| 可评候选 / 完成复核 | 23 / 23 | 包含 3 个未发布候选，不能记为已交付 |
| 全部候选核心质量通过 | 15 / 23 | 用于误拒分析，不替代交付质量 |
| hard 已交付匹配 | 1 / 6 | 4 个已经标记 adjusted；不能全部称为 strict 误判 |
| 全轮 / 在线生成 / 建库调用 | 189 / 177 / 12 | 含失败、修复和检索 |
| 所有提交 / 已交付耗时中位数 | 25.94 s / 25.94 s | 每条件一次随机生成，描述性数字 |

author、隔离答案的 solve、review 均使用同一个 `deepseek-flash`。角色或会话隔离不等于独立模型，可能存在相关错误。后续 Codex AI 复核是独立于产品门控的一层流程，但不是人工金标准、教师验收、真实学生难度测量或多评审一致性研究。

这 24 条输入组成 AI 编制的开发集：12 个知识需求，每个有中文和英文变体。Q2 已根据 Q1 的问题选择改动，因此同集改善只能说明定向修复效果，不证明泛化、因果效果或“最强策略”。正式论文应另设未参与调参的冻结测试集，教师评审和学生表现应作为新证据层。

## 2. 控制变量与允许干预

保持 Q1 的数据集、12 份来源文本、许可证、同课程全库检索及任务顺序不变。数据集文件 SHA-256 为 `de8dc096f5e2d0648e3a056e32bf09d3cf2ce9308f46229fc46fdd0c65cbc0dd`；manifest 的 `dataset_sha256` 是规范化 JSON 摘要，不能与文件摘要混用。

| 固定项 | 值 |
| --- | --- |
| 样本 | OS / DB / Networks，各 8 请求；中英文各 12；easy / medium / hard 各 8 |
| 题型 | 单选 / 简答各 12；每请求 1 题；关闭题前教学内容，保留答案解析 |
| 来源语言 | 全部英文；未测试英文输入检索中文材料、扫描解析或 OCR |
| 生成 | `deepseek-flash`；thinking disabled；max_tokens 6000；JSON mode |
| 嵌入 / 重排 | `qwen/qwen3-embedding-8b` / `qwen/qwen3-reranker-8b` |
| 切分 | `recursive_token_v1`；256 token；同 tokenizer 摘要 |
| 检索 | `hybrid_dense_lexical_v1`；candidate_k 20；top_k 5；context 1024 token |
| 编排 | `agent_v1 / native / sequential_v1 / none`；并发 1 |
| 关闭功能 | fusion、自动探索、需求追问 |
| 顺序 | 使用 Q1 相同的 20260922 seed 和完整 case_order |
| 每轮预算 | 全轮最多 192 次调用，含重新建库、查询嵌入、重排、失败及所有修复 |
| 单任务预算 / 墙钟 | 12 次调用 / 全轮累计 3600 秒 |

应用源码允许的干预仅为：工具检查适用性契约；native 角色响应的有界 schema 修复；预算预检错误分类；必要条件、逐选项与解析一致性检查；以可观察认知任务为依据的难度检查及缺陷修复指令。实际包含哪些项，必须在运行前的干预记录逐项列出，不能将尚未实现的计划写成实验处理。

不得在本轮同时更换模型、chunk、检索、重排、资料、任务、上下文预算或并发；不得将参考答案、证据锚点或数据集 case ID 加入生成提示，也不得用 `source_ids` 过滤出已知正确材料。runner 和 metrics 保持 Q1 版本。修复只在原有硬预算内进行，不能因 schema 修复隐式增加调用上限，不能将内容错误直接改为通过。无需工具时应明确不适用；真实计算和实际工具结果仍必须检查。响应结构修复不是重新生成一道更容易的题，也不能把近似字段自动映射为正确性通过。

先运行离线回归，再冻结并运行一次完整 Q2。此轮 192 是 Q2 单轮上限，不是 Q1 的追加额度；不为失败、预算停止或低分任务另起隐性重跑以择优汇报。重复实验、消融或新的数据集属于另行编号的研究。

## 3. 运行前冻结与停止行为

1. 保存 Q1 原始运行、候选、失败、代码、调用账本和复核文件，禁止覆盖。
2. 保存 Q2 干预说明：源码差异和摘要、每项处理机制、离线回归结果；明确与 Q1 相同的运行参数。冻结后不边跑边改应用源码。
3. 以现有 runner 创建 Q2 新目录，使用独立数据库和新建嵌入索引。冻结 dataset、case_order、配置、源码、依赖和 tokenizer 摘要。生产课程与用户数据不参与实验写入。
4. 所有调用进入真实账本，包括失败；保留 response、usage、阶段记录、每次拒绝与修复。达到调用/时间上限、授权错误或持续上游错误时按现有 runner 停止，留下未提交和预检失败行。恢复也不清零预算，不无声重放已提交任务。
5. 如果除预定应用干预外还有配置差异，停止将结果称为受控 Q1/Q2 比较；将差异及影响明确列出。相同名义模型也可能有服务端漂移，因此不能保证一次生成可精确复现。

## 4. 两阶段 AI 复核

使用与 Q1 相同的掩蔽脚本和核心质量定义，优先分配未读过这些生成答案的 AI 评审者。每个有可解析候选的任务都应进入评审，包括失败任务的最后可解析候选；无候选的预算预检任务保留为无可评内容，不虚构失败答案。

第一阶段只提供匿名题面、学习目标与学习者背景，不提供目标难度、作者答案、difficulty_design、是否发布或门控结果。评审者先独立作答、评定难度，保存时间和文件 SHA-256。第二阶段才提供生成答案、解析及实际检索上下文；引用充分性只基于题目实际引用的来源。独立答案和难度不得事后覆盖，来源导致的修正另记。随后验证封存、原始产物摘要和逐字引文，再关联运行状态。

核心质量通过定义沿用 Q1：可答性、答案、解析、学习目标一致性全部 pass；单选唯一性 pass（简答不适用）；引用为 supported。难度不合并进核心质量指标。保留 fail、uncertain、partially_supported 等原始标签，记录评审者分配与批次。若只有一名 AI 评审看每题，不声称测得评审一致性。

## 5. 比较指标与缺失处理

主指标为“已交付且全部核心质量项通过 / 24 个计划请求”，同时列实际提交分母。失败、预检拒绝、未提交请求不能从计划分母移除。已交付题质量另外用 20/24 等实际交付分母的变化解释：只比较已交付质量率容易产生选择偏差。

次要指标包括：交付率；AI 核心质量各分项；目标难度匹配及 hard 匹配；strict 与 adjusted 各自的匹配；零调用预检和失败类别；不适用工具检查拒绝次数、schema 修复及内容修复；完整调用、可获得 token、墙钟 p50 及配对案例。接受难度降档的交付是有记录的产品折中，不能算原目标达成，也不能把所有 adjusted 不匹配都称为 strict 检查错误。

按同一 case ID 对照，再按 12 个 need ID 分组汇报中英双版本；中英两条不是两个独立知识点。不使用一次运行的 p50 变化推断稳定速度提升，不将 24 条视为独立学习者。可列成功→失败、失败→成功、合格→不合格等逐题转移；缺失复核时转移为 unknown。

AI 复核尚未完成时：可以报告已交付数、已复核数和已知通过数，但完整核心质量率及其提升保持 null。比较器同时给出缺失结果的最好/最坏界限；这些不是统计置信区间。未评题不能默认为正确，也不能默认为质量不合格。失败候选通过复核可帮助发现误拒，但不能计入“交付且合格”。

成本沿用调用账本实际报告，不补零、不用局部 cost 冒充全费用。Q1 只有 58/189 次报告 cost，且未标币种；文本模型 131 次 cost 未知。不同服务 token 口径不同；token 总量可用于计账，不能视为统一货币成本。外部 Codex AI 评审消耗未包含在 Lumori 的 192 次上游调用里，应明确写出。

Q1 最后一条原始 outcome 为 provider_failed，但 0 次调用及明确的预算错误表明是本地额度预检。保留原始数据，比较器另列诊断分类 resource_limited，不重写基线。Q2 若修复了该分类，比较时不能把改名误认为实际服务故障数改善。

```sh
.venv/bin/python scripts/quality_latency_compare.py \

  docs/evaluation/runs/Q2-live-20260922 \
  --output docs/evaluation/comparisons/Q1-Q2-20260922
```

产物：`comparison.json` 保留控制变量差异、输入摘要、各分母、缺失界限、完整调用计量、逐题及逐知识需求配对；`paired_cases.csv` 便于错误分析。控制变量不匹配时不输出汇总提升量。比较器只读取已有 run，不访问网络、不写生产库、不覆盖任一输入归档。

Q2 的验收不是保证数值上升，而是得到可信的对照结果：完整保留失败及预算停止、分清误拒和真正质量缺陷、报告质量与交付的取舍。若质量或 hard 匹配未改善，应如实保留，再选择下一项单独干预；不得事后变更核心质量标准以“证明优化成功”。
