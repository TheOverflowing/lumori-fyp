# 中英文本科课程检索人工标注包

本包保存真实课程教材原文，尚无人工检索标签，**不能直接作为 human-reviewed 评测集**。两份 CSV 当前只有列名，没有评分或人工署名。不要将助手、模型、脚本写入的评分标成真人评分。

## 文件

- `manifest.json`：来源、固定 commit、许可、原始文件 SHA-256。
- 两个教材目录：中文 Hello 算法和英文 OpenDSA 的原文及许可。
- `corpus.json` / `passages.csv`：只做机械分段的证据候选清单；不是人工相关性标签。每个片段有稳定 ID、来源、行号和准确文本。
- `human_queries.csv`：由真人编写的问题；当前未填。
- `human_judgments.csv`：由真人阅读证据后给出的标签；当前未填。

从仓库根目录运行 `python scripts/prepare_course_annotation.py` 可以离线复建清单。它核验原始文件哈希，保留源文件语句和标记，按空行段落打包到约 1200 字符，长段按原始行切分，不重写内容，不添加模型摘要。脚本保留已经存在的两份人工 CSV，避免覆盖真人工作。

## 先写问题，再看检索排名

由学过对应课程的真人写出自然问题，尽量包含同义表述、需要结合两个知识点的问题以及中英跨语言问题。记录 `author_id` 和 UTC 日期；可以用稳定的匿名 ID，无需姓名或学号。`query_language` 使用 `zh` 或 `en`。

问题的意图应来自课程学习任务，而不是为了让某个检索方法胜出。标注者完成问题与标签之前不要查看待比较方法的排名或分数。相同概念的改写、翻译和近重复问题使用同一个 `family_id`；同一 family 只能分到 dev 或 test 的一边。`proposed_split` 只是待冻结划分建议，正式划分应在评测前完成并记录。

`category` 可采用 `lexical`、`semantic`、`cross_language`、`multi_evidence`。若材料不包含回答问题所需的信息，`answerable` 为 `false`，记录理由；必须检查整个冻结语料，不能因为单次搜索没找到就判为不可答。不要把依赖未导入图片、动态练习或代码导入宏的问题标为文字可答。

## 逐条判断证据

先阅读全部候选语料，再在 `human_judgments.csv` 中逐条填写 `query_id` 和 `passage_id`。这一小型语料建议完整判断，以免把未判断片段误当不相关。正式扩展后可以使用多方法候选池，但必须保留未判断状态并披露标注覆盖率。

`relevance_grade`：

- `0`：不能为问题提供有用证据；仅有相同关键词不算相关。
- `1`：提供部分回答证据，或有用的必要背景，但单独不足以回答所问事实。
- `2`：直接、充分支持问题所需的一个关键事实。一个复杂问题可能需要多个等级 2 片段共同回答。

`required_evidence_group` 表示回答必不可少的事实组，例如 `g1`、`g2`。两个片段若都可替代地支持同一个必要事实，使用同一个组；必须结合的不同事实使用不同组。必要证据组只填写在实际支持该事实的片段上，无关或纯背景片段留空。如一个片段确实同时支持多个组，以分号分隔，并在 rationale 说明。后续导入程序必须明确支持此格式，不能默默把多个组当成一个组名。

`rationale` 简要指出片段中支撑判断的具体句子与缺失信息。`annotator_id` 与 `judged_at_utc` 由真人实际填写。两份表的 `reviewer_id`、`reviewed_at` 记录实际复核者和带时区的 ISO 日期，例如 `2026-09-12T08:00:00Z`；单人标注可以填同一人的稳定 ID，但必须说明只有一人。`review_status` 使用 `draft`、`reviewed` 或 `adjudicated`，不能根据脚本运行自动变成 reviewed。

## 复核与冻结

至少有一名具备对应课程知识的人完整复核；条件允许时由两人独立标注，并保留原始分歧及仲裁结果。报告标注人数、背景、样本数、覆盖率、分歧规则以及一致性指标，不虚构第二位标注者。只有一名真人时，应在论文中说明单人标注限制。

在计算正式 Recall、nDCG 或必要证据找齐率前，完成：所有 query/passsage 引用有效；真实人工字段已填；必要事实组合理；所有候选有判断或明确未判断；重复问题 family 不跨划分；语料、问题、标签及协议 SHA-256 已冻结。用开发集决定参数，仅在方案冻结后运行保留测试集。

## 转换成现有评测格式

完整填好两份表后，在仓库根目录运行 `python scripts/build_course_benchmark.py`。默认输出 `benchmarks/rag/course_human_v1.json`，兼容现有 RAG 实验脚本。它不会覆盖已有输出；后续版本通过 `--output` 和 `--dataset-id` 指定新名称。

当前转换器只接受穷尽式标注：每个问题必须对 80 个冻结片段都有明确的 `0`、`1` 或 `2`，不能把空值默认为 0。问题和判断行都必须已复核，人工字段与时间完整；答案必需的事实组必须由等级 2 片段支持；不可答问题需有理由且所有评分为 0。同一 `(query_id, passage_id)` 只能有一行最终判断，双人原始分歧表应另存，在最终表中记录仲裁结果。转换器保留输入文件哈希和完整原始评分行，不替人打分、不核实身份或专业背景，也不把 CSV 字段齐全当作真实专家已经参与的证据。

空表、未复核、遗漏判断、未知片段或来源 ID、被改动的片段文本、跨 dev/test 的问题 family 都会拒绝转换。因此此包当前运行转换器会明确报错，并且不会产出 `human_reviewed` 数据集。
